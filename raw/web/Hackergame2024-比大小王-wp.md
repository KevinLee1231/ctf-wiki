# 比大小王

## 题目简述

页面会在 `POST /game` 后一次性把 100 组待比较数值和开始时间放入前端 `state` 对象。每次手工选择后，`chooseAnswer` 都会用 `setTimeout(..., 200)` 禁止输入 200 ms；对手则每 100 ms 完成一题，10 秒后结束比赛。按页面的正常交互无法在时限内完成 100 题。

服务端使用签名 session cookie 保存题目和开始时间，提交时会重新校验 100 个答案及时间窗口。因此解法不是伪造题目或改 cookie，而是绕过纯客户端的 200 ms 交互延时，直接提交已经泄露给浏览器的正确答案。

## 解题过程

打开开发者工具后等待 `/game` 加载完成。此时 `state.values` 的每个元素都是 `[v1, v2]`，而页面自带的 `submit(inputs)` 会发送：

```http
POST /submit
Content-Type: application/json

{"inputs":["<",">", "..."]}
```

在倒计时结束后、对手完成前，直接在 Console 中运行：

```javascript
submit(state.values.map(([v1, v2]) => v1 < v2 ? '<' : '>'));
```

`map` 会为 100 组数值生成对应的比较符，整个过程不经过 `chooseAnswer`，所以不受 200 ms 限制。不要在开始时间之前提交：后端会拒绝“时空穿越”；也不能晚于开始后 10 秒，否则对手已完成。

另一种等价做法是在 Console 里重定义 `chooseAnswer`，把末尾的 200 ms 改成 1 ms，再用定时器自动答题。直接调用 `submit` 更简洁，也更清楚地显示安全边界在服务端提交校验，而不在 UI 动画。

验证依据是 `/submit` 返回“挑战成功”并附带 flag；若返回异常提交，应检查数组长度和比较符，若返回时间错误，则重新请求一局并在有效窗口内提交。

## 方法总结

- 核心技巧：调用页面已有的提交函数，批量生成正确答案，绕过前端人机交互延时。
- 识别信号：所有题目已保存在全局前端状态，而计时和每题延时只由 JavaScript 实现。
- 复用要点：先找真正的服务端校验和最终请求格式；倒计时、按钮禁用和动画不是可信安全边界，但后端时间窗口仍需遵守。
