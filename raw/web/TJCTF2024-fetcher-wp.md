# fetcher

## 题目简述

应用提供 `/fetch`，接收 URL 后由服务器执行 `fetch` 并返回响应正文。`/flag` 只允许来源 IP 为本机。过滤器拒绝 host 中包含 `localhost` 或 `127.0.0.1` 的 URL，但没有拒绝整个 IPv4 回环网段。

## 解题过程

IPv4 的 `127.0.0.0/8` 都是回环地址，`127.0.0.2` 与 `127.0.0.1` 一样会路由回当前主机。它的字符串又不包含被检查的 `127.0.0.1`，因此通过黑名单：

```bash
curl -s -X POST \
  -d 'url=http://127.0.0.2:3000/flag' \
  'https://TARGET/fetch'
```

Node/Bun 从本机连接该地址时，Express 在 `/flag` 看到的 `req.ip` 仍是本地回环形式（例如 `127.0.0.1` 或 IPv4-mapped 地址），通过访问控制并返回：

```text
tjctf{h3ll0_m3_h3e_h3e_d699bdcd}
```

这里不需要重定向；应用虽然设置 `redirect: 'manual'`，直接使用同一服务的回环别名已经足够。

## 方法总结

- SSRF 过滤不能用少量字符串黑名单表示网络地址；`127/8`、IPv6、整数/混合表示和 DNS 重绑定都可能绕过。
- 安全实现应解析并解析 DNS，拒绝私网、回环、链路本地和保留地址，并在每次重定向后重新校验目标。
- 本题的关键差异是“URL 文本不含 127.0.0.1”与“实际网络目的地仍是 loopback”，应在 WP 中同时说明过滤视角和路由视角。
