# Hackergame 启动

## 题目简述

页面要求使用麦克风录下一段“Hackergame 启动”，并在浏览器中比较录音波形与目标波形。正常录制很难达到页面要求的 `99.9` 相似度；真正决定能否取得 flag 的却不是音频处理，而是提交结果时的 Web 参数校验。

## 解题过程

完成任意一次录音并点击提交后，浏览器会跳转到带有查询参数的结果地址，形如：

```text
...?similarity=87.65
```

这里暴露了关键边界：波形匹配和相似度计算都发生在客户端，而服务端直接使用浏览器提交的 `similarity`，没有重新读取录音或复算分数。因此，无需设法伪造完美波形，只需在地址栏中把该参数改成一个明显超过阈值的数，例如：

```text
...?similarity=9999
```

重新访问修改后的地址，服务端便会把伪造的高相似度视为通过并返回 flag。

这一结果也说明攻击点不在麦克风权限、声纹特征或 Canvas 绘图：音频从未成为服务端可信的验证材料，服务端真正相信的只是一个可由用户任意修改的数字。

## 方法总结

本题的决定性障碍是客户端参数可篡改，因此归类为 Web。遇到“浏览器计算分数、服务端按分数发奖”的接口，应直接检查最终请求中的原始输入，确认服务端是否持有足够数据独立验证。只在前端计算并把结论上传，等同于把判题权交给客户端；正确设计应上传可验证的原始证据，或由服务端重新计算相似度。
