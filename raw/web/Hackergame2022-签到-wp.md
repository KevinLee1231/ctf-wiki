# 签到

## 题目简述

Hackergame 2022 的签到题是一个手写数字识别页面。页面要求依次写出 `2022`，后两个输入框的倒计时非常短，正常书写很容易被识别成其他数字或 `?`。真正决定结果的不是画布内容，而是提交后 URL 中的 `result` 查询参数；服务端直接按该参数判断是否签下了 `2022`。

## 解题过程

先在四个框里任意书写并点击提交。即使识别结果错误，浏览器也会跳转到类似下面的地址：

```text
/?result=207?
```

页面只是读取 `result` 并提示“你签的不是 2022”。因此无需继续和手写识别模型较劲，直接把查询参数改成：

```text
/?result=2022
```

重新访问后，服务端接受这个结果并返回 flag。核心绕过点是客户端生成的识别结果可以在请求发出前后任意修改，而服务端没有重新验证画布轨迹。

## 方法总结

- 核心技巧：修改由客户端控制、但被服务端直接信任的查询参数。
- 识别信号：页面交互看似要求完成手写、计时或模型识别，但提交后 URL 或表单里出现了最终判定值。
- 复用要点：遇到客户端小游戏时，应检查网络请求和地址栏，区分“生成答案的前端流程”与“服务端真正校验的字段”。
