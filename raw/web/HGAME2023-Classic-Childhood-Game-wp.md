# Classic Childhood Game

## 题目简述

题目是一款完全运行在浏览器前端的魔塔游戏。地图、人物状态、事件分支和存档都由客户端 JavaScript 管理，因此通关后输出 flag 的逻辑也必然存在于前端代码中。出题人在 `/Res/Events.js` 中额外加入了 `mota()`：任意结局通关时都会调用该函数，而函数体经过变量重命名、字符串加密、字符串重排、Base64 编码和 Unicode 转义等方式混淆，以避免直接搜索 `hgame{` 就定位到结果。

出题人公开的[题目源码](https://github.com/ek1ng/My-CTF-Challenges/tree/main/HGAME2023-Classic%20Childhood%20Game)可以用于复核事件系统、`mota()` 调用点和本地存档机制；理解主线并不依赖打开该链接。

## 解题过程

### 定位通关逻辑

在浏览器开发者工具的 Sources 面板中检查 `/Res/Events.js`，搜索游戏结局相关事件，可以看到某个能够通关的 `switch` 分支最终执行：

```javascript
mota();
```

继续查看 `mota()`，虽然函数体被混淆，但它没有依赖服务端状态，直接在当前页面执行即可还原并弹出 flag。因此最短路径是在控制台调用：

```javascript
mota();
```

页面弹窗给出：

```text
hgame{fUnnyJavascript&FunnyM0taG4me}
```

### 其它可行路径

PDF 同时给出了两种不需要理解完整混淆代码的方法：

1. 在初次与仙子对话时给 `switch` 语句下断点，将当前事件 ID 改成任意能够触发通关结局的分支（例如 `41`），恢复运行后同样会进入 `mota()`。
2. 游戏存档保存在 `localStorage` 中，可以修改角色生命、攻击、防御等数据，再正常推进到任意结局。

这两种方法都建立在同一事实之上：客户端完全控制游戏状态，而且客户端代码包含最终输出逻辑。

## 方法总结

- 核心技巧：审计纯前端游戏的事件脚本，直接调用通关函数或篡改客户端状态。
- 识别信号：题目没有服务端判定、地图和事件脚本可由浏览器直接读取、存档位于 `localStorage`。
- 复用要点：先从结局文本、事件分支和 flag 输出点反向定位关键函数；代码经过混淆时，不必立即完整反混淆，也可以通过控制台调用、断点改分支或修改存档绕过游戏流程。
