# 签到

## 题目简述

页面要求在倒计时内填写多组文本，并用前端 JavaScript 即时标红、标绿且禁止粘贴。提交失败后，浏览器会跳转到带有 `pass=false` 查询参数的地址。题目的决定性机制不是输入速度，而是服务端直接信任客户端提交的 `pass` 参数。

## 解题过程

先随意填写或直接提交，让页面进入失败结果。观察地址栏可以看到 URL 中出现：

```text
?pass=false
```

将它改成：

```text
?pass=true
```

重新访问即可让服务端按“通过”分支返回 flag。这里不需要绕过前端的粘贴限制，因为前端输入校验并不是最终安全边界。

另一条等价路径是查看页面脚本。正确答案保存在前端的 `answers` 对象中，可以在控制台自动填入所有输入框后正常提交：

```javascript
document.querySelectorAll('.input-box').forEach((input) => {
    input.value = answers[input.id];
});
```

两种方法都说明核心问题相同：答案和通过状态都由客户端掌控，服务端没有独立验证完成过程。

## 方法总结

- 核心技巧：修改客户端可控的查询参数，绕过仅存在于前端的流程校验。
- 识别信号：失败跳转后 URL 出现 `pass=false`，且页面脚本保存完整答案。
- 复用要点：遇到倒计时、禁粘贴、按钮禁用等前端限制时，应检查请求参数、跳转逻辑和服务端是否重新验证；不要把 UI 限制误当成安全校验。
