# Re:Go

## 题目简述

题目提供一个 Go Web 服务。表面目标是登录管理员并通过二次验证码读取 flag；真正的入口在资料更新接口：处理函数把请求 JSON 直接绑定到完整的 `User` 结构体，虽然页面只展示修改密码，却允许额外提交 `Name` 字段，把当前账户改名为 `admin`。随后根据源码中的 TOTP 密钥生成当前验证码即可通过检查。

## 解题过程

先恢复 Go 二进制的函数名和类型信息，定位用户注册、登录、资料修改和 flag 路由。`UpdateProfile` 的前端只发送密码，但后端绑定的对象包含用户名等字段，而且没有使用单独的请求 DTO，也没有对允许修改的字段做白名单限制。

登录普通账户后，在原有修改资料请求中加入：

```json
{
  "Name": "admin",
  "Password": "new-password"
}
```

字段名应以实际反编译得到的 JSON 标签为准；本题使用导出的 `Name` 字段即可被 Go 的 JSON 解码器匹配。请求成功后，当前用户记录的名字变为 `admin`。这不是密码绕过，而是典型的批量赋值：客户端提交了页面未承诺可修改、但后端结构体仍接受的字段。

继续分析 flag 处理函数，可以看到服务端用 `github.com/xlzd/gotp` 校验基于时间的一次性密码，硬编码密钥为：

```text
X5JMTFGT4FVJ34GV
```

可用相同库生成当前 6 位验证码：

```go
package main

import (
    "fmt"

    "github.com/xlzd/gotp"
)

func main() {
    totp := gotp.NewDefaultTOTP("X5JMTFGT4FVJ34GV")
    fmt.Println(totp.Now())
}
```

也可以把该 Base32 密钥导入 Google Authenticator。TOTP 随时间窗口变化，因此不能把某一次运行得到的数字当作固定答案；复现时还要保证本机时间准确。以改名后的管理员会话提交当前验证码，身份判断和 TOTP 判断同时通过后即可取得 flag。

原始服务端项目可参考 [HGAME2020 Week4 ReGo 源码仓库](https://github.com/wuhan005/HGAME2020_Week4_ReGo)。上述正文已展开源码中决定利用结果的两个事实：资料接口接受越权字段，以及 flag 接口使用的 TOTP 密钥与算法。

## 方法总结

- Go 二进制保留了足够的类型和函数信息时，应围绕路由、绑定结构体和数据库更新语句恢复业务数据流，而不是只搜索字符串。
- 页面没有提供某字段，不代表后端不会接受它；更新接口应使用只包含允许字段的请求结构体，并在持久化层显式选择列。
- TOTP 只是第二个条件，不能修补已经失效的身份边界；密钥也不应硬编码在可分发的程序中。
