# Tetris plus

## 题目简述

题目表面上是一个俄罗斯方块游戏，达到指定分数后会执行前端 JavaScript。直接阅读正常分支只能看到一个经过 Base64 编码的假 flag，真正结果藏在同一段脚本中被注释掉的 JSFuck 表达式里。

## 解题过程

打开浏览器开发者工具，在页面加载的 `checking.js` 中定位分数判断。该分支先检查 `score >= 3000 && !window.winned`，随后把 `window.winned` 置真，并用 `alert(atob(encodedText))` 显示一段 Base64 解码结果；紧随其后的注释则保存了一整段 JSFuck 表达式。

因此没有必要真的把游戏打到 3000 分。`atob(...)` 对应的内容只是诱饵；应复制被注释的 JSFuck 表达式，去掉注释标记后在当前页面的控制台中执行。

JSFuck 只使用 `[]()!+` 等少量字符构造 JavaScript 值、属性名与函数调用。虽然表达式很长，但浏览器仍会把它当作普通 JavaScript 求值。执行后得到真正的弹窗调用：

```javascript
alert("hgame{jsfuck_1s_S0_fUu1n}");
```

最终 flag 为：

```text
hgame{jsfuck_1s_S0_fUu1n}
```

## 方法总结

题目的核心是区分“会被正常业务流程执行的诱饵”与“源代码中隐藏的真实逻辑”。遇到前端游戏题时，应优先审计计分判断、胜利回调和注释代码；JSFuck 虽然难以人工阅读，却可以在受控的浏览器上下文中直接求值，再观察其还原结果。执行陌生脚本前仍应确认代码来源和作用域，避免在含有敏感登录状态的页面中运行。
