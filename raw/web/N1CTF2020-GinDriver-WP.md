# N1CTF 2020 GinDriver Writeup

## 题目简述

GinDriver 是一个 Go Web 服务，使用 WebAuthn 登录、JWT 保存身份，并提供数据库配置上传和连接测试功能。题目看似围绕无密码认证，实际利用链跨越三个信任边界：泄露管理员公钥后伪造管理员 JWT；通过配置上传控制 MySQL 客户端参数；再借 `LOAD DATA LOCAL INFILE` 读取服务器本地文件。

服务端源码和出题人的赛后说明均表明，WebAuthn 本身并未被破解。问题在于应用把同一份公开密钥错误地用于 JWT 校验，并允许用户提交会驱动数据库客户端访问本地文件的配置。

## 解题过程

### 伪造管理员会话

注册普通账号并观察前端请求，可以梳理出注册、挑战生成、认证和配置上传等路由。管理员 WebAuthn 公钥可以从应用接口取得，而 JWT 校验逻辑同时接受非对称和对称算法，且没有把算法与密钥类型绑定。

攻击时将 JWT 头部算法改为 HMAC 类算法，把公开可得的管理员公钥字节当作 HMAC 密钥，对包含管理员身份的 payload 重新签名。服务端随后用同一份公钥字节验签，造成典型的 JWT 算法混淆。成功后，受管理员权限保护的配置功能即可访问。

### 借数据库连接读取本地文件

配置上传接口存在路径穿越，可以覆盖应用所使用的数据库配置。连接测试最终由 MySQL 客户端发起，且启用了本地文件加载能力。控制数据库服务器的一方可以在握手和查询过程中要求客户端执行：

```sql
LOAD DATA LOCAL INFILE '/path/to/local/file'
INTO TABLE collected_data
```

这里读取文件的是题目服务器上的 MySQL 客户端，而不是攻击者的数据库主机。搭建一个能够响应 MySQL 协议并发出 `LOCAL INFILE` 请求的恶意服务后，可依次尝试应用配置、进程环境、用户目录和 SSH 相关文件。返回的数据通过数据库协议送回攻击者控制端，从而形成任意文件读取。

### 从文件读取落地到持久访问

基础题只要求拿到 flag，因此读到目标文件即完成。更完整的链条还可以读取用户的 SSH 配置或密钥材料，并利用配置上传的路径穿越写入用户目录。关键点是：JWT 伪造解决授权，数据库客户端解决任意读，路径穿越解决任意位置写，三者缺一不可。

出题人公开的 [GinDriver 源码](https://github.com/evi0s/gindriver) 可用于复现路由、JWT 和数据库配置逻辑；外部项目只提供实现背景，本题所需的关键利用步骤已在上文给出。

## 方法总结

WebAuthn 的存在容易让分析偏向密码学，但决定性缺陷位于认证结果之后。面对组合型 Web 题，应分别追踪“谁能生成身份”“谁验证身份”“高权限功能把哪些数据交给下游客户端”。JWT 必须固定允许算法并校验密钥类型；数据库客户端的 `LOCAL INFILE` 应默认关闭；上传路径则必须在规范化后确认仍位于预期目录。
