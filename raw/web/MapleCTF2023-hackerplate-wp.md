# hackerplate

## 题目简述

应用模拟车牌抽奖：管理员浏览举报生成的 PDF，内部 WebSocket 则用 V8 `Math.random()` 选择每轮候选车牌。攻击链需要先从公开页面把脚本送进内部 PDF 渲染器，再恢复 xorshift128+ 状态，预测目标车牌 `L-337-HX` 出现的轮次并精确停止抽奖。

仓库包含完整源码和官方 solver，但真实 flag 只在部署时通过环境变量注入；离线仓库中的测试值不是赛事 flag，因此本文不伪造一个结果字符串。

## 解题过程

第一阶段取得内部脚本执行。举报机器人只接受 localhost 目标，但公开 `/redirect?url=...` 可以把预览 iframe 导向内部 `/download-report`。该路由使用 EJS 生成 PDF，链接的 `style` 值未转义。用引号结束属性并插入 `<script>`，Puppeteer 渲染 PDF 时便会执行攻击代码；再加入一个长期不结束的图片请求，避免渲染器在异步操作完成前关闭页面。

内部脚本先注册一个满足格式的 17 字符 VIN，再连接仅内网可达的抽奖 WebSocket。服务在每个 tick 预先从 `Math.random()` 生成 50 个缩放浮点数。连续回传这些观察值，攻击端把 IEEE-754 双精度数暴露的高 52 位约束写入 Z3，恢复 V8 xorshift128+ 的两个 64 位状态。

预测时必须复现 V8 的 64 项随机数缓存：引擎成批生成值，却以逆序从缓存中消费，跨缓存边界时不能简单地逐次调用同一 recurrence。恢复正确边界后，向前搜索哪一 tick 的候选索引会命中原始车牌表中编号 228017 的 `L-337-HX`；还要减去已经注册车牌造成的索引偏移。

最后按源码状态机倒推停止命令。总轮数为 600，停止阶段长度为 5，tick 间隔参数为 3；在进入 choosing 状态的正确 tick 发送 stop，使最终选中的候选正好是目标车牌。服务验证命中后返回部署环境中的 flag。

## 方法总结

这题由三个信任边界串联：开放重定向把外部输入送进内网，未转义模板让 PDF 渲染器执行脚本，可观察的 `Math.random()` 再泄露未来抽奖状态。预测 V8 PRNG 不能只实现 xorshift 公式，还必须匹配浮点截断、批量缓存和逆序消费。整理题解时也应把“求解链完整”和“仓库含真实 flag”分开；后者缺失不妨碍复现机制，但不能用测试占位符冒充赛题答案。
