# 组委会模拟器

## 题目简述

页面模拟一个不断刷新的群聊，共有 1000 条定时出现的消息。玩家要在目标消息出现后的 3 秒内撤回所有包含小写 `hack[` 的消息，同时不能误删普通消息。手工点击来不及，关键是利用稳定的 DOM 结构自动识别并触发页面已有的撤回流程。

## 解题过程

后端为每条消息保存文本和出现延迟，判定目标的条件非常直接：

```python
def should_delete(self):
    return "hack[" in self.text
```

撤回接口还会校验消息编号和时间：请求比消息出现更早会被视为时间穿越，出现超过 3 秒才请求则超时；删除非目标消息同样会使最终检查失败。全部 1000 条消息结束后，只有“所有目标均删除、所有非目标均保留”才能取 flag。

前端把每条消息文本放在 `.fakeqq-message__bubble` 元素中，点击气泡会调用页面自身的 `revoke` 逻辑，再由它向 `/api/deleteMessage` 提交正确的消息编号。因此不必重新实现计时和编号映射，只需在消息出现后尽快点击所有匹配气泡。在浏览器控制台执行：

```javascript
setInterval(() => {
  document
    .querySelectorAll(".fakeqq-message__bubble")
    .forEach((element) => {
      if (element.textContent.includes("hack[")) {
        element.click();
      }
    });
}, 100);
```

应在新一局开始后立即执行脚本；若已有目标消息出现超过 3 秒，应重开本局，不能指望补删通过。100 毫秒的轮询周期远小于 3 秒容差。目标气泡第一次被点击后会进入撤回状态并从可匹配文本中消失，因此后续轮询不会反复误删；普通消息不包含精确的小写子串 `hack[`，不会被点击。保持页面和控制台运行，等待消息播放完毕，再使用页面的取 flag 操作即可通过后端完整性检查。

## 方法总结

本题的关键在浏览器 DOM 自动化与 Web 接口时序，因此归类为 Web。可靠方案应复用前端已经维护好的消息编号和撤回请求，只把人类难以完成的“及时筛选并点击”自动化。筛选条件必须与服务端完全一致：大小写、左方括号都属于判定的一部分；使用更宽泛的 `flag` 或 `hack` 会误删诱饵消息并导致整局失败。
