# Evalgelist

## 题目简述

页面接受 `input` 参数，删除一组字符后在末尾追加 `();`，再交给 PHP `eval()`：

```php
$filtered = str_replace(
    ['$', '(', ')', '`', '"', "'", "+", ":", "/", "!", "?"],
    '',
    $_GET['input']
);
$cmd = $filtered . '();';
eval($cmd);
```

过滤器禁用了引号、变量、括号和斜杠，却保留了分号、点号、数组下标和 PHP 的语言结构。容器使用 PHP 7.3，并把 flag 写在绝对路径 `/flag`。目标是无需输入被过滤的 `/` 与引号，构造出 `include "/flag"`。

## 解题过程

### 用分号摆脱函数名上下文

程序本来希望用户只输入 `phpinfo` 一类函数名，再自动补成：

```php
phpinfo();
```

但分号没有被删除，可以先结束一条自定义语句。由于末尾固定存在 `();`，还应在载荷末尾放一个合法函数名，使追加部分能够正常解析。

### 无引号构造 `/flag`

`include` 是 PHP 语言结构，不要求写成函数调用，因此被删除的括号不会造成影响。PHP 还预定义了字符串常量 `PHP_MANDIR`，其值是 PHP 手册目录的绝对路径，首字符必然为 `/`。数组下标没有被过滤，所以：

```php
PHP_MANDIR[0]
```

可以取得字符串的第一个字符。容器使用 PHP 7.3；在这个版本中，未定义的裸标识符 `flag` 会在告警后按字符串 `"flag"` 处理。点号也未被过滤，于是：

```php
PHP_MANDIR[0].flag
```

计算结果就是 `/flag`。

### 完整载荷

提交：

```php
include PHP_MANDIR[0].flag;phpinfo
```

过滤后字符不变，服务追加 `();` 后实际执行：

```php
include PHP_MANDIR[0].flag;phpinfo();
```

第一条语句包含 `/flag`，其内容会进入输出缓冲区；第二条语句吸收固定追加的括号并保持整体语法有效。页面最后虽然用 `htmlspecialchars()` 转义结果，但 flag 仍以普通文本显示。

如果通过 URL 手工发送，参数值中的空格和分号需要正常 URL 编码；不要直接写 `/flag`，因为斜杠会在服务端过滤阶段被删除。

## 方法总结

黑名单只移除了部分“危险字符”，却没有限制输入必须是单个函数标识符。分号把输入重新提升为任意语句，`include` 绕过括号限制，预定义路径常量和字符串下标又合成了被禁用的斜杠。

这个载荷依赖 PHP 7 对未定义常量的兼容行为；在 PHP 8 中裸 `flag` 会抛出 `Error`，不能照搬。容器的 `FROM php:7.3-fpm-alpine` 因而是利用条件，而不是无关的部署细节。另一份复现可参照 [Threalwinky 的 R3CTF 2025 题解](https://threalwinky.github.io/post/r3ctf2025/)，正文已包含完整过滤结果和版本要求。
