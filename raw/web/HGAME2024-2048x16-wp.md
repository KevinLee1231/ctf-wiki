# 2048*16

## 题目简述

题目是带有禁用右键/F12、`debugger` 反调试和 JavaScript 混淆的 2048 类网页游戏。flag 不是从游戏状态本身计算出来，而是藏在“胜利”分支调用的字符串解码逻辑中；只要定位并强制触发该分支，就不必真正完成游戏。

## 解题过程

首先通过浏览器菜单进入“更多工具 → 开发者工具”，绕过页面对 F12 和右键的拦截。若脚本持续触发 `debugger`，根据暂停时的调用栈定位反调试代码，将脚本保存到本地覆盖版本并删除对应语句，或在开发者工具中停用断点。

混淆代码把字符串集中存入数组，通过 `h(编号)` 计算偏移后取值。搜索界面上可观察到的 `Game Over!`，可以定位到游戏结束处理函数。官方题解找到的关键分支为：

```javascript
g[h(432)][h(469)] = function (x) {
    var n = h;
    var cssClass = x ? "game-won" : n(443);
    var message = x
        ? s0(n(439), "V+g5LpoEej/fy0nPNivz9SswHIhGaDOmU8CuXb72dB1xYMrZFRAl=QcTq6JkWK4t3")
        : n(453);

    this[n(438)][n(437)].add(cssClass);
    this[n(438)][n(435)]("p")[0].textContent = message;
};
```

原式中的数组下标是 `-1257 * -5 + 9 * 1094 + -5377 * 3`，计算结果为 0，因此上面直接写成 `[0]`。形参 `x` 决定是否进入胜利分支。最直接的验证方法是在函数入口下断点，故意输掉游戏使函数被调用，然后在控制台把 `x` 改为 `true` 后继续执行。页面随即应用 `game-won` 样式，并由 `s0` 解码、显示胜利文本中的 flag。

## 方法总结

- 核心技巧：清理浏览器反调试，借助界面字符串定位结束函数，再篡改分支参数强制进入胜利路径。
- 识别信号：网页游戏只在胜利时显示秘密，脚本中存在字符串数组映射、动态属性名和显式 `debugger`。
- 复用要点：不必先完整反混淆整个程序；从稳定的界面文本和 DOM 写入点反向追踪，通常能更快收敛到真正承载 flag 的分支。
