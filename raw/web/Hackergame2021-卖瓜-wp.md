# 卖瓜

## 题目简述

服务端用 6 斤和 9 斤两种瓜更新会话中的整数 `pool`，目标是让它严格等于 20。正常整数线性组合始终能被 3 整除，因此不可能得到 20；突破口是 PHP 在整数乘法溢出后自动转为浮点数，随后 `intval` 把超出范围的浮点数转换回平台整数时产生异常的环绕结果。

核心逻辑可概括为：

```php
$bottle_6 = intval($_POST['b6']);
$bottle_9 = intval($_POST['b9']);
if ($bottle_6 < 0 || $bottle_9 < 0) {
    die();
}
$_SESSION['pool'] += intval($bottle_6 * 6 + $bottle_9 * 9);

if ($_SESSION['pool'] === 20) {
    // return flag
}
```

## 解题过程

### 为什么普通输入无解

每次正常更新量都是 $6a+9b=3(2a+3b)$，从初始值 0 出发，`pool` 永远是 3 的倍数，而 $20\not\equiv0\pmod3$。

### 利用整数到浮点数的类型切换

在 64 位 PHP 上，只要乘积超过 `PHP_INT_MAX`，运算结果就会变成精度有限的 IEEE 754 双精度浮点数。`intval` 再把这个越界浮点数转回整数时，结果不再保持原本的模 3 性质。

一种较短的两次提交方案是只填写 9 斤瓜数量：

```text
第 1 次：b6=0, b9=1500000000000000000
第 2 次：b6=0, b9=549638230412172404
```

在题目使用的 PHP/x86-64 环境中，两次 `intval(b9 * 9)` 的异常转换结果相加恰好为 20。第二次请求后，严格比较 `$_SESSION['pool'] === 20` 成立，服务端返回 flag。

这个数值依赖题目运行时的浮点舍入和越界转换行为；复现时应使用与题目一致的 PHP 版本和 64 位整数环境，而不能仅用任意语言的大整数运算验证。

## 方法总结

- 核心技巧：利用 PHP 整数乘法溢出后的浮点提升，以及越界浮点数再转整数时的实现行为。
- 识别信号：目标值受模约束明显不可达，但源码混用 `intval`、超大用户输入、整数乘法和严格类型比较。
- 复用要点：先证明正常整数域无解，再检查类型提升边界；浮点到整数的越界结果具有平台依赖性，payload 必须在目标运行时验证。
