# Hackergame2020 签到 WP

## 题目简述

页面提供一个滑杆，并根据提交的 `number` 参数决定“提取多少个 flag”。滑杆的前端脚本会在值恰好为 `1` 时把它改成 `1.00001` 或 `0.99999`，因此正常拖动无法停在目标值。决定性问题是服务端接受浏览器提交的查询参数，而不是滑杆这个界面本身。

## 解题过程

先提交滑杆当前值，可以从响应中确认服务端要求的是正整数。观察地址栏或表单请求后，会发现数值直接放在 `number` 查询参数中。于是无需操纵滑杆，只要把请求改成：

```text
/?number=1
```

服务端收到整数 `1` 后直接返回个人化 flag。

若希望从页面内完成，也可以在开发者工具 Console 中直接设置 DOM 值，再点击提交：

```javascript
document.querySelector('#number').value = 1;
```

这能生效，是因为脚本只在滑杆触发 `input` 事件时执行“避开 1”的逻辑；直接赋值并提交不会重新触发该分支。官方材料中的两张统计图只记录参赛者提交值的分布，与解题机制无关，因此不归档。

## 方法总结

这题考查的是不要把前端控件当作安全边界。HTML 属性、JavaScript 事件和滑杆步长都只能约束正常交互，攻击者可以直接修改查询参数、表单数据或 DOM。分析 Web 题时应先定位最终请求及服务端判定条件，再判断界面限制是否真的参与校验。
