# data-explorer

## 题目简述

服务允许上传 SQLite 数据库，并提供一个数据浏览接口。查询构造器会给列名加引号，排序方向则只靠 Python `assert` 限制为 `ASC` 或 `DESC`。容器以 `PYTHONOPTIMIZE=1` 启动，所有 assert 在运行时被移除，排序方向因此成为原样拼接的 SQL 注入点。

接口总共只允许执行两次查询，不能按传统布尔盲注逐字符请求。

## 解题过程

先制作一张攻击者控制的表。放入 16 行十六进制标记 `c0` 到 `cf`，为它们分配递增奇数排序值；再放入 128 行位置标记 `p0` 到 `p127`。注入的 ORDER BY 表达式从服务端秘密 key 中取指定位置字符，用 `instr` 查出它在字符串 `0123456789abcdef` 中的序号，再映射为相邻的偶数排序值：

```sql
iif(
  <row is a position marker>,
  instr('0123456789abcdef', substr((SELECT key FROM secrets), <position>, 1)) * 2,
  <marker's odd value>
)
```

查询结果排序后，每个 `pN` 会落在对应十六进制标记旁边。客户端不需要看到秘密列，只需扫描返回行顺序，判断每个位置标记位于哪两个 `cX` 标记之间，即可恢复该位置的十六进制字符。一条查询并行编码 128 个位置，第二条把位置偏移 128，正好还原全部 256 个字符。

将拼出的完整 key 提交到升级接口，应用授予权限并返回：

```text
maple{0rder_by_1nject1on_is_v3ry_powerfuL!_b5e3b549713b0cd0}
```

## 方法总结

`assert` 是开发期断言，不是输入校验；优化模式会把它彻底删除。有限查询盲注的关键是提高单次响应的信息容量，本题利用攻击者可控行的相对顺序，把 128 个十六进制符号并行编码在一张结果表中。设计接口时应对排序方向使用固定枚举分支，绝不能把用户字符串拼接进 SQL 语法位置。
