# Failed Extraction

## 题目简述

题目给出 Linux 内存镜像，要求定位客户端进程中一段可疑映射并尝试提取。官方附件本身不足以稳定恢复预期文件，因此比赛最终接受映射起始地址与长度，而不是声称已经成功导出了未知载荷。

## 解题过程

先用镜像信息确定内核版本为 Linux `5.13.0-39`，再枚举进程找到 PID 1946 的 `client`。查看该进程内存映射时，可疑的单页区域为：

```text
0x000055d125526000 - 0x000055d125527000
```

区间长度是：

$$
0x000055d125527000-0x000055d125526000=0x1000=4096.
$$

这里的真实长度是十进制 `4096`，规范十六进制应写成 `0x1000`。但官方题解把十进制数字 `4096` 直接加上了 `0x` 前缀，比赛接受串也沿用了这个不规范写法。官方尝试使用类似 `dd` 的方式抽取该页，但保存下来的材料无法证明抽取文件具有可解释内容，因此应精确保留官方答案字符串：

```text
n00bz{0x000055d125526000, 0x4096}
```

## 方法总结

内存取证必须区分“定位到映射”与“成功恢复载荷”。进程列表、映射边界和区间长度均有镜像证据支持；提取物若无法验证文件头、哈希或语义，就不应在 WP 中夸大为完整恢复。
