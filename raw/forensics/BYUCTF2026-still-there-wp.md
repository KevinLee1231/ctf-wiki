# Still There

## 题目简述

同一份网络抓包中包含一系列 ICMP Echo Request。隐藏内容被切成四字节片段放进请求负载，并通过 ICMP 序号给出重组顺序。

## 解题过程

先过滤 `icmp.type == 8`，导出每个请求的序号和数据字段。不要直接按抓包出现顺序拼接，因为重传或乱序会破坏结果；应以 `icmp.seq` 排序，然后依次连接负载。

使用 tshark 可以先得到便于处理的两列：

    tshark -r GLaDOS_Network.pcapng -Y "icmp.type == 8" \
      -T fields -e icmp.seq -e data.data

将十六进制数据还原为字节并按序号连接，得到完整明文：

    byuctf{Turr3t_R3d3mpt!0n_L!n3s_4r3_N0t_R!d3s}

原仓库中的截图只是把 ICMP 序号和负载列显示出来，文字步骤已经完整保留证据，因此无需继续引用截图。

## 方法总结

协议隐蔽数据的关键是找出“载荷在哪里”和“顺序由什么决定”。本题载荷本身未加密，真正容易遗漏的是按协议序号重组。提取时还应去重，并确认每个片段长度及序号是否连续。
