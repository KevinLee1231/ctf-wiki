# sneaker-zipper

## 题目简述

附件是一个 ZIP，内部有名为 `flag/` 的目录和大量内容相同的诱饵文本。异常点在于 ZIP 的目录条目本身声明了 58 字节数据；常规解压只创建目录，容易忽略这段载荷。

## 解题过程

先列出中央目录可看到 `flag/` 的长度并非 0：

```bash
unzip -l chall.zip
```

不要递归查看一百个诱饵文件，而是让 `unzip -p` 直接把目录条目的数据写到标准输出：

```bash
unzip -p chall.zip 'flag/'
```

输出即为：

```text
tjctf{sneakers_with_zippers_are_hip_no?_874d174bb26fcf95}
```

各个 `flag-*.txt` 仅重复 `your flag is in another castle`，与真正载荷无关。ZIP 规范中的文件名末尾斜杠通常表示目录，但“目录项必须没有文件数据”只是工具惯例，并非解析时可盲信的安全条件。

## 方法总结

- 归档取证要比较条目类型、声明长度与实际数据，目录条目也可能携带内容。
- `unzip -p` 可读取指定条目的原始解压数据，避免落盘行为把异常目录语义掩盖掉。
- 大量同质诱饵应先做计数与去重，真正异常往往体现在中央目录属性而非文件名。
