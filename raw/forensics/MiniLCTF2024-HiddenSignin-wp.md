# miniLCTF 2024 HiddenSignin Writeup

## 题目简述

附件是一个 `volume.hc`，题面同时给出由大量汉字组成、前后以 `65536` 标记的第一段密钥。题目围绕“隐藏”连续设置了 Base65536 编码、VeraCrypt 加密卷、图像最低有效位、VeraCrypt 隐藏卷、零宽字符和回收站残留等多层线索。

本题归入取证而非单纯隐写：决定性目标是从加密卷及其文件系统残留中恢复真实文件；图像 LSB 只是中间密钥的承载方式。

## 解题过程

### 解出外层卷

题面中的关键字符串为：

```text
65536/////洰驦栶椶昳湥顥氳椸洸汣敥鬹渳止敦騲驤攷騰昷朶杤湤氳阶氱橡止杤湣騷/////65536
```

`65536` 是编码类型提示。去掉两端分隔符后按 Base65536 解码，得到第一把口令。随后用 VeraCrypt 挂载 `volume.hc` 的普通卷：

```text
VeraCrypt -> Select File -> volume.hc -> Mount
```

挂载时使用刚解出的口令，不要勾选“以隐藏卷挂载”。外层卷中应出现 `keyinside.png`。

### 从图像恢复第二把口令

将 `keyinside.png` 放入 StegSolve 或等价的位平面查看器，分别检查：

```text
Red plane 0
Green plane 0
Blue plane 0
```

三个颜色通道最低位组合出的图像包含 `The Second Key`。这一信息依赖像素平面的空间排列，若归档原始解题截图就应保留该结果图；当前源仓库没有保存 `keyinside.png` 或对应截图，因此本文不能补造图片或第二把口令。

### 进入隐藏卷并恢复真实 flag

再次选择同一个 `volume.hc`，改用第二把口令挂载。VeraCrypt 会根据口令自动识别隐藏卷，无需另选附件。隐藏卷根目录中的 `Flag.txt` 是诱饵：文件显示内容与实际大小不一致，说明其中混有零宽 Unicode 字符。解码这些零宽字符得到的只是“去回收站查找”这一提示。

正确做法是把卷作为文件系统证据打开，检查回收站目录：

```text
$RECYCLE.BIN/
```

在 Windows 取证工具或能够显示隐藏系统目录的非 Windows 文件管理器中，可从回收站对象恢复 `RealFlag`。不要把诱饵 `Flag.txt` 的可见内容当作最终答案。

当前公开仓库仅保留题面和外层 `volume.hc`，没有保存第一把口令的解码结果、解密后的 `keyinside.png`、第二把口令以及隐藏卷中的 `RealFlag` 内容；以上流程来自官方题解并可由完整赛题附件复现，但本文据此明确停止，不虚构缺失的 flag。

## 方法总结

本题每一层都在提示下一层：Base65536 给出外层口令，RGB LSB 给出隐藏卷口令，零宽字符再引向回收站。处理加密卷题时，挂载后不仅要看正常文件，还要核对文件大小、隐藏目录、删除记录和卷类型。证据不完整时，应保留可验证的操作链并明确缺失边界，而不是从题解措辞猜测最终内容。
