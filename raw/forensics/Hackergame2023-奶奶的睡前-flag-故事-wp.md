# 奶奶的睡前 flag 故事

## 题目简述

附件是一张由 Pixel 3 旧版系统生成并裁剪过的 PNG 截图，画面只保留了故事开头。目标是利用 aCropalypse（CVE-2023-21036）留下的文件尾部数据，恢复裁剪前截图底部的 flag。

## 解题过程

PNG 正常应在 `IEND` 数据块结束后立即终止。对附件执行：

```bash
zsteg screenshot.png
```

可看到文件在首个 `IEND` 后仍有 `184073` 字节数据。对原文件做结构核对也得到相同结果：首个 `IEND` 块结束位置为 `0x4e908`，整个文件大小为 `505873` 字节，并且文件尾部还能找到第二个 `IEND`。

这正是 aCropalypse 的特征。受影响的 Android 截图编辑器保存裁剪结果时，会从原文件开头覆盖写入新的 PNG，却没有把旧文件截短。新图较小时，原始 PNG 后半段的压缩数据便残留在新 `IEND` 之后。恢复工具可以结合新图结构与残留的 DEFLATE 数据，重建部分裁剪前画面。

在 aCropalypse 恢复工具中选择设备 `Pixel 3`，上传 `screenshot.png` 并执行恢复。所得图像的上半部因缺失数据而损坏，但原截图底部仍能重建，flag 清晰可读：

```text
flag{sh1nj1ru_k0k0r0_4nata_m4h0}
```

![aCropalypse 恢复出的裁剪前长截图，底部重新出现完整 flag](Hackergame2023-奶奶的睡前-flag-故事-wp/recovered-original.png)

## 方法总结

本题从已经取得的数字文件中恢复被裁剪前的数据，决定性障碍是文件取证，而不是有意设计的像素隐写，因此归类为 Forensics。排查可疑 PNG 时，不应只看渲染结果和元数据，还要验证数据块边界、首个 `IEND` 后是否存在异常尾随数据，以及尾部能否与已知漏洞的写文件行为对应。恢复图只作为视觉验证保留，关键字节数、漏洞机制和 flag 已在正文中完整记录。
