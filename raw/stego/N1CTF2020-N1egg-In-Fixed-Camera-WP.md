# N1CTF 2020 N1egg In Fixed Camera Writeup

## 题目简述

这是 Fixed Camera 场景中的隐藏彩蛋。主线 flag 通过修改摄像机角度后在场景内可见，而 `N1egg` 作为另一段隐藏文本被放在正常镜头背面/关卡资源中。其决定性障碍是定位有意隐藏的空间或资源载荷，因此归入隐写。

## 解题过程

### 方法一：越过摄像机限制观察场景

沿用 Fixed Camera 的 IL2CPP 分析结果，定位摄像机对象的 `angleY`，补丁角度上下界或直接修改真实字段。正常玩家视角只覆盖很小的俯仰范围；把镜头转向背面并绕场景移动，可以看到不属于主线展示区域的彩蛋文本。

这里要修改持续状态而不是一帧缓存。如果数值立即回弹，应继续追踪摄像机更新函数的写入点，禁用范围钳制后再旋转。

### 方法二：直接搜索关卡资源

Unity 关卡文件 `level0` 中仍保存了文本对象内容。无需完整启动游戏，直接对资源执行字符串扫描：

```bash
strings -a level0 | grep -E 'n1egg\{|n1ctf\{'
```

即可找到：

```text
n1egg{you_found_the_eggs}
```

若 `strings` 未命中，应使用 Unity 资源解析器查看 `TextAsset`、`MonoBehaviour` 和场景 GameObject，而不是对二进制做无目标的编码爆破。

### 图片取舍

官方材料只有“彩蛋在摄像机背后或搜索内存”的简短截图说明。空间位置和资源搜索命令已经完整表达关键视觉信息，截图不增加独立证据，因此未归档图片。

## 方法总结

游戏隐写题的载荷可能同时存在于场景空间和序列化资源。先扩大相机/角色可达范围，再对关卡资源做字符串和对象级检查，通常能相互验证。分类时应看“flag 为何不可见”：本题不是破解相机加密算法本身，而是发现被刻意藏在正常视野之外的彩蛋。
