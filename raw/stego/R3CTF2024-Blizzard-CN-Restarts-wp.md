# Blizzard CN Restarts

## 题目简述

附件 `R3ctf.w3x` 是一张 Warcraft III 地图。`.w3x` 并不是单一场景文件，而是带 Warcraft 地图头的 MPQ 容器；触发器文本、地图脚本、对象数据和资源都以独立成员存放其中。

flag 被有意藏在地图内部的触发器字符串表，而不是像素或文件尾追加数据，因此本题归入隐写/隐藏载荷提取。

## 解题过程

先检查文件头：

```text
00000000  48 4d 33 57 ... 52 33 43 54 46 ...
          H  M  3  W
```

`HM3W` 是 Warcraft III 地图包装头的字节表现，后面包含 MPQ 数据。普通 ZIP 解压器无法正确读取，应该使用支持 Warcraft 地图的 MPQMaster、Ladik's MPQ Editor、StormLib 工具或地图解包器。

一种通用流程是：

1. 让 MPQ 工具识别 `.w3x` 的地图头并打开内嵌归档；
2. 导出文件列表；
3. 提取 `war3map.wts`；
4. 按文本查看或搜索 `r3ctf{`。

```bash
rg -n -i "r3ctf\\{" war3map.wts
```

`war3map.wts` 是 World Editor 使用的触发器字符串表，常见格式为：

```text
STRING <编号>
{
字符串内容
}
```

在该文件中可以直接找到：

```text
r3ctf{Elune_be_with_you}
```

不需要启动 Warcraft III，也不需要执行地图脚本。若工具只导出了原始 MPQ 而没有正确识别地图包装头，应先按工具说明剥离/指定 W3X 头偏移，再重新读取归档，不能把整个文件当作标准 MPQ 从偏移 0 强行解析。

## 方法总结

这道题考查游戏地图格式识别。遇到可正常加载的游戏关卡文件，应先判断它是单文件格式还是资源容器，再检查脚本、字符串表和对象元数据。`war3map.wts` 保存触发器可见文本，是 Warcraft III 地图中最值得优先检查的成员之一。提取到明确字符串后即可停止，不必把简单容器题扩展成地图逻辑逆向。
