# At0m 的给你们的（迟到的）情人节礼物

## 题目简述

题目附件表面上包含一个普通视频，实际利用 RAR 对 NTFS Alternate Data Streams（备用数据流）的保留能力，把提示文本藏在 `gift.mp4:hide.txt` 中。提示文本用手动挡换挡方向编码出一串数字，再将这串数字作为 MSU StegoVideo 的解码口令，从视频中提取 flag。

## 解题过程

首先确认压缩包格式。附件虽然可能使用了误导性的扩展名，但文件头表明它是 RAR；这一点很重要，因为 WinRAR 能保存 NTFS 备用数据流。应在 Windows 的 NTFS 分区上用 WinRAR 解压，并保留文件流。若改用不支持 ADS 的解压器，或把文件先放到 FAT/exFAT 等文件系统，隐藏流可能直接丢失。

PowerShell 可以枚举视频上的数据流：

```powershell
Get-Item -Path ".\gift.mp4" -Stream *
```

除默认的 `:$DATA` 外，还会看到 `hide.txt`。读取它：

```powershell
Get-Content -Path ".\gift.mp4" -Stream "hide.txt"
```

内容由 `up`、`down`、`left`、`right` 等方向词组成，并以数字 `4` 开头。这里不是普通方位编码，而是在描述手从当前挡位移动到下一个挡位的轨迹；“油门”表示保持当前挡位对应的数据。按常见手动挡挡位图跟随整段移动方向，把每次到达的挡位数字依次记录，得到：

```text
6557225
```

官方 PDF 只保留了这一中间结果。[比赛期间的公开复现记录](https://www.cnblogs.com/zysgmzb/p/15882495.html)进一步确认了两个容易踩坑的细节：隐藏文本确实位于 `gift.mp4:hide.txt`，早先对 `gift2` 使用口令 `123456` 得到的只是干扰结果，真正目标应是 `gift.mp4`。

从题目 hint 视频中还能看到作者使用了 MSU StegoVideo。打开该工具的解码/恢复界面，选择 `gift.mp4` 作为载体，将 `6557225` 填入口令或密钥字段并执行提取，输出数据即为 flag。官方 PDF 与现存公开复现均未记录最终 flag 字符串，因此本文不凭空补写；但从 ADS 恢复、换挡解码到视频隐写提取的操作链已经闭合，持有原附件即可复现最终输出。

## 方法总结

本题最容易失败的地方不是算法，而是文件系统语义：ADS 不属于普通文件正文，跨文件系统复制或使用不支持它的解压器都会丢证据。发现 RAR、NTFS 和“文件看起来正常但体积或结构异常”同时出现时，应主动枚举备用数据流。恢复提示后再根据词汇语境识别换挡轨迹，最后把所得数字交给题面 hint 指向的视频隐写工具即可。
