# tictactoe

## 题目简述

附件是一个 Android APK。应用先异或解密一组字符串，得到 Telegram 频道邀请链接；频道描述包含一个用于解密本地文件的十六进制/文本密钥和对应文件索引。解密后的文件是 DEX 模块，应用通过 Android 动态加载机制调用其中代码。

默认流程只处理第一个模块后停止，而真正打印 Flag 的逻辑位于第 18 个模块。题目分三部分，分别要求识别外部域名、恢复索引 2 的密钥，以及执行或还原最终 DEX。

## 解题过程

先用 JADX 打开 APK，搜索字符串解密、网络请求和 DEX 加载相关调用。需要串起的流程是：

```text
硬编码密文字符串
    -> XOR 解出 Telegram 邀请链接
    -> 读取频道描述中的 key 和 index
    -> key 解密对应本地文件
    -> DexClassLoader 动态加载并调用模块
```

从解密后的链接可确认应用访问的域名为：

```text
t.me
```

继续按源码中的解析方式读取频道描述，即可取得索引 2 的密钥：

```text
hBc63dbs
```

最后一部分有两条等价路径：

1. 静态修改循环/返回逻辑，让应用不要在第一个模块后停止，依次解密到第 18 个 DEX；
2. 使用 Frida Hook 控制“当前索引”或模块选择函数，重复调用解密和加载路径，直接跳到目标模块。

为了避免网络内容变化，实际操作时应把每次获得的 `index`、`key` 和解出的 DEX 保存到本地，再用 JADX 检查模块行为。第 18 个模块会把最终 Flag 写入 Logcat：

```text
grey{dont_install_apps_outside_of_play_store!_1bdac4980ebd7}
```

## 方法总结

- 核心技巧：跟踪 Android 应用的字符串解密、外部配置和 `DexClassLoader` 动态模块链，并绕过只执行首个模块的控制流。
- 识别信号：APK 联系外部频道、响应中包含 key/index、本地存在多份加密 DEX、动态加载后反射调用。
- 复用要点：外部配置可能失效，应及时保存中间 DEX 和键值；静态补丁与 Frida Hook 都应以同一条加载链为验证依据。
