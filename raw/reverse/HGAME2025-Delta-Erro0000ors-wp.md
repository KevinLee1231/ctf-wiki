# Delta Erro0000ors

## 题目简述

附件是一个 Windows 程序。它调用 `ApplyDeltaB` 对输入应用增量补丁，随后校验目标数据的哈希；题目故意破坏了哈希，使 API 在目标内容已经生成后报错，并通过结构化异常处理转入后续逻辑。程序允许回填一次正确 MD5，之后把恢复出的目标字符串作为循环异或密钥校验 flag。

## 解题过程

### 利用失败后的中间结果

`ApplyDeltaB` 的关键顺序是“先生成增量目标，再做哈希校验”。题目中的错误哈希导致最终验证失败并抛出异常，但目标缓冲区仍留在进程内存中。由于源数据与目标数据差异很大，这段新生成的内容很容易在调试器的内存中辨认。

异常表会让 IDA 的控制流恢复不完整。官方题解通过 NOP 掉异常入口附近的一条跳转，使反编译器显示正常的处理路径；动态分析时则可直接在 `ApplyDeltaB` 返回/抛错处检查目标缓冲区。内存中得到的关键字符串是：

```text
Seven says you're right!!!!
```

字符串在程序中作为 C 字符串参与定长哈希，末尾的 `0x00` 也属于被校验的 28 字节数据：

```text
53 65 76 65 6E 20 73 61 79 73 20 79 6F 75 27 72
65 20 72 69 67 68 74 21 21 21 21 00
```

因此回填值必须是这 28 字节的 MD5，而不是只对 27 个可见字符求哈希：

```text
44d292ffe2e91730ae69eb50ae11d04a
```

### 恢复循环异或密钥

最终加密只有循环异或。即使尚未定位目标字符串，也可以用已知 flag 前缀 `hgame{` 与密文前 6 字节异或，得到密钥前缀 `Seven `，再据此搜索进程内存，定位完整字符串。

下面的脚本同时验证 MD5 并解密 43 字节密文：

```python
import hashlib


key = b"Seven says you're right!!!!\x00"
cipher = bytes([
    0x3B, 0x02, 0x17, 0x08, 0x0B, 0x5B, 0x4A, 0x52,
    0x4D, 0x11, 0x11, 0x4B, 0x5C, 0x43, 0x0A, 0x13,
    0x54, 0x12, 0x46, 0x44, 0x53, 0x59, 0x41, 0x11,
    0x0C, 0x18, 0x17, 0x37, 0x30, 0x48, 0x15, 0x07,
    0x5A, 0x46, 0x15, 0x54, 0x1B, 0x10, 0x43, 0x40,
    0x5F, 0x45, 0x5A,
])

print(hashlib.md5(key).hexdigest())
plain = bytes(value ^ key[i % len(key)] for i, value in enumerate(cipher))
print(plain.decode())
```

输出为：

```text
44d292ffe2e91730ae69eb50ae11d04a
hgame{934b1236-a124-4150-967c-cb4ff5bcc900}
```

## 方法总结

- 核心技巧：利用增量补丁“先产生目标缓冲区、后校验失败”的时序，从异常现场恢复中间结果，再通过已知明文定位循环异或密钥。
- 识别信号：API 返回失败并不代表所有输出都被回滚；当程序故意破坏哈希、进入异常处理且源/目标差异明显时，应检查输出缓冲区是否已经写入。
- 复用要点：C 字符串的显示长度和参与哈希/加密的缓冲区长度可能不同。本题必须把结尾 `0x00` 同时计入 MD5 和 28 字节循环密钥，否则回填与第 28 字节之后的解密都会出错。
