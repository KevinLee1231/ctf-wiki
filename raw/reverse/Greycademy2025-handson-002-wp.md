# handson-002

## 题目简述

这也是一道人为设计的 GDB 观察练习，而不是漏洞利用题。程序在寄存器中写入常量，然后要求提交 `r12` 的值和当前函数保存的返回地址；两项正确后才启动 shell。

## 解题过程

在 `level` 中选择写入 `r12` 之后的 `puts` 调用设置断点：

```gdb
disassemble level
break *0x40123b
run
info registers r12
```

可以看到：

```text
r12 = 0xc4febabe
```

第二项可在断点处读取 `rsp`/`rbp` 并用 `x/gx` 检查栈，也可直接从非 PIE 反汇编确定。`main` 在 `0x4013bf` 调用 `level`，所以压栈的返回地址是紧随调用之后的 `0x4013c4`；源码中的 `(&attempt)[2]` 正是在读取这一保存的 RIP。

提交 `0xc4febabe` 和 `0x4013c4` 后程序执行 `/bin/sh`，读取服务端文件得到：

```text
flag{gdb_pr0digy}
```

## 方法总结

函数调用会把下一条指令地址压栈，因此“保存的返回地址”可通过栈查看，也可由 `call` 后继地址推导。只有在目标非 PIE 时，这个代码地址才可直接复用；若启用 PIE，则还必须先获得模块加载基址。
