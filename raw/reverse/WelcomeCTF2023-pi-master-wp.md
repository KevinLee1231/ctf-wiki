# pi_master

## 题目简述

服务端声称会随机询问圆周率中的不同区间，并要求在很短时间内连续回答 314 次。源码先生成随机 `offset` 和 `len`，但紧接着把它们固定覆盖为：

```python
offset = 2
len = 2
```

因此每一轮实际都询问从第 2 位开始的两个数字，即 `14`。主要障碍是发现程序语义与题面不一致并自动完成重复交互。

## 解题过程

发送 `y` 开始后，对 314 个提示重复回复 `14` 即可：

```python
from pwn import remote

p = remote("HOST", PORT)
p.sendlineafter(b"> ", b"y")

for _ in range(314):
    p.recvuntil(b"> ")
    p.sendline(b"14")

p.interactive()
```

官方脚本也提供了通用写法：从题目文本中解析长度和偏移，再从本地圆周率数字文件切片回答。但在当前源码中固定覆盖使所有问题相同，不需要加载一百多万位圆周率。

完成 314 轮后输出：

```text
greyctf{m3m0r1s3d_4_m1ll10n_dig1ts_0f_pi}
```

## 方法总结

- 核心技巧：审查赋值顺序，发现随机参数被后续常量覆盖，再自动化重复交互。
- 识别信号：题面强调随机或海量数据，但源码在使用前重新赋固定值。
- 复用要点：先确认服务端最终使用的变量值，再决定是否真的需要准备大型数据集；不要被未生效的随机代码误导。
