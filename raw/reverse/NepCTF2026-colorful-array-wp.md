# NepCTF2026 ColorfulArray Writeup

## 题目简述

程序是一个被 UPX 包裹的 FlipJump 单指令集虚拟机。真实校验逻辑并不直接存在于原生代码中，而是先由 C 代码经 `c2fj` 编译为 FlipJump，再把若干 RISC-V 片段和数据嵌入虚拟机镜像。题目要求从多层执行结构中恢复 flag 约束。

最终校验要求输入长度为 33，并检查 `NepCTF{...}` 的前后缀。中间内容还经过逐字节异或和一组 16 位递推关系。

## 解题过程

先处理最外层 UPX。由于样本被修改，直接 `upx -d` 不一定成功；动态运行到解压完成后的最终跳转，在原始入口点附近转储内存并修复映像，便可得到较干净的主体。

主体是 FlipJump：每条指令只包含“翻转某一位”和“跳转到下一地址”两个动作。结合解释器的取指方式定位虚拟机内存，并从映像中提取可执行段与数据段。附件的构建痕迹表明其由 `c2fj` 生成，因此内层实际是 RISC-V 校验程序；按段地址恢复后，可交给普通 RISC-V 反汇编器分析。

还原出的检查流程可概括为：

1. 输入总长度必须为 33；
2. 开头和结尾必须符合 `NepCTF{...}`；
3. flag body 的前 10 个字节分别与下标异或；
4. 按 5 组、每次跨 5 字节的顺序遍历 25 字节 body，并构造 25 个 `uint16_t` 状态；
5. 除位掩码 `0x210042` 标出的少数索引外，把状态与固定表比较，并额外检查 body 第 10 至 13 字节为 `Real`。

目标表为：

```text
30193, 41450, 41342, 33147, 33704,
16159, 7257, 46213, 64473, 11125,
1271, 59403, 51161, 55937, 31380,
32400, 32471, 26976, 36296, 38967,
53726, 43978, 11812, 21068, 13914
```

每一步将当前字符 $x$ 加入 16 位状态：

```c
next = (
    ((state >> 13) ^ 2 | (state << 3) ^ 0x75a8)
    + x
) & 0xffff;
```

遍历顺序和目标索引由反编译中的 `+5` 指针步长与 `+0x0d mod 25` 索引更新共同决定。由于当前 `state` 和目标 `next` 已知，未知字符可以直接用 16 位减法回代；先固定 `Real`，其余位置按执行顺序逐个恢复。最后再把 body 前 10 个字节与各自下标异或，撤销输入前的预处理。

这些约束都是确定性的逐字节关系，不需要爆破。也可以用 Z3 将每个字符限制在可打印 ASCII 范围内，并精确模拟 `uint16_t` 溢出。

恢复结果为：

```text
NepCTF{G0tTheTru3RealCu7eNeuro!^}
```

将该字符串交给原程序验证，可通过所有检查。

## 方法总结

本题的核心是识别“UPX → FlipJump → RISC-V → 字符约束”的分层结构。分析这类多层虚拟化样本时，应尽早区分外层装载器、虚拟机解释器和真正业务逻辑，避免在 FlipJump 位级指令上逐条手工追踪。只要恢复内层段布局，后续就回到了常规反汇编与约束求解问题。
