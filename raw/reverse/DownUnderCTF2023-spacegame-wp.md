# DownUnderCTF 2023 SPACEGAME Writeup

## 题目简述

附件是一个使用 LÖVE 2D 打包的游戏。可执行包本质上包含一组 Lua 资源，脚本经过混淆；正常游玩时玩家很容易死亡，而击败拥有 250 点生命值的 Boss 后才会显示 flag。

预期解法是提取 Lua 脚本、恢复全局对象结构，并覆盖玩家死亡函数，使角色保持无敌直到 Boss 被自动射击击败。

## 解题过程

LÖVE 游戏包可以按 ZIP 结构打开。先解出资源，再重点分析 `Player.lua`。混淆包装会隐藏模块返回值，因此官方解法暂时移除相关 `return`，并递归打印 `_G` 全局表，从而发现全局 `Player` 对象及其 `kill` 方法。

无需理解整个玩家状态机，只要在脚本加载后覆盖该方法：

```lua
function Player:kill()
end
```

重新打包游戏后，碰撞或受到攻击仍会调用 `Player:kill()`，但函数不再改变玩家状态。源码还表明：

- 玩家每 0.25 秒自动发射一枚子弹；
- Boss 初始生命值为 250；
- 子弹命中会持续扣除 Boss 生命；
- Boss 生命归零后，`Boss:draw()` 进入胜利分支并显示 flag。

因此补丁生效后，只需保持游戏运行并躲到能持续命中的位置，最终可看到：

```text
DUCTF{your_journey_is_over_a1eb723d}
```

当前公开题目源码仓库中的 `Boss.lua` 已直接保留这段字符串，所以在赛后仓库环境中静态阅读该文件也能验证结果；这不等于比赛时拿到的混淆附件无需逆向。原始预期路径仍是从打包文件恢复脚本结构、覆盖 `Player:kill()` 并触发胜利逻辑。

题目附带的玩家、Boss 和子弹贴图只用于游戏显示，不承载解题证据，因此没有把这些装饰图片复制进 WP 资源目录。

## 方法总结

面对脚本游戏题，先识别打包格式，再围绕胜负状态做程序切片，通常比完整去混淆更有效。本题只需确认“死亡入口”和“胜利输出”两条链：将 `Player:kill()` 替换为空操作即可切断失败路径，而自动射击会自然推动 Boss 进入输出 flag 的状态。
