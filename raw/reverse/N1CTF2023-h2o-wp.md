# N1CTF 2023 h2o

## 题目简述

题目给出一份体积约 1.6 MiB 的 `h2o.binary`。它并不是常见架构的机器码，而是 H2OC 编译器依次经过 H2OASM 和 Subleq 后生成的整数序列。运行时输入最多 32 个字符，程序将其按小端序每 4 字节打包为一个 32 位整数，再与内置目标值比较。

附件同时保留了 `h2o.asm`、`h2o.sym` 和编译前的 `h2o.h2oc`。因此解题重点有两层：先理解 H2OASM 如何降低为 Subleq，再从上层逻辑中还原自定义 XTEA 的逆运算。

## 解题过程

### 从 Subleq 恢复上层指令

Subleq 只有一种指令：

```text
subleq a, b, c
mem[b] = mem[b] - mem[a]
if mem[b] <= 0: ip = c
else:           ip = next
```

`h2o.sym` 中的 `insns` 与 `ips` 给出了 H2OASM 指令序号到 Subleq 地址的对应关系。结合 `h2o.asm` 可以看出，编译器用固定的 Subleq 片段实现上层操作。例如，上层的 `sub r0, r1` 只需一次减法，而 `add r0, r1` 会借助临时单元取负后再相减：

```text
subleq TMP, TMP, next
subleq r1,  TMP, next
subleq TMP, r0,  next
```

因此不必逐条阅读近两百万字节的原始整数。以符号表切分指令流、匹配这些固定模板，就能回到更易读的 H2OASM；附件中的 `h2o.h2oc` 则进一步确认了恢复结果。

### 定位校验算法

程序把 32 字节输入打包为 8 个 `uint32_t`，每两个整数组成一组 64 位分组。密钥的四个字均为 `0x636f3268`，同时它也是轮常量 `delta`。每个分组执行 8 轮如下变换，所有运算均截断到 32 位：

```c
v0 += (((v1 << 9) ^ (v1 >> 6)) + v1)
      ^ (sum + key[sum & 3]);
sum += delta;
v1 += (((v0 << 2) ^ (v0 >> 10)) + v0)
      ^ (sum + key[(sum >> 11) & 3]);
```

加密结果依次与下列 8 个整数比较：

```text
1979671746, 897489479, 1099794343, 1301154413,
1769714755, 960071495, 1038852409, 3276753339
```

### 逆向 8 轮变换

这是一个改动了移位参数和轮常量的 XTEA。逆运算必须严格倒序：令初始 `sum = delta * 8`，先撤销本轮对 `v1` 的加法，再令 `sum -= delta`，最后撤销对 `v0` 的加法。

```c
for (int i = 0; i < 8; i++) {
    v1 -= (((v0 << 2) ^ (v0 >> 10)) + v0)
          ^ (sum + key[(sum >> 11) & 3]);
    sum -= delta;
    v0 -= (((v1 << 9) ^ (v1 >> 6)) + v1)
          ^ (sum + key[sum & 3]);
}
```

对四个分组分别解密，再按小端序还原字节。实际编译并运行附件中的 `sol.c`，得到：

```text
n1ctf{a_n1ce_h2occ_powered_xtea}
```

## 方法总结

这道题的难点不是暴力处理庞大的 Subleq 程序，而是利用编译器生成代码的规律提升抽象层级。符号表负责划分指令边界，固定模板负责把 Subleq 还原为 H2OASM，最终只需逆向一个结构清晰的 8 轮分组密码。面对自定义虚拟机或单指令计算机时，优先寻找符号信息、编译器模板和重复片段，通常比从最底层逐指令跟踪更可靠。
