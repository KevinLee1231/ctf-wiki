# NepCTF2026 谁引闪了我的灯 Writeup

## 题目简述

题目用固件与照片模拟无线闪光灯发射端、接收端的通信。目标是从 JPEG 元数据取得频道和设备 ID，再逆向固件中的 16 字节报文格式，构造一次合法的引闪命令并计算 flag。

虽然题材涉及无线设备，但附件没有真实射频采样或物理总线交互；决定性工作是固件协议还原，因此归入 Reverse。

## 解题过程

先检查照片元数据：

```bash
exiftool "🐮.jpg"
```

其中隐藏了：

```text
ch18 id19
```

`id19` 表示十进制设备号 19，写入单字节字段时为 `0x13`。再对固件执行 `strings`，能找到一条示例原始报文：

```text
raw 55 01 01 01 00 00 00 00 00 00 00 00 00 00 00 70
```

沿字符串交叉引用分析收发函数，可恢复字段布局：

| 字段 | 字节位置 |
| --- | --- |
| Header | `buf[0]` |
| Group | `buf[1]` |
| ID | `buf[2]` |
| Command | `buf[3]` |
| Data | `buf[4]..buf[13]` |
| 保留 | `buf[14]` |
| Checksum | `buf[15]` |

固定头为 `0x55`，默认组为 `0x01`；引闪命令为 `0x01`，触发第一组时 `Data[0] = 0x01`。校验是前 15 字节的 8 位累加和：

```c
uint8_t check_sum(const uint8_t *buf) {
    uint8_t sum = 0;
    for (int i = 0; i < 15; i++) {
        sum += buf[i];
    }
    return sum;
}
```

因此：

```text
0x55 + 0x01 + 0x13 + 0x01 + 0x01 = 0x6B
```

最终报文为：

```text
55 01 13 01 01 00 00 00 00 00 00 00 00 00 00 6B
```

flag 使用无空格、保留大写十六进制字符的报文文本计算 MD5：

```python
from hashlib import md5

packet_hex = "5501130101000000000000000000006B"
digest = md5(packet_hex.encode()).hexdigest()
print(f"NepCTF{{{digest}}}")
```

得到：

```text
NepCTF{5bf7d6ca3d718c33301a52e5f45909b8}
```

## 方法总结

照片中的 EXIF 只提供设备参数，真正的校验和字段位置必须由固件确认。最后的 MD5 对输入表示形式敏感：它哈希的是无空格且末字节写作大写 `6B` 的 ASCII 文本，不是 16 个原始字节，也不是全小写十六进制串。把“协议字节”和“用于派生 flag 的字符串”分开记录，可以避免得到完全不同的摘要。
