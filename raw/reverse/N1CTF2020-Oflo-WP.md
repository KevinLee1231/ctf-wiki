# N1CTF 2020 Oflo Writeup

## 题目简述

Oflo 是一题带花指令和运行时环境依赖的 Linux 逆向。程序先用三类控制流花指令干扰反汇编，再由子进程执行 `/bin/cat /proc/version`，父进程通过 `ptrace` 取得输出。输入前 5 字节用于异或解密真正的校验函数，后 14 字节则与 Linux 版本字符串参与校验。

## 解题过程

### 修复花指令

IDA 初始无法稳定反编译 `main`。在错误控制流处可见原地跳转、永真/永假条件跳转和把数据夹在跳转间的典型花指令。逐处确认运行时不会执行的字节后，用 NOP 覆盖，并重新定义函数边界和基本块。

不能只看“反编译成功”就认为修复正确；应在调试器中单步经过每个补丁点，确认寄存器和栈行为与补丁前真实路径一致。

### 恢复自解密校验函数

程序把输入前 5 字节与一段函数开头异或。flag 固定前缀为 `n1ctf`，因此这 5 字节已知，可以恢复函数序言并继续反编译。校验逻辑随后 fork：子进程执行：

```bash
/bin/cat /proc/version
```

父进程用 `ptrace` 捕获输出，把版本字符串的前 14 字节加 2，再与常量数组和输入异或比较。

### 解出后 14 字节

官方环境版本串以：

```text
Linux version 4.19.104-microsoft-standard (
```

开头，校验常量为：

```python
check = [53, 45, 17, 26, 73, 125, 17, 20, 43, 59, 62, 61, 60, 95]
```

逆运算为：

```python
version = b'Linux version 4.19.104-microsoft-standard ('
body = bytes(check[i] ^ (version[i] + 2) for i in range(14))
print(b'n1ctf' + body)
```

得到：

```text
n1ctf{Fam3_is_NULL}
```

如果在不同内核上直接运行，`/proc/version` 内容会变化并导致合法输入不同；复现应使用附件预期的版本前缀或在调试时记录程序实际读到的字节。

## 方法总结

花指令只是分析入口，真正的校验还依赖运行时生成的数据。处理自修改或自解密代码时，应优先利用 flag 格式等已知明文恢复可执行区域，再沿数据流找外部环境输入。把 `/proc/version` 这样的环境依赖写进 WP，可以解释为何同一二进制在不同机器上给出不同结果。
