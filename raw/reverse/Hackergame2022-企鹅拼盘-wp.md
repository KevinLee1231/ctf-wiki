# 企鹅拼盘

## 题目简述

题目给出若干个 JSON 格式的“分支程序”。每条指令形如：

```text
[bit_index, move_if_one, move_if_zero]
```

程序读取输入串的某一位，并在两段滑块移动序列中选择一段执行。所有指令执行完后，只要棋盘没有回到初始排列，服务器就判定输入正确。三关分别使用 4、16 和 64 位输入；后两关还对分支程序做了混淆。

表面上这是滑块游戏，决定性障碍却是恢复分支程序的语义和隐藏输入，因此归入逆向，而不是把棋盘移动当作普通搜索题。

## 解题过程

### 把棋盘操作还原成置换乘法

`BP.py` 中每个移动串都会对棋盘位置施加一个置换。固定空格最终回到右下角后，这些置换落在十五个非空方块的交错群 $A_{15}$ 中。对输入向量 $x$，第 $i$ 条指令选择的置换为

$$
p_i(x)=
\begin{cases}
p_i^{(1)}, & x_{b_i}=1,\\
p_i^{(0)}, & x_{b_i}=0.
\end{cases}
$$

整个分支程序的输出就是按顺序相乘：

$$
P(x)=p_0(x)p_1(x)\cdots p_{n-1}(x).
$$

因此不需要操作题目的终端界面。直接复刻 `Board` 的移动规则，或把每段移动预先转换成置换，即可在本地判断某个输入是否让最终棋盘发生变化。一个最小求值器的结构如下：

```python
def evaluate(program, bits):
    board = Board()
    for bit_index, move_if_one, move_if_zero in program:
        moves = move_if_one if bits[bit_index] else move_if_zero
        board.move(moves)
    return board.state
```

### 前两关直接枚举

4 位和 16 位输入空间分别只有 $2^4$ 和 $2^{16}$。枚举所有输入，在本地执行分支程序并检查最终棋盘即可。得到：

```text
b4.json       -> 1000
b16_obf.json  -> 0010111110000110
```

16 位关卡虽然经过了 Kilian 风格的随机化，但随机化只是在相邻指令之间插入相互抵消的共轭因子。例如在相邻乘积中插入 $vv^{-1}$，会把局部指令改写为等价形式，却不改变程序的整体乘积。所以枚举求值仍然有效。

### 从 64 位程序中逐对恢复输入

64 位关卡不能再做完整枚举。观察生成代码可知，最前面一层把两个可能取反的输入文字用交换子组合，形成一个 AND 门。每四条连续指令恰好对应两个输入位。

对这一小段只需要测试四种赋值：

```python
candidates = {}
for x in (0, 1):
    for y in (0, 1):
        value = evaluate_segment(segment, {bit_a: x, bit_b: y})
        candidates.setdefault(value, []).append((x, y))
```

四个结果会按 $3:1$ 分成两组：三种赋值使 AND 为假，只有一种赋值使 AND 为真。那个只出现一次的乘积对应生成器选中的目标位对。依次扫描每四条指令，便能一次恢复两位，而不必理解后续把各个门组合起来的完整布尔电路。

需要注意，程序里记录的两个下标未必按大小排列；先排序并把恢复值写回相应位置，避免交换位序。对全部分组重复后得到：

```text
b64_obf.json -> 1100111101111000111001000001111000011010100110101000011010011011
```

把三段输入依次交给服务即可通过全部关卡。

## 方法总结

本题的关键不是求解十五数码，而是把移动序列抽象为置换，并认出 JSON 实际描述了一个群上的分支程序。短输入可直接复刻解释器后枚举；64 位输入则要回到生成逻辑，利用第一层 AND 门在四种赋值下呈现的 $3:1$ 输出分布，逐对恢复秘密位。面对经过等价变换混淆的程序，先寻找保持不变的整体语义和可独立分析的局部结构，通常比试图撤销全部混淆更有效。
