# HeiLang

## 题目简述

题目给出扩展名为 `.hei.py` 的“新语言”源码。它声称语句 `a[x | y | z] = t` 表示连续执行 `a[x] = t`、`a[y] = t`、`a[z] = t`。附件其余部分仍是普通 Python，因此决定性步骤是恢复这一个自定义语法的语义，再运行还原后的程序取得 flag。

## 解题过程

直接把源码交给 Python 时，`|` 会被解释成按位或，整个下标只会得到一个整数，这与题目定义的多位置赋值不同。观察附件可知相关语句统一写成：

```python
a[1 | 2 | 3] = 4
```

Python 原生支持链式赋值，所以目标语义可以写成：

```python
a[1] = a[2] = a[3] = 4
```

在该附件的固定格式下，只需把每个分隔符 ` | ` 替换为 `] = a[`。下面的转换脚本会保留原文件，并生成可执行的标准 Python：

```python
from pathlib import Path

source = Path("getflag.hei.py").read_text(encoding="utf-8")
translated = source.replace(" | ", "] = a[")
Path("getflag.py").write_text(translated, encoding="utf-8")
```

随后执行：

```bash
python getflag.py
```

程序会按题目定义给数组多个位置赋值，最后输出 flag。这里不需要实现完整词法分析器，因为附件只扩展了一个格式固定、不会出现在字符串或注释中的语法点；若输入不再满足这些约束，才应改用 AST、词法器或专门解释器。

## 方法总结

- 核心技巧：从题面给出的语言语义出发，把自定义多下标赋值恢复成 Python 链式赋值。
- 识别信号：附件看似是熟悉语言，却在某个运算符上定义了与宿主语言不同的行为时，应先确认语法层含义，而不是直接运行。
- 复用要点：文本替换只在格式和上下文严格受控时可靠；更一般的自定义语言应使用词法或语法解析，避免误改字符串、注释和真正的按位或表达式。
