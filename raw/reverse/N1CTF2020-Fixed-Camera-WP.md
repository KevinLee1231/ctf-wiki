# N1CTF 2020 Fixed Camera Writeup

## 题目简述

题目是 Unity IL2CPP 游戏。摄像机俯仰角被限制在约 $[-9^\circ,9^\circ]$，flag 物体位于正常视角之外；相关字段还通过随时间变化的简单“加密值”包装，直接在内存编辑器里搜索角度会失败。解法是恢复 IL2CPP 元数据，定位摄像机类和 `EncryptValue`，再固定随机种子或直接修改真实 `angleY`。

## 解题过程

### 恢复 IL2CPP 类型信息

从游戏目录取得 `GameAssembly.dll` 与 `global-metadata.dat`，使用 IL2CppDumper 生成类、字段和方法映射。重点搜索摄像机更新函数、角度上下限、随机种子初始化和 `EncryptValue` 的 getter/setter。

摄像机构造时会按固定顺序写入一组浮点常量：

```text
20.0, 1.0, 1.0, 80.0, -60.0, -30.0, 30.0
```

这组相邻值可作为 Cheat Engine 的结构特征，定位摄像机对象，即使角度本身被包装也能找到对应字段。

### 绕过加密值和角度限制

`EncryptValue` 使用 Unity 时间/随机数生成掩码。两种可靠方法是：

1. 补丁 `set_seed` 或随机函数，使其固定返回 0，再按 getter 逆出实际角度；
2. 直接补丁摄像机更新函数中的上下界判断，让超范围 `angleY` 不再被重置。

定位到字段后，把 `angleY` 改为约 `-120` 并移动视角；在场景中继续调整到约 `-60` 时，隐藏文字进入视野。公开复现得到：

```text
n1ctf{encrypt_value}
```

修改后应观察游戏下一帧是否把数值恢复。如果立即回弹，说明改的是缓存/显示值而非真实字段，或者仍有 setter 在重新加密。

### 图片取舍

官方 PDF 中的游戏和反编译截图只用于展示字段位置，所有决定性信息都能由上述常量序列、方法名和角度值准确表达，因此归档 WP 不保留截图。隐藏 flag 的空间位置由文字说明即可复现。

## 方法总结

Unity IL2CPP 逆向应把元数据恢复与运行时对象定位结合起来。字段被轻量加密时，不必先彻底逆完算法：构造函数中的邻近常量、对象布局和更新函数写访问同样可以定位目标。修改角度后还要追踪每帧写回，才能区分真实状态与瞬时缓存。
