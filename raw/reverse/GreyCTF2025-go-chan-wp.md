# GreyCTF 2025 go-chan Writeup

## 题目简述

程序用 Go 的无缓冲 channel 搭出一个 $4\times4\times4$ 管道立方体。每个方块有 Front、Right、Back、Left、Top、Bottom 六个面，但内部只把其中两个面连接为一段管道；玩家可以旋转除起点外的方块。程序完成所有旋转后再连接相邻方块，从 `(0, 0, 0)` 的 Top 面发送 flag，并在 `(3, 3, 3)` 的 Bottom 面等待接收。

真正的逆向目标不是逐个猜旋转，而是从 Go 二进制的 channel 操作中恢复 64 个方块各自的内部面连接，再求一条贯穿立方体的可旋转管道路径。

## 解题过程

源码中的 `Block` 用两个 channel 队列保存六个面的通道对象。`LeftRotate` 循环横向四个面，`UpRotate` 则在横向面与 Top、Bottom 之间交换通道。`LinkChannels(c1, c2)` 会启动 goroutine，在两个通道之间双向转发一次字符串。因此，每个初始化语句

```go
LinkChannels(blocks[d][r][c].Face1(), blocks[d][r][c].Face2())
```

都直接描述了该方块内部管道连接的两个面。

官方解法从 Ghidra 反编译结果 `decomp.c` 中定位 `runtime_chanrecv1` 与 `main_LinkChannels`。一个面的访问函数会以固定次序从保存横向面或上下表面的 channel 队列取值；据此把反编译变量映射回六个面，并按初始化顺序填入三维数组：

```python
grid[idx // 16][(idx % 16) // 4][idx % 4] = (face1, face2)
```

接着把搜索状态定义为 `(方块坐标, 进入面)`。对于当前方块，枚举使用 U、L 两种基本旋转可达的所有朝向；若进入面属于当前管道，就从另一个面离开，并移动到相邻方块的相反面。用优先队列搜索时，未旋转的朝向代价为 0，改变朝向代价为 1，便可得到一条旋转数较少的连通路径。起点保持为 `((0, 0, 0), Top)`，终点则根据最后一个方块的固定内部管道，计算能从 Bottom 导出的目标进入面。

官方 solver 找到的方块路径为：

```text
(0,0,0) -> (1,0,0) -> (1,0,1) -> (2,0,1) -> (3,0,1)
-> (3,1,1) -> (2,1,1) -> (2,1,0) -> (2,0,0) -> (3,0,0)
-> (3,1,0) -> (3,2,0) -> (3,2,1) -> (2,2,1) -> (2,3,1)
-> (2,3,0) -> (3,3,0) -> (3,3,1) -> (3,3,2) -> (2,3,2)
-> (2,3,3) -> (3,3,3)
```

最后把每次旋转编码为四个整数 `x, y, z, m`。程序规定 `m=0` 为 Up、`m=2` 为 Left；先发送旋转次数，再依次发送这些四元组。连接建立后，flag 会沿求得的管道传播到终点并被打印：

```text
grey{https://x.com/etum_dev/status/1469721147088547841_d6e8d8cef2cdc80df3ae8c89c5225f6e}
```

其中 URL 是 flag 字符串本身的一部分，不是完成解题所依赖的外部资料。

## 方法总结

本题的关键是把 Go channel 的运行时操作重新解释为“面”和“管道”，再把逆向结果转化为图搜索问题。恢复每个方块的两端后，状态中必须同时保留坐标与进入面，因为同一坐标从不同面进入会产生不同的后继。旋转群只需由 U、L 两个生成元做闭包枚举，最终再把搜索路径反向编码成程序接受的操作序列即可。
