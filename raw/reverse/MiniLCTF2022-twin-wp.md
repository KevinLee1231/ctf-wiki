# MiniLCTF2022 twin Writeup

## 题目简述

附件是 32 位 Windows PE。`main` 中的数组异或会生成 `You_are_too_young_this_is_a_fake_flag!!!`，但该字符串明确是假 flag。真实校验被拆到进程附加与分离阶段的 TLS 回调、资源中的子进程、`WriteFile` 导入钩子和调试事件处理器中；父子进程分别校验 flag 的两半。

## 解题过程

先修正干扰反编译的 `call/ret` 花指令，并查看 PE TLS Directory，而不是继续追 `main`。进程附加回调创建文件映射，将其作为输入共享区，同时注册后续回调。进程分离阶段从资源中释放另一个 EXE 到临时文件并启动它。

释放前，父进程遍历导入表，将 `WriteFile` 的 IAT 项替换为自定义函数。这个钩子在写出子程序时修改其 `.text`：子程序内 XXTEA 的一处右移量从 5 改为 6。因此直接从未修改的资源运行解密脚本，会得到错误的前半段。

子进程还会主动触发异常并检查调试器；父进程以调试方式创建它，在调试事件中修正寄存器后继续执行。子程序用修改后的 XXTEA 校验前半段，恢复为：

```text
miniLctf{cbda59ff59e
```

父进程等待子进程返回成功后，再用标准 XXTEA 校验后 20 字节，恢复为：

```text
3e90c91c02e9b40b78b}
```

两部分拼接得到：

```text
miniLctf{cbda59ff59e3e90c91c02e9b40b78b}
```

当前官方源目录未保留该 PE，以上控制流由多份参赛者分析相互校验；没有虚构缺失附件中的地址、密钥或密文常量。

## 方法总结

Windows 程序的入口逻辑不一定在 `main`。TLS 回调可在进程/线程生命周期事件发生时执行，资源子程序也可能在落盘前被 IAT Hook 动态修改。本题应把“磁盘中的子程序”和“真正执行的子程序”区分开，再分别分析父子校验。调试时可在 `WriteFile` 钩子返回后直接保存缓冲区，从而得到已经修补、最接近真实执行状态的样本。
