# Cake Puzzle

## 题目简述

这题的核心是一个 4x4 滑块交互程序。`chal` 每次读入一段输入（`char`），尝试执行 `U/D/L/R` 操作交换零格与邻格，主循环会不断调用 `q()` 做通关检查。

`q()` 只遍历左上角的 $3\times3$ 区域，并要求其中每个格子都小于其右邻和下邻：

```c
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (M[i][j] >= M[i][j+1]) return 1;
        if (M[i][j] >= M[i+1][j]) return 1;
    }
}
```

因此它检查的是 18 条局部有序约束，而不是传统十五数码“空格位于固定位置”的判定。最后一行的横向关系和最后一列的纵向关系没有直接检查，不能把它表述成对整个矩阵做完整的行优先排序检查；不过生成器所对应的复原态确实满足这些约束。

源码里 `main.c` 的矩阵 `M` 并非直接是 `0..15`，而是通过 `gen.py` 用一组随机映射值替换后的版本：

```c
int M[4][4] = {
    {1146640091,1277362948,2245791,1729795767},
    {1817593079,2146722439,1860814889,1557802610},
    {0,1770948809,870734415,1355570260},
    {323584794,1405652852,629508793,1928951512},
};
```

因此只要保持映射后的顺序关系一致，等价于把拼图恢复到由 `gen.py` 对 `0..15` 派生出的初态排序态。

源码证据还给出 `gen.py` 的关键链路：先在 16 数码上执行 100000 次随机合法移动生成 query，再把这些移动按逆序转存到 `ans.txt`。这意味着解题主链其实是直接复用官方预生成答案。

## 解题过程

### 关键观察

1. 题目没有额外加密层，最终通关只靠 `q()` 的顺序判定。
2. `gen.py` 已明确给出逆序操作序列 `ans.txt`，这是最强可复用证据。
3. `main.c` 每轮调用 `scanf("%s", buf)`，但实际只把 `buf[0]` 交给移动函数。这里的 `%s` 没有宽度限制，`buf[100]` 并不会自动阻止溢出；正常解法应每次发送一个移动字符，而不是把 100000 个字符拼成一个 token。

### 求解步骤

1. 读取仓库内 `challenge/main.c` 与 `challenge/ans.txt`。
2. 用 `ans.txt` 里的字符序列按顺序作为交互输入（或逐字符发送）。
3. 每次向服务发送一个字符即可触发一次移动；执行完全部 100000 步后 `q()` 会在某次循环命中 `0` 并读取 `/flag.txt`。

### 本地验证

为了不依赖远端，我用 `main.c` 的交换逻辑对 `ans.txt` 做重放验证：

```python
from pathlib import Path

board = [
    [1146640091, 1277362948, 2245791, 1729795767],
    [1817593079, 2146722439, 1860814889, 1557802610],
    [0, 1770948809, 870734415, 1355570260],
    [323584794, 1405652852, 629508793, 1928951512],
]

ans = Path("challenge/ans.txt").read_text().split()

for i in range(4):
    for j in range(4):
        if board[i][j] == 0:
            y, x = i, j

def do(op):
    global y, x
    if op == "U" and y > 0:
        board[y][x], board[y - 1][x] = board[y - 1][x], board[y][x]
        y -= 1
    elif op == "D" and y < 3:
        board[y][x], board[y + 1][x] = board[y + 1][x], board[y][x]
        y += 1
    elif op == "L" and x > 0:
        board[y][x], board[y][x - 1] = board[y][x - 1], board[y][x]
        x -= 1
    elif op == "R" and x < 3:
        board[y][x], board[y][x + 1] = board[y][x + 1], board[y][x]
        x += 1

for c in ans:
    do(c)

ok = True
for i in range(3):
    for j in range(3):
        ok &= board[i][j] < board[i][j + 1]
        ok &= board[i][j] < board[i + 1][j]
print("solved", ok)
```

输出为 `solved True`，与服务端判定一致。

服务返回的 flag 为：

```text
CakeCTF{wh0_at3_a_missing_pi3c3_0f_a_cak3}
```

## 方法总结

- 核心技巧：精确还原 `q()` 的局部有序约束，并把生成器的随机移动轨迹反向重放。
- 识别信号：出现 `q`/`check` 检查严格大小关系，且题目有 `solution`/`generator` 已给逆变换时，应优先走“生成链路还原”而非盲猜搜索。
- 复用要点：对于题目源码提供了完整答案轨迹的 reverse/replay 题，最安全是直接重放并加本地可复现实验，避免手工路径推导。
