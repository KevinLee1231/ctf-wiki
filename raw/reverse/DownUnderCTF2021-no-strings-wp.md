# DownUnderCTF 2021 - No Strings

## 题目简述

程序要求输入 flag，却无法直接用常规 `strings` 搜到完整明文。原因并不是复杂加密，而是程序把每个有效字符后都插入一个空字节，再逐隔一个字节进行比较。普通字符串扫描器会把这些空字节视作字符串结束符，因此只能看到零散字符。

## 解题过程

反编译 `main` 后可以看到，程序逐字节读取输入，但比较目标使用的是 `flag[2 * i]`：

```c
for (int i = 0; i < strlen(input); i++) {
    if (input[i] != flag[2 * i]) {
        puts("Incorrect!");
        return 1;
    }
}
```

目标数组在源码中的实际布局如下：

```c
char *flag =
    "D\0U\0C\0T\0F\0{\0s\0t\0r\0i\0n\0g\0e\0n\0t\0_\0"
    "s\0t\0r\0i\0n\0g\0s\0_\0s\0t\0r\0i\0n\0g\0}";
```

因此可以直接查看 `.rodata` 的十六进制内容，再取偶数位置字节。也可以用一个很短的脚本完成恢复：

```python
data = bytes.fromhex(
    "44 00 55 00 43 00 54 00 46 00 7b 00 73 00 74 00 "
    "72 00 69 00 6e 00 67 00 65 00 6e 00 74 00 5f 00 "
    "73 00 74 00 72 00 69 00 6e 00 67 00 73 00 5f 00 "
    "73 00 74 00 72 00 69 00 6e 00 67 00 7d"
)
print(data[::2].decode())
```

输出为：

```text
DUCTF{stringent_strings_string}
```

## 方法总结

本题利用空字节干扰基于 C 字符串规则的静态扫描，但有效数据仍以固定步长明文保存在二进制中。遇到 `strings` 没有结果时，应继续检查原始字节、交叉引用和比较循环；本题只需识别 `flag[2 * i]` 的步长关系，不能把它误判为宽字符编码或密码算法。
