# bbbbbb

## 题目简述

Windows 程序会计算代码页以及调试寄存器 `dr0` 至 `dr3` 的 SHA-256，从而同时检测软件断点和硬件断点。官方 PDF 只列出内存转储、API hook、内存断点和虚拟机断点等思路，没有给出完整恢复过程。可行方案是在校验代码区之外拦住退出流程，再从内存中定位输入数组旁的目标值。

## 解题过程

反编译可见程序调用 `K32GetModuleInformation` 获取主模块范围，并分块哈希约 `0x7ff6a2971000` 至 `0x7ff6a2975000` 的代码页。普通 `int3` 会把代码字节改为 `0xcc`，因此摘要变化；`GetThreadContext` 又读取调试寄存器，使硬件执行断点也会进入摘要。

不在被哈希的模块代码里下断点，而是在系统库的 `exit` 入口暂停。先用一个易识别输入，例如：

```text
123_456_789_111
```

程序把它解析为 4 个 32 位整数。使用内存搜索定位这四个连续 DWORD，再观察相邻内存即可找到程序用于最终比较的四个目标字。按校验逻辑调整顺序后，需要提交的无符号值为：

```text
1302398954
2468902829
1518694932
3345474667
```

输入函数使用 `atoi`，其中两个值大于 `INT_MAX`，交互时应写成对应的 32 位有符号十进制：

```text
1302398954_-1826064467_1518694932_-949492629
```

换算关系为：

```python
signed_values = [1302398954, -1826064467, 1518694932, -949492629]
unsigned_values = [value & 0xffffffff for value in signed_values]
print(unsigned_values)
```

输出：

```text
[1302398954, 2468902829, 1518694932, 3345474667]
```

程序最终按无符号十进制拼接 flag：

```text
hgame{1302398954_2468902829_1518694932_3345474667}
```

## 方法总结

- 核心技巧：避开自校验代码区，在未被哈希的系统 API 上拦截控制流，再通过已知输入定位内存中的比较目标。
- 识别信号：程序同时读取模块范围和 `CONTEXT` 调试寄存器，通常意味着软件断点与硬件断点都在检测范围内。
- 复用要点：反调试不一定要正面移除；可改用内存搜索、API hook、页副本或校验区外断点。还要区分输入的有符号表示与最终 flag 的无符号表示。
