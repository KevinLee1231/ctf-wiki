# 旧日之痕

## 题目简述

附件给出 256 个去除符号的 SHA3 基准程序。它们都由同一份 LLVM IR 编译而来，只是在编译阶段被一个自定义 LLVM Pass 写入了不同的字符串水印。服务端维护全部合法水印：提交任意一个不同水印可获得第一问 flag，累计提交 100 个不同水印可获得第二问 flag。

水印并不是作为连续字节写入二进制，而是编码成函数内基本块的排列。因此，本题的决定性障碍是恢复编译器 Pass 的编码语义，再从二进制控制流中反推出排列所代表的比特串，归入 reverse。

## 解题过程

### 还原水印的比特编码

生成脚本先由秘密种子和样本编号确定水印，长度在 16 到 31 个字符之间，字符来自一个自定义 Base64 字符表。`constructBW` 的处理过程可概括为：

1. 先组成整数序列 `ubw = [len(watermark)] + [b64idx[c] for c in watermark]`，每个整数均按 6 位展开；
2. 对所有 6 位分组按位异或求校验值 `parity`，再用它覆盖总比特串的第 0 位；
3. 以 `len(watermark) + (parity << 5)` 为种子初始化 C++ `mt19937`；
4. 保留开头 6 位不动，只对余下的水印数据位执行 `std::shuffle`。

因此，最终比特串开头的第 0 位是校验位，第 1 至 5 位是水印长度；实际总长度为

$$
t=6+6\ell,
$$

其中 $\ell$ 是水印字符数。剩余位需要按同一随机数生成器产生的置换逆序还原。

### 理解基本块排列编码

Pass 遍历模块中的普通函数，忽略 `llvm.*` 函数。对每个函数，它只计入指令数大于 1 的非平凡基本块，并把数量上限截到 35。入口块保持在第一个位置，只有其余 $n-1$ 个块参与排列，因此某函数能承载

$$
\left\lfloor\log_2((n-1)!)\right\rfloor
$$

位；源码中的 `cantor_bitlen[n-1]` 正是这一定长容量。编码器从水印比特流中取出这么多位，解释为一个整数，再用逆 Cantor 展开得到其余基本块的排列。随后 Pass 按该排列重排函数中的基本块，并添加 `noinline`、`optnone`，避免后续优化抹掉顺序。

解码时要准备由同一份 `main.ll` 编译出的未加水印基准程序，将目标程序每个函数的基本块一一对应回基准程序，然后把目标中的顺序写成“基准基本块编号”的排列。其 Cantor 排名就是该函数承载的整数：

```python
def cantor(order):
    result = 0
    for i in range(1, len(order) - 1):
        count = sum(order[j] < order[i] for j in range(i, len(order)))
        result += count
        result *= len(order) - i - 1
    return result
```

排名要补零到该函数的固定容量；最后一个函数只取拼出完整水印所需的低位。第一段数据一旦恢复出头 6 位，就能从第 1 至 5 位读出 $\ell$，从而知道何时停止继续取块。

### 匹配基本块并还原字符串

去符号二进制不能依赖块地址直接匹配。官方解法为每个基本块构造两类与排列无关的特征：

- 汇编指令操作码的多重集合，用不同小质数的乘积表示；
- 从该块出发遍历控制流图得到的深度序列，同样映射成质数特征。

据此建立基准块与目标块的距离矩阵，再做一对一贪心匹配。单看指令多重集合时，重复或近似基本块容易混淆；控制流深度特征提供了必要的结构约束。匹配完成后逐函数计算 Cantor 排名并拼接，即可取得被打乱后的水印比特串。

Python 的 `random.shuffle` 与 C++ 标准库的 `std::shuffle(mt19937)` 不兼容，因此应使用一个很小的 C++ 辅助程序，在相同种子下对索引序列执行同样的洗牌。设它输出洗牌后的索引 `order`，则对数据区使用逆置换：

```python
original = "".join(
    shuffled[6 + order.index(i)]
    for i in range(total_bits - 6)
)
bits = shuffled[:6] + original
```

最后从第 6 位开始每 6 位转成一个整数，再按 `b64idx` 的逆表查回字符。可用两种方式验证恢复结果：

1. 对恢复出的水印重新执行 `constructBW`，应与从基本块排列解出的比特串完全一致；
2. 将水印提交给服务端，服务端应只接受隐藏集合中的值，且第二问必须累计 100 个互不重复的合法水印。

对多个附件重复上述流程，保存去重后的结果并依次提交，即可完成两问。

## 方法总结

本题的核心链路是“水印字符串 $\rightarrow$ 六位分组与校验位 $\rightarrow$ C++ 随机置换 $\rightarrow$ Cantor 排列 $\rightarrow$ LLVM 基本块顺序”。逆向时必须沿这条链路逐层求逆：用同源基准程序匹配基本块，以 Cantor 排名恢复分段比特，按 `std::shuffle` 的真实实现逆置换，再用自定义 Base64 表还原字符串。

容易踩坑的地方有三处：不能把去符号后的地址当作稳定标识；不能只凭操作码匹配结构相似的基本块；也不能用 Python 随机库模拟 C++ 洗牌。重新正向编码并比对比特串，是比仅凭服务端返回更细粒度的本地验证方法。
