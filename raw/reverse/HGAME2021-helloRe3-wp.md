# helloRe3

## 题目简述

程序用 Dear ImGui 绘制虚拟键盘。每个按键不是直接保存字符，而是带有一个 `order` 编号；玩家点击按键后，程序依次记录这些编号，点击 `check`（`order == 65`）才进入校验。校验函数又用 `call + pop` 制造异常栈分析，导致 IDA 报出 `positive sp value has been found`。需要恢复二维结构体数组、修正反编译干扰，再识别 RC4 并把解出的编号映射回按键字符。

## 解题过程

从调试字符串 `player tapped [%s], order:%d` 追到按键处理逻辑，可以为键盘数组建立如下结构体：

```c
struct Key {
    const char *name;
    unsigned int order;
    unsigned int reserved1;
    unsigned int reserved2;
    float offset;
    float width;
};
```

给数组套用该类型后，可以直接看到每个显示字符与 `order` 的对应关系。点击普通按键时，程序把其 `order` 追加到全局数组；点击 `check` 时，`order` 为 65，程序设置另一个全局变量。沿这个变量的交叉引用即可定位真正的校验函数。

IDA 在该函数中断反编译，是因为 `0x1400C8C39` 附近存在下面的取址写法：

```asm
call 0x1400C8C40
; call 压入的返回地址为 0x1400C8C3E
pop  rax
```

`call` 把下一条指令地址压栈，随后的 `pop` 又将其取到 `rax`，这既取得了位置相关地址，也破坏了反编译器推导出的栈平衡。可以临时把 `call + pop` NOP 掉以观察主体逻辑，但要记住这会改变后续参数：原程序传给加密函数的第一个参数实际是 `0x1400C8C3E`，分析时必须手工补回。

修正参数后，加密函数表现为标准 RC4：按输入的 `order` 字节序列执行 KSA/PRGA，再与内置结果比较。RC4 加解密是同一运算，对目标密文再次运行即可得到正确的按键编号：

```python
orders = [
    0x3B, 0x3A, 0x36, 0x48, 0x27,
    0x2F, 0x1A, 0x1F, 0x3D, 0x18,
    0x3D, 0x4A, 0x18, 0x28, 0x20,
    0x17, 0x44, 0x18, 0x29, 0x30,
]
```

最后遍历已经恢复类型的 `Key` 数组，以 `order` 查找对应的 `name`，按上述顺序拼接。官方 PDF 到这里为止，没有附出键位表或最终字符串；同期解题人的 [Week3 复盘](https://wr-web.github.io/2021/03/14/HGAME_WEEK3_WP/) 保留了映射后的结果，其代码注释原样写作：

```text
HGAME{6-K4K.4R+3C4T}
```

这里保留来源中的大写前缀，不自行改成赛事中更常见的小写形式。

## 方法总结

本题的三个层次彼此相连：调试字符串用于定位输入处理，二维结构体把字符与编号联系起来，`call + pop` 既阻碍反编译又提供 RC4 所需的真实地址。临时修补反汇编时，不能忘记补回被修补指令产生的数据；解出 `order` 序列后，也必须回到结构体数组做编号到字符的映射。外部复盘只用于补足官方 PDF 缺失的最终映射结果，关键分析过程已经完整保留在正文中。
