# TSGCTF2021 optimized WP

## 题目简述

题目给出一个没有节区表、看似静态链接的 64 位 ELF，要求输入四个无符号整数作为密码。程序先经过修改标识的 UPX 打包，解包后又以编译器优化生成的大量 SIMD 和 128 位乘法实现取模、整除判断，使反编译结果显得非常复杂。

核心并不是逐条模拟 SIMD，而是识别 Daniel Lemire 风格的常数除数快速取模公式。四个输入分别受到两条同余或“整除加同余”约束；求出四个整数后，程序将它们重复拼成 32 字节 ChaCha20 密钥并解密内置密文。

## 解题过程

### 恢复可分析的程序

入口特征表明程序经过 UPX 打包，但三个标准 `UPX!` 标识被替换成了 `tsg_`。将这三处字节恢复为 `UPX!` 后即可正常执行：

```sh
upx -d optimized
```

另一种不修改文件的办法是在调试器中运行到解包后的代码，再用 `gcore` 导出内存镜像。解包后可以看到程序读取四个 `uint32_t`，并调用两类检查函数。

### 化简快速取模

源码中的预计算常数为：

```c
uint64_t computeM_u32(uint32_t d) {
    return UINT64_MAX / d + 1;
}
```

令 $M=\lfloor(2^{64}-1)/d\rfloor+1$。第一类检查：

```c
uint64_t lowbits = M * a;
return ((__uint128_t)lowbits * d) >> 64;
```

等价于计算 $a\bmod d$。第二类表达式 `v * M < M` 在 64 位无符号溢出语义下等价于 $v\bmod d=0$。因此八个看似晦涩的检查可以还原为：

```text
k0 % 176017 == 772928896 % 176017
k0 % 215737 == 772928896 % 215737
k1 % 224057 == 2204180909 % 224057
k1 % 238291 == 2204180909 % 238291
k2 % 3460307 == 0
k2 % 163321 == 4273479145 % 163321
k3 % 8840597 == 0
k3 % 244837 == 1334930147 % 244837
```

每组两条约束可用扩展欧几里得算法和中国剩余定理合并。在 `uint32_t` 范围内得到唯一一组密码：

```text
772928896 2204180909 4273479145 1334930147
```

### 解密内置密文

程序把四个 32 位整数按本机小端字节序存入 `k[0:4]`，再复制到 `k[4:8]`，形成 32 字节密钥。源码把下面字符串的地址传给 OpenSSL 作为 IV：

```text
welcometotsgctfaaa
```

该字面量有 18 字节，而 `EVP_chacha20()` 的 IV 长度为 16 字节，所以实际使用的是前 16 字节 `welcometotsgctfa`。

用 OpenSSL ChaCha20 解密内置的 20 字节密文，或直接把四个整数输入原程序，得到：

```text
TSGCTF{F457_m0dul0!}
```

## 方法总结

本题有两层干扰：修改标识的 UPX 隐藏真实代码，编译器展开的快速除法又隐藏简单的模约束。遇到无节区表且入口形似解包 stub 的 ELF，应先恢复真实程序；面对成片的乘法高位、固定倒数和 SIMD 比较，则应通过少量输入验证其数学语义，而不是照着伪代码硬算。识别出 $a\bmod d$ 和 $d\mid a$ 后，剩余工作只是 CRT 求解以及按程序实际内存布局构造 ChaCha20 密钥。
