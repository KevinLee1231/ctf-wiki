# server

## 题目简述

题目附件是 Go 编写的 HTTP 服务，监听 `9090` 端口并通过查询参数接收候选 flag。验证函数先对 153 位十进制字符串做两轮链式异或，再把所得整数作为 RSA 密文解密。目标是从 Go 二进制中恢复异或数组、RSA 参数和变换顺序，最终还原明文。

## 解题过程

Go 二进制的入口应从 `main.main`（IDA 符号常显示为 `main_main`）开始寻找。较新版本的 IDA 能利用二进制内嵌的 Go 符号表，验证主线位于 `main.encrypt`。若反编译器没有正确识别 `math/big.(*Int).SetString` 的调用约定，可结合汇编手动修正参数类型，再观察其后的两轮异或循环。

两轮链式异或的逆运算都可以从数组末尾向前执行，但首轮需要的末态字节未知。它只有 256 种可能，逐一尝试并要求结果全部为 ASCII 数字即可唯一确定。随后按二进制中的 $p$、$q$ 和 $e$ 做标准 RSA 私钥运算：

```python
from Crypto.Util.number import long_to_bytes

cipher = [
    99, 85, 4, 3, 5, 5, 5, 3, 7, 7, 2, 8, 8, 11, 1, 2, 10, 4, 2, 13,
    8, 9, 12, 9, 4, 13, 8, 0, 14, 0, 15, 13, 14, 10, 2, 2, 1, 7, 3,
    5, 6, 4, 6, 7, 6, 2, 2, 5, 3, 3, 9, 6, 0, 11, 13, 11, 0, 2, 3, 8,
    3, 11, 7, 1, 11, 5, 14, 5, 0, 10, 14, 15, 13, 7, 13, 7, 14, 1, 15,
    1, 11, 5, 6, 2, 12, 6, 10, 4, 1, 7, 4, 2, 6, 3, 6, 12, 5, 12, 3,
    12, 6, 0, 4, 15, 2, 14, 7, 0, 14, 14, 12, 4, 3, 4, 2, 0, 0, 2, 6,
    2, 3, 6, 4, 4, 4, 7, 1, 2, 3, 9, 2, 12, 8, 1, 12, 3, 12, 2, 0, 3,
    14, 3, 14, 12, 9, 1, 7, 15, 5, 7, 2, 2, 4,
]

for seed in range(256):
    digits = cipher.copy()
    carry = seed

    for i in range(len(digits) - 1, -1, -1):
        carry ^= digits[i]
        digits[i] ^= carry

    for i in range(len(digits) - 1, -1, -1):
        carry ^= digits[i]
        digits[i] ^= carry

    try:
        decimal = bytes(digits).decode("ascii")
    except UnicodeDecodeError:
        continue

    if len(decimal) == 153 and decimal.isdigit():
        enc = int(decimal)
        break
else:
    raise RuntimeError("未恢复出十进制 RSA 密文")

p = 92582184765240663364795767694262273105045150785272129481762171937885924776597
q = 107310528658039985708896636559112400334262005367649176746429531274300859498993
e = 950501

phi = (p - 1) * (q - 1)
d = pow(e, -1, phi)
m = pow(enc, d, p * q)
print(long_to_bytes(m))
```

## 方法总结

Go 的运行时符号很多，但应先沿 HTTP 参数处理和比较函数收缩范围，再识别 `math/big` 等高信息量调用。链式异或的未知状态只有一个字节，不必引入复杂求解器；利用“结果必须是 153 位十进制串”的强约束，枚举 256 种末态即可。最后再把恢复出的十进制整数交给标准 RSA 运算，能把自定义混淆与密码学主体清晰分离。
