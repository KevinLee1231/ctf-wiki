# L3akCTF 2024 Hidden Writeup

## 题目简述

程序接收一个命令行参数并调用 `strcmp` 与内部构造的字符串比较。目标字符串没有经过加密，只是被拆成一组字符，通过可变参数函数逐字节追加到堆缓冲区中。

这是一道入门级动态或静态逆向题：定位 `strcmp` 的第二个参数即可得到正确输入。

## 解题过程

主函数的关键逻辑是：

```c
char *str = flag();

if (argv[1] && !strcmp(argv[1], str))
    printf("Correct!\n");
else
    printf("Wrong!\n");
```

有两种直接解法。

第一种是动态跟踪 libc 调用：

```bash
ltrace -s 256 ./hidden test
```

在 `strcmp` 调用处可以看到用户输入与目标字符串：

```text
strcmp("test", "L3AK{b4by_sT3Ps}")
```

第二种是反编译 `flag`。该函数调用自定义可变参数函数 `c`，参数依次为：

```c
c(
    str,
    'L', '3', 'A', 'K', '{',
    'b', '4', 'b', 'y', '_',
    's', 'T', '3', 'P', 's', '}',
    0
);
```

末尾的 0 是可变参数终止标记。按顺序拼接字符即可得到：

```text
L3AK{b4by_sT3Ps}
```

使用该字符串运行程序会进入 `Correct!` 分支。

源码还有一个与解题无关的缺陷：`malloc(512)` 后没有先写入 `str[0] = '\0'`，而 `appendChar` 立即对这块未初始化内存调用 `strlen`。新分配页面常常恰好含零字节，所以样本通常能运行，但从 C 语言语义看并不可靠。它不是获得 flag 所需的漏洞。

## 方法总结

- 对直接调用 `strcmp`、`memcmp` 的 checker，先观察比较函数参数，往往比分析所有字符串构造代码更快。
- 字符被拆成立即数并不等于真正加密；在反编译器中跟入构造函数，按调用顺序恢复即可。
- 动态跟踪得到候选后仍应回到源码或反编译结果确认终止符和完整长度，避免被输出截断。
- 应区分实现中的未初始化内存问题与决定性解题机制；本题归入 Reverse，而不是 Pwn。
