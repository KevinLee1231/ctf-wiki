# GreyCTF2022 - untransparent2

## 题目简述

程序经过 OLLVM 的控制流平坦化、虚假控制流、指令替换和基本块切分。生成源码包含大量由固定随机序列选择的无关分支，只有 `target == 589` 的分支执行真实的逐字符 flag 检查。

## 解题过程

从初始化处可以看到 `srand(3133337)`。同一 libc 实现下，后续 `rand()` 序列可复现；结合源码生成器可确定真实目标编号为 589。与其完整去除所有 OLLVM 混淆，不如围绕这个比较定位对应基本块并追踪成功路径。

```c
if (target == 589) {
    if (flag[idx] == 'g') {
        /* 下一字符检查 */
    }
}
```

在反编译器中把平坦化调度变量重命名，忽略永远不会由固定随机序列选中的块，按 `idx` 顺序记录每个字符常量。仓库的 `sourceGen.py` 与混淆前 `pain.c` 可用于逐项交叉验证，恢复：

```text
grey{y0u_aR3_a_Pr0fe551on4l}
```

## 方法总结

面对控制流混淆，不一定要先做全程序反混淆。若调度值来自固定种子或存在唯一真实分支，可通过动态跟踪、污点分析或生成器源码先锁定决定性路径，再局部恢复字符约束。所有字符应回送混淆后二进制验证。
