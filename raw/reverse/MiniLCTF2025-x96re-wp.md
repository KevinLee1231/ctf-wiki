# x96re

## 题目简述

题目给出一个 32 位原生程序，但真正的校验逻辑并不完全运行在 32 位代码段中。程序将一段机器码映射到固定地址，再通过远返回切换到 64 位代码段执行；隐藏逻辑先对输入做逐字节异或，再进行标准 SM4 加密并比较密文。

决定性障碍是识别跨执行模式的控制流并继续分析映射出来的 64 位代码，因此归类为 Reverse。

## 解题过程

### 跟踪动态映射的代码

程序启动后调用 `mmap`，在 `0x0DEAD000` 一带建立可执行映射，初始化函数随后把一段机器码复制到该区域。若只按 32 位程序的静态函数列表分析，真正的校验代码不会自然出现在正常调用图中，因此需要把复制目标视为新的代码区继续反汇编。

关键函数使用 `retf`，并把代码段选择子设置为 `0x21`。远返回不仅改变指令指针，还会装载新的代码段；这里借此从 32 位兼容代码切换到 64 位代码执行。调试时应在远返回前后分别使用匹配的反汇编位数，否则同一串机器码会被错误解码。

### 还原 64 位校验逻辑

进入映射区的 64 位代码后，数据流可以归纳为两步：

1. 输入除最后两个字节外，逐字节与 `0x4C`（字符 `L`）异或；
2. 对处理后的数据执行标准 SM4 加密，并与程序内置密文比较。

因此，若从程序中提取到 SM4 密钥和目标密文，通用反解顺序应为：

```text
目标密文 --SM4 解密--> 中间明文 --除末两字节外逐字节 XOR 0x4C--> 原输入
```

异或是自身的逆运算，所以不需要另写逆函数；需要特别保留“最后两个字节不参与异或”这一边界条件。

原始题解给出的最终结果是：

```text
miniLCTF{3ac159d665b4ccfb25c0927c1a23edb3}
```

### 证据边界

现存材料只有题解文字以及两张通过站内媒体接口引用、当前源目录中并不存在的截图；题目二进制、SM4 密钥、目标密文和可运行求解脚本均未随仓库保存。因此可以可靠转写模式切换、异或边界、SM4 校验链和题解公布的 flag，但无法仅凭现有文件独立重放 SM4 解密，也不应补猜缺失常量。

## 方法总结

这道题最容易漏掉的是“32 位外壳不代表所有代码都按 32 位执行”。遇到固定地址映射、复制机器码、`retf` 和异常代码段选择子时，应检查是否发生了执行模式切换，并在目标位数下重新反汇编。确认校验链后，按 SM4 解密、异或还原的逆序处理即可；末两字节的例外必须原样保留。

最终 flag 为：

```text
miniLCTF{3ac159d665b4ccfb25c0927c1a23edb3}
```
