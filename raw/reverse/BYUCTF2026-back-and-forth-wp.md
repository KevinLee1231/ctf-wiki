# Back and Forth

## 题目简述

附件是 Android 应用，但校验逻辑并不集中在 Java 层，而是在 SQLite、JNI/C++、Java 随机数逻辑、WASM/Rust 和本地哈希检查之间来回切换。决定性工作是恢复多运行时拼接的输入约束，因此归入 Reverse。

## 解题过程

从应用入口沿每个校验函数分别分析，可以按最终字符串中的位置恢复各段：

1. 应用数据库直接给出一段 `4ndr01d`。
2. JNI 的 `finalize` 对输入字节做累计检查，逆推得到 `thr0ugh`。
3. C++ 层以 MT19937 产生状态，再把结果交给 Java `Random` 和除法条件，恢复 `styl3s`。
4. WASM 模块由 Rust 编译而来。其检查会格式化并转置输入位，按逆变换还原为 `j0mp1n6_`。
5. 本地 `check1` 对偏移 `0x1f` 开始的四字节计算 SHA-256，只比较摘要的隔位字节。枚举四个可打印字符即可得到 `c0d3`。
6. 另一处 `strcmp` 的真假分支写反，导致错误后缀也可能被接受；结合程序内预期常量，设计上的正确后缀是 `28f6}`。

再结合固定前缀和各段之间的下划线，完整输入为：

    byuctf{j0mp1n6_thr0ugh_4ndr01d_c0d3_styl3s_28f6}

将该值输入应用可以走完所有有效校验。通关时不能只依赖写反的 `strcmp` 获得任意接受值，因为那样无法解释题目设计的完整 flag。

## 方法总结

多语言应用应先建立调用边界和字符串偏移表，再逐模块求解。Android 只是承载平台；SQLite、JNI、Java PRNG、WASM 和哈希约束各自都能独立验证。对反编译中异常的条件分支还要区分“程序实际接受什么”与“作者原本想检查什么”。
