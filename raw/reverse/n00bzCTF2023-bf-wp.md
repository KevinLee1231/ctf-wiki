# bf

## 题目简述

附件是 UTF-16LE 编码的 Brainfuck 源码。直接运行会得到误导性输出；真正的 flag 被编码在源码中 59 段重复结构的减号长度里。

## 解题过程

文件以 `FF FE` 开头，每个 Brainfuck 字符后跟一个零字节，因此先按 UTF-16LE 解码。源码中反复出现如下结构：

```text
>>>>>-------------------------------[[-]--+[-<+]-<[-]+>++[-->++]]
```

提取全部 59 段，记每个 `>>>>>` 后连续 `-` 的数量为 $n$。生成逻辑使用了两个区间，逆变换为：

```python
def decode_count(n):
    if n + 79 <= 125:
        return chr(n + 79)
    return chr(n - 15)
```

按源码顺序解码所有长度，得到：

```text
n00bz{Y0u_60D_1t_60d4Mm17_1m_Pr0Ud_0f_y0U_N0W_t4K3_Re57!!!}
```

## 方法总结

Esolang 附件不一定要按正常控制流执行。大量高度重复、只有运行长度不同的片段通常构成第二层编码；本题应保留源码结构，提取 59 个长度并验证结果满足 flag 格式。
