# N1CTF 2020 Oh My Julia Writeup

## 题目简述

附件是由 Julia PackageCompiler 生成的 x64 可执行文件。大量 Julia 运行时和 JIT 代码会淹没真正校验逻辑，静态搜索很难直接定位。正确入口是在输入和输出 API 下断点，跟踪到编译后的用户函数，再把 flag 花括号内按下划线分隔的五段校验分别逆向：直接比较、固定异或、中国剩余定理、位运算约束和快速幂编码。

## 解题过程

### 从 Julia 运行时定位用户代码

在 x64dbg 中对读取输入和打印结果的位置下断点，输入一个长度、分隔符都合理的测试串。沿调用栈返回，直到进入不属于通用 Julia runtime 的代码页。将该区域转储并建立函数边界，可以看到程序先按 `_` 分割字符串，再把五段送往不同校验函数。

这种方法比在整个打包程序中盲搜常量可靠，因为 PackageCompiler 会把运行时、标准库和用户代码一起封装。

### 分别逆向五段

第一段与常量直接比较，得到：

```text
n0w
```

第二段把目标数组 `[0xe8, 0xde, 0xc4]` 与 `0xb1` 异或：

```python
part2 = bytes(x ^ 0xb1 for x in [0xe8, 0xde, 0xc4])  # b'You'
```

第三段把一个 32 位整数分别对三个模数取余。用 CRT 合并并按小端打包：

```python
part3 = crt([
    (0x1337, 0x8ff),
    (0x18d9, 0x105a),
    (0x245f, 0x1595),
]).to_bytes(4, 'little')  # b'kN0w'
```

第四段含 5 个字节的循环移位、异或和移位约束，目标数组为：

```text
59 be 62 fa 04
```

将原始 5 字节建成 8 位 BitVec，逐句翻译运算并交给 Z3，得到 `juL1@`。所有移位都要限制在 8 位；缺少 `& 0xff` 会改变方程语义。

第五段把一个大整数取以 3 为底的对数，转二进制后逆序，并把 0/1 分别映射为 `z`/`Z`，得到 `ZzzZZzzzZZzZZ`。这是普通可逆编码，不需要求离散对数。

### 拼接最终输入

保持原大小写和下划线：

```text
n1ctf{n0w_You_kN0w_juL1@_ZzzZZzzzZZzZZ}
```

把该字符串送回附件，五个校验分支均通过。

## 方法总结

面对语言运行时打包二进制，先从可观察 I/O 回溯用户逻辑，通常比全局静态分析更高效。复杂校验应按独立分支拆解：常量变换手算，模方程用 CRT，有限位宽约束交给 SMT。求解后仍要用原程序验证完整字符串，特别留意端序、位宽和大小写。
