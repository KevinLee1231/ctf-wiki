# StupidTinyAsm

## 题目简述

附件是 Python 字节码，内部又实现了一套只有寄存器、内存和跳转指令的小型虚拟机。指令流先经 Base64 解码和固定异或恢复，其中还夹有不会执行的诱饵区段与解密后清空内存的逻辑。目标是沿真实跳转路径提取九字节循环密钥和 27 个密文字节，在结果被擦除前还原 flag。

## 解题过程

### 解开指令封装

字节码中的指令字符串先做 Base64 解码，再逐字节异或 42，最后以 `|` 分隔：

```python
import base64

def decode_instructions(encoded):
    raw = base64.b64decode(encoded)
    return bytes(value ^ 42 for value in raw).decode().split("|")
```

解码后共有 79 条指令。虚拟机支持 `LOAD`、`STORE`、`LOADMEM`、算术、异或及条件跳转，按语义解释即可，不必为每一条指令生成真实机器码。

### 跟随有效控制流

初始化段构造 `mem[0:8]`：

```text
0: 97 - 14 = 83  -> S
1: 72            -> H
2: 69            -> E
3: 19 * 4 = 76   -> L
4: 19 * 4 = 76   -> L
5: 36            -> $
6: 37 + 14 = 51  -> 3
7: 99            -> c
```

第 20 条指令是 `JNZ C 53`。此时 `C=14`，所以一定跳到 53，21 至 52 的 honeypot 与提前清理段不会执行。第 53、54 条又把 67 写入 `mem[8]`，于是完整的九字节表为：

```text
SHELL$3cC
```

解密区从 `mem[20]` 开始循环 27 次。对相对位置 $j$，指令 58 至 73 实现：

$$
p_j=(c_j+5)\oplus K_{j\bmod9}
$$

其中整数除法再乘回 9 的一段代码，等价于手工计算 `j % 9`。

### 在清空前直接恢复结果

密文字节为：

```python
encrypted = [
    27, 27, 27, 27, 27, 68, 77, 18, 33,
    27, 46, 17, 119, 28, 18, 103, 11, 50,
    33, 51, 111, 3, 14, 96, 18, 9, 57,
]
```

不需要把整个解释器运行到结尾，直接执行等价变换：

```python
key = b"SHELL$3cC"
plain = bytes(
    ((value + 5) & 0xff) ^ key[i % len(key)]
    for i, value in enumerate(encrypted)
)
print(plain.decode())
```

得到：

```text
shellmates{S0m3_stup1D_A$m}
```

解密循环结束后，第 77 条指令跳回内存清理区，最终才到 `HALT`。因此若只在 VM 正常退出后读取 `mem[20:47]`，看到的会是零值；应在跳转到清理段之前截取，或像上面一样直接实现等价公式。

## 方法总结

这道题的障碍是多层解释：Python 字节码包裹 Base64/XOR 指令，指令又由自定义 VM 执行。有效做法是逐层降低抽象：先恢复指令文本，再跟踪确定成立的条件跳转，最后把长指令段归纳成简单公式。尤其要留意“先解密、后擦除”的控制流，程序最终状态不一定保留中间的正确答案。
