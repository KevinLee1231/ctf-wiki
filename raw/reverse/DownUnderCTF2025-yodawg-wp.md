# YoDawg

## 题目简述

附件是一个 .NET WinForms 程序（`Yo Dawg.exe` 与 `Yo Dawg.dll`），模拟名为 Yo Dawg CTF 的多关卡游戏。发布包没有源代码；官方说明给出两条路径：在隔离 Windows 环境中按 UI 逐关作答，或静态逆向程序的校验链。DLL 中存在 `flagstart`、`flagmiddle*`、`flagend` 等字段，同时混入多套伪 AES、伪 `getflag`、假 Base64 和无关变量，不能把第一个看似解密函数当成答案来源。理解程序状态与真实的最终 DES 校验链是主障碍，故归入 reverse。

## 解题过程

先把 ZIP 视为受信任 CTF 附件之外的未知 Windows 程序：不要在日常主机直接运行。静态路线应从按钮事件、关卡计数和提交比较处反向追踪，筛去未被最终状态引用的假 AES 与假 `getflag`，确认每一关对状态的实际贡献。

官方给出的正常关卡链可整理如下：

1. 2025 部分依次包含 Caesar（`Salads`）、弱密码哈希、ROT、隐藏的 Morse、RSA 和 Vaas 语音演员等小题；Vaas 的答案会被要求输入两次。
2. 进入 1995 部分后，DES 小题的中间值为 `flag{des4eva}`，DEFCON 3 问答答案为 `Tropicana`，电影 *Hackers* 的三词引语为 `Hack the Planet!`。
3. 完成状态机的全部关卡后，程序展示一段最终 DES 密文。沿真实的 DES key/IV 与解密调用处理该密文，而非调用四个诱饵 AES 函数。

最终 DES 明文为：

```text
DUCTF{1995_to_2025}
```

仓库提供的官方说明没有保留弱哈希明文、RSA 参数和最终密文的字面值；它们仅在编译后的程序中。以上保留了官方给出的完整状态推进顺序和已公开的中间答案，静态复现时应以实际比较点与资源中的值为准，不能凭本文补造缺失常量。

## 方法总结

- 核心技巧：以最终状态、实际比较和可达调用链为准清理诱饵，而不是按函数名搜索加密例程。
- 识别信号：多窗体游戏程序含有同类加密函数、半明文 flag 片段和明显假函数时，通常存在伪控制流或死代码；先恢复关卡状态机再分析最后的解密分支。
- 复用要点：对仅提供编译产物的 GUI 题，先静态确认运行时、资源、按钮事件与状态变量；若需要动态验证，应使用隔离环境并将每个输入与状态变化记录下来。
