# mostly-harmless

## 题目简述

服务去掉输入外层的 `maple{}`，把每个字符编码成嵌套泛型类型，并替换到生成文件的固定位置；只有 `mypy` 类型检查成功才接受。文件定义了大量泛型类和一个逆变类型变量，实际把子类型关系当成了一台编译期图灵机。

目标不是爆破 mypy，而是从生成代码中恢复状态转移和每次输出的字符。

## 解题过程

字符 `c` 被编码为类似 `L_c[N[...]]` 的嵌套类型。由于 `T = TypeVar(..., contravariant=True)`，泛型参数的子类型方向被反转；配合类继承声明，mypy 在证明最终赋值合法时会沿预设状态不断归约。文件后半部分的类名已经暴露状态编号，例如形如：

```python
class QL_s29(..., L_n["N[QLW_s31[...]]"]):
    ...
```

可解释为“状态 29 消耗或输出字符 `n`，随后进入状态 31”。从入口状态 29 开始，逐个解析这些继承基类，记录 `L_` 后的字符和 `s` 后的下一状态；遇到终止状态 71 时停止。这样得到的是唯一能让类型归约走到接受态的字符序列。

将恢复出的内容放回 `maple{}`，可在本地用题目相同版本的 mypy 再做一次验证。最终 flag 为：

```text
maple{no_type_system_is_safe_from_pl_grads_with_too_much_time_on_their_hands}
```

## 方法总结

类型系统题不必从所有泛型规则同时入手。先找到输入如何编码、接受条件在哪里，再把重复命名模式压缩成“当前状态—字符—下一状态”三元组，复杂继承图就会退化成普通状态机。逆变决定子类型方向，字符串前向引用只延迟名称解析；这两点分清后，剩余工作主要是忠实提取转移而非猜 flag。
