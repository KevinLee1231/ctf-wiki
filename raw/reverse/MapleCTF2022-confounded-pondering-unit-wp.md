# confounded-pondering-unit

## 题目简述

附件是一个 Logisim Evolution 实现的 16 位自定义 CPU 和运行其上的 flag checker。题目说明输入为 64 位十六进制数，格式是 `maple{XXXX_XXXX_XXXXX_XXX}`，检查器从内存地址 `0xf1a9` 读取输入。需要恢复 CPU 指令集并理解校验程序。

## 解题过程

从 Logisim 电路沿程序计数器、指令寄存器和多路选择器追踪数据路径，可以区分立即数、算术、访存和跳转类指令。给各控制线重新命名后，再对照 ROM 中重复出现的指令模式，先恢复装载常量、读写内存和条件跳转，随后即可把 checker 转写为伪代码。

校验程序把地址 `0xf1a9` 起的四个 16 位字拼为 64 位输入，经固定的移位、异或和比较流程后与内置常量比对。官方源码还附带了 customasm 汇编定义和设计说明，可以反向核对静态分析；其中给出的目标 64 位值为：

```text
0xf1a9_f33d_bac04_777
```

按题目要求保留大写十六进制并加外层格式，得到：

```text
maple{F1A9_F33D_BAC04_777}
```

## 方法总结

分析门级或 Logisim CPU 时，先恢复数据通路和控制信号，再读程序，比直接猜每个 opcode 更稳定。输入地址 `0xf1a9` 同时是 flag 的开头，是题目刻意留下的线索。官方源码中的汇编器和设计说明适合用于验证已经恢复的 ISA，但完整题解仍应说明内存布局和 checker 的作用，不能只抄最终常量。
