# DownUnderCTF 2021 - Juniperus

## 题目简述

题目模拟把后门口令伪装成正常日志字符串的供应链后门。程序表面上会对输入计算 SHA3-512 并与随机数据比较，使正常认证几乎不可能成功；但另一条隐藏分支把用户输入与一条看似普通的日志消息比较，只要命中该字符串就直接通过认证。

## 解题过程

从 `main` 开始追踪认证结果，可以看到两条可能成功的路径。第一条对输入做 SHA3-512，再与运行时生成的随机字节比较。这条路径没有可预测的固定目标，属于障眼法。

继续检查日志相关函数的交叉引用。大部分日志文本都传给同一个输出函数，只有下面这条字符串进入另一个函数：

```text
[I] Authentication complete.
```

该函数内部没有复杂哈希逻辑，而是一个被编译器内联的字符串比较。它依次比较日志字符串和调用方作为可变参数传入的用户输入，并把比较结果返回给认证表达式。程序的判断关系等价于：

```c
authenticated = backdoor("[I] Authentication complete.", input)
             || normal_hash_check(input);
```

因此不需要攻击 SHA3，也不需要猜随机值。直接把这条完整日志消息作为密码提交：

```text
[I] Authentication complete.
```

认证通过后即可得到：

```text
DUCTF{57r1ng5-4bl3... k1nd4}
```

题名对应 Juniper ScreenOS 的历史后门事件：当时的特殊口令同样被伪装成貌似无害的日志文本。本题复现的是这种“日志字符串实际参与认证”的设计，而不是复现当年的具体密码或密码算法。

## 方法总结

逆向认证程序时不能只盯着最显眼的哈希函数。应从最终布尔结果反向追踪每一个可达的成功分支，并检查字符串的所有交叉引用。这里随机 SHA3 比较只是不可行的正常路径，决定性线索是某条日志字符串被传入了不同的函数，并在其中与用户输入直接比较。
