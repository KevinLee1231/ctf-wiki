# What's Up Sys

## 题目简述

附件提供一份原始二进制和一份被破坏的版本。程序允许用户在映像偏移 0 至 0x1fff 内修复一个字节；只有恢复正确字节后，最终系统调用才会正常写出 flag。任务是定位两文件唯一差异并按十六进制格式提交。

## 解题过程

逐字节比较两文件，只有一个差异：

~~~text
offset 0x1572: original 0x01, corrupted 0x3c
~~~

该字节位于构造 syscall 编号的指令中。0x3c 对应 exit 系统调用相关值，使程序提前走错路径；恢复 0x01 后，getFlag 路径使用正确的 write 调用。

输入解析采用 %4x 和 %2x，所以偏移和值都应发送十六进制文本：

~~~text
1572
01
~~~

程序在内存映像中完成单字节修补并执行，输出：

~~~text
maple{W1ck3D_5h0oT1N9_C4pT41n!}
~~~

## 方法总结

有参考文件时，二进制 diff 是比盲目反汇编更低成本的入口。找到差异后仍应回到指令语义确认它为何影响控制流或系统调用，并注意题目输入的是文件偏移、虚拟地址还是段内偏移。提交格式中的十进制/十六进制也必须从 scanf 格式串核对。
