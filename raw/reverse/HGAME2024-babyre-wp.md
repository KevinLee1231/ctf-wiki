# babyre

## 题目简述

这是一道 Linux ELF 逆向题，主要考查构造函数、信号异常处理以及信号量实现的多线程同步。程序要求输入 32 字节，加密操作被分散在四个线程中；恢复出真正的 key、异常处理后的尾部状态和线程执行顺序，才能正确逆变换。

## 解题过程

### 恢复输入与 key 初始化

主函数先检查输入长度是否为 32，将字符逐个保存到整型数组，然后把第 33 个数组元素设为 `249`。静态观察到的 key 是 `123456`，但对该全局数组查交叉引用，可发现一个在 `main` 之前运行的 constructor 将其改写为：

```text
feifei
```

后续循环原本要对 key 的六个字节都异或 `0x11`，但当索引为 3 时会做除零操作，触发 `SIGFPE`。信号处理函数结束该循环，并将尾部状态从 `249` 加到 `250`。因此只有前三个 key 字节被异或，最终为：

```text
feifei XOR 0x11 on the first three bytes = wtxfei
```

即整数形式：

```c
char key[] = {119, 116, 120, 102, 101, 105};
```

### 确定四个线程的顺序

程序初始化四个信号量，每个工作线程在处理当前位置后唤醒下一个线程。沿 `sem_wait` 和 `sem_post` 对应关系可得到循环：

```text
加法 → 减法 → 乘法 → 异或 → 下一组加法
```

每四个输入字节为一组，并会依赖后一位。因此解密时要从最后一组向前走，并按“异或、乘法、减法、加法”的逆序撤销变换。第 33 个元素 `250` 正是最后一组逆算所需的边界状态。

### 逆变换并输出 flag

完整解密程序如下：

```c
#include <stdio.h>

char key[] = {119, 116, 120, 102, 101, 105};

int main(void) {
    int enc[33] = {
        12052, 78, 20467, 109, 13016, 109, 27467, -110,
        9807, 91, 21243, -100, 11121, 20, 10863, -107,
        10490, 29, 10633, -101, 10420, 78, 17670, -38,
        6011, -4, 16590, 125, 10723, 15, 7953, 255, 250
    };

    for (int i = 28; i >= 0; i -= 4) {
        enc[i + 3] ^= enc[i + 4] - key[(i + 4) % 6];
        enc[i + 2] /= enc[i + 3] + key[(i + 3) % 6];
        enc[i + 1] += enc[i + 2] ^ key[(i + 2) % 6];
        enc[i] -= enc[i + 1] * key[(i + 1) % 6];
    }

    for (int i = 0; i < 32; ++i) {
        putchar(enc[i]);
    }
    putchar('\n');
    return 0;
}
```

运行后得到：

```text
hgame{you_are_3o_c1ever2_3Olve!}
```

## 方法总结

- 全局常量不一定是真正运行值；要继续查交叉引用、`.init_array` 和 constructor。
- `setjmp/longjmp`、`signal` 与人为除零常用来隐藏非线性控制流，不能把循环按正常路径全部执行。
- 多线程代码的源码排列顺序不等于运行顺序；应以信号量、锁和条件变量构建真正的依赖图。
- 从最后一组向前逆算是因为当前组依赖后继状态；先识别数据依赖，再决定逆变换的遍历方向。
