# Cpp

## 题目简述

题目使用 C++ 类和虚函数包装一个改造过的 ChaCha20 流程，并附带 PDB 符号。主函数中存在两个假 flag；真正数据进入 `encrypt2` 对象。需要恢复类结构、识别字节序转换与加密函数，最终从运行时状态中取得密钥流并异或密文。

## 解题过程

加载 PDB 后，把主函数中的对象指针类型改为 `encrypt2 *`，虚函数调用关系会清晰很多：

- `func2` 初始化 ChaCha 状态；
- `func3` 把输入字符串复制到字节向量；
- `func5` 每四字节按大端序组合为一个 32 位整数；
- `func6` 生成密钥流并与输入异或；
- `func7` 负责最终校验或解密输出。

`func5` 的关键组合为：

```c
word = byte3 + (byte2 << 8) + (byte1 << 16) + (byte0 << 24);
```

状态中能看到 ChaCha 常量、计数器 `0x12345678` 和 nonce `hga`，但题目把字符分别放进 32 位槽位，初始矩阵并不符合标准库的常规密钥布局，所以直接调用现成 ChaCha20 API 得不到正确结果。

在最终异或前下断点，导出十个 32 位密钥流字：

```text
1077387342, 4258923078, 1013905953, 3483163055, 1731413945,
233590496, 327206097, 984787250, 39669927, 2202679682
```

加密后的 40 字节为：

```text
28 50 c1 23 98 a1 41 36 4c 31 cb 52 90 f1 ac cc
0f 6c 2a 89 7f df 11 84 7f e6 a2 e0 59 c7 c5 46
5d 29 38 93 ed 15 7a ff
```

按照程序的大端分组方式逐字节异或：

```python
key = [
    1077387342, 4258923078, 1013905953, 3483163055, 1731413945,
    233590496, 327206097, 984787250, 39669927, 2202679682,
]
encrypted = [
    0x28, 0x50, 0xC1, 0x23, 0x98, 0xA1, 0x41, 0x36,
    0x4C, 0x31, 0xCB, 0x52, 0x90, 0xF1, 0xAC, 0xCC,
    0x0F, 0x6C, 0x2A, 0x89, 0x7F, 0xDF, 0x11, 0x84,
    0x7F, 0xE6, 0xA2, 0xE0, 0x59, 0xC7, 0xC5, 0x46,
    0x5D, 0x29, 0x38, 0x93, 0xED, 0x15, 0x7A, 0xFF,
]

plain = bytes(
    value ^ ((key[index // 4] >> (24 - 8 * (index % 4))) & 0xFF)
    for index, value in enumerate(encrypted)
)
print(plain.decode())
```

得到：

```text
hgame{Cpp_1s_much_m0r3_dlff1cult_th4n_C}
```

## 方法总结

有 PDB 时应先恢复 C++ 类和虚表类型，再跟踪各成员函数职责。识别出标准算法只是起点，还必须核对初始矩阵、计数器、nonce、端序和数据布局；题目只要改动其中一项，直接套库就会失败。动态导出最终密钥流再复现最后的异或，是验证静态分析结果的有效办法。
