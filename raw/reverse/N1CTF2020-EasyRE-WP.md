# N1CTF 2020 EasyRE Writeup

## 题目简述

EasyRE 是 Windows x64 自定义虚拟机。`vm_init` 把 `opcode.bin` 映射到固定地址，`vm_run` 通过嵌套结构化异常处理和 `WaitForMultipleObjects` 调度指令；每条虚拟指令长 12 字节。输入长度为 63，前半段由累积关系校验，后半段还会经过半字节交换与异或。

## 解题过程

### 恢复异常驱动的 VM 调度

程序不使用普通 `switch(opcode)`。不同异常处理器承担不同操作，线程/事件等待结果决定下一个处理器。先在所有异常入口和 `WaitForMultipleObjects` 返回点下断点，记录：

```text
指令地址、12 字节原始指令、被触发的 handler、寄存器/栈变化
```

结合 `opcode.bin` 的固定映射地址，在 IDA 中为每个 handler 建立独立函数，并给 12 字节格式的操作数命名。这样可以写出简易反汇编器，把异常控制流还原为顺序 VM 指令。

### 解第一层累积约束

第一层从已知前缀 `n1ctf{` 开始维护累积和及两个滚动状态。每条指令产生一个结果常量。官方脚本把这些常量保存为 `result_i`，再按当前指令类型建立关系：

```python
x = abs(result[i] - running_sum)
```

一类指令执行普通异或，另一类还交换字节的高低半字节：

```python
def swap_nibble(x):
    return ((x << 4) & 0xf0) | ((x >> 4) & 0x0f)
```

把每个输入字节建成 8 位变量，按 VM 指令顺序更新状态；可以直接逆推，也可以交给 Z3。每得到一个字节就更新累积和，不能把所有方程当作彼此独立。

### 解第二层并验证

第二段对已恢复字节再次执行 nibble swap、异或和状态交换。按反汇编后的逆序应用逆变换，可得到完整 63 字节输入：

```text
n1ctf{ThE_X64_StRuCtUrEd_eXcEpTiOn_hAnDlInG_Is_sO_InTeReStInG.}
```

源码 `encrypt.cpp` 中留有相同字符串，可作为最终交叉验证；但求解过程仍应以 VM 字节码和运行轨迹为证据，不能只从源码注释抄答案。

## 方法总结

自定义 VM 的首要工作是恢复“取指—译码—执行—跳转”四个角色，即使它们被异常处理和线程等待拆散。固定指令宽度提供了强结构线索。写解释器或反汇编器后，再把状态更新翻译成方程，比在异常处理器间手工追踪 63 个字符更可靠。
