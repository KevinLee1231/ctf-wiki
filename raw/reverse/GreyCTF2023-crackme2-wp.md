# GreyCTF 2023 Crackme2

## 题目简述

题目给出一个分块自解密的 x86-64 crackme。真正的校验代码没有以普通函数形式留在可执行段，而是被切成许多小块后用不同的 32 位密钥异或，混入 `ENC_CODE` 数组。程序每次只解密并执行一块，再由该块返回下一块的编号和密钥；此外还加入假校验、无效算术、`ptrace` 反调试和 512 层调用包装。

## 解题过程

主程序给出了链入口：

```c
#define STARTING_ID 305
#define STARTING_KEY 657042170
```

`codewriter` 先把 `ENC_CODE[id]` 当作块长度，随后按 32 位小端字逐项异或密钥，将结果写入 RWX 映射。`trampoline` 调用恢复出的代码，并把返回值 `eax` 作为下一块编号、`ecx` 作为下一块密钥。因而可以在离线模拟器中按以下状态转移遍历真实执行链：

```text
id  = 305
key = 657042170

重复：
  words = ENC_CODE[id + 1 : id + 1 + ENC_CODE[id]]
  code  = 每个 words[i] 与 key 异或后按小端拼接
  执行或仿真 code
  id  = EAX
  key = ECX
```

不能把每个访问输入的块都当作有效条件。生成器中的真实检查会恢复输入地址和下标，读取一个字节，计算 `expected - input[i]`，再把差值 OR 进 `r12`：

```asm
movzx reg3, BYTE PTR [flag_base + index]
sub   expected_reg, reg3
or    r12, expected_reg
```

假块虽然也读取输入，却只做 XOR、比较和噪声运算，不会更新最终累计值。首块还通过 `ptrace` 的返回值选择失败链，因此离线仿真时应把未被调试的语义固定下来。遍历链并筛选所有写入 `r12` 的真实块，就能按下标收集期望字节；末尾的 `test r12, r12` 与条件移动则验证只有全部差值为零时才进入成功块。

按下标排列恢复出的字节为：

```text
grey{d1d_y0u_s0lv3_by_emul4t1ng?_1e4b8adeg}
```

## 方法总结

面对分块自修改程序，先识别“块地址、解密密钥、下一状态”三元组，比从静态反汇编中追逐随机数据有效。这里 `eax/ecx` 明确构成了解密链，`r12` 则是区分真实校验与诱饵的关键数据流。最稳妥的方案是逐块仿真并记录有效输入约束，而不是在反调试和深调用栈下直接单步整个程序。
