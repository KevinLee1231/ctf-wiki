# Wacky Recipe

## 题目简述

`recipe.txt` 采用 Chef 式“食谱程序”叙述，两个关键配料数量 `pain` 与 `effort` 被替换为 `??`。生成器揭示这并不是菜谱计算，而是将每个 flag 字节倒序拆成线性表达式。难点在于还原这门描述性语言的运算语义，归入 Reverse。

## 解题过程

每一组烹饪指令对应一个输出字节。`Put water` 加上后续 `Add water` 的次数给出系数 $q$；`Combine pain` 贡献 $q \times a$；加入或移除某种配料给出带符号常数 $r$；`Add effort` 最后加上 $d$。因而每组满足：

$$c=q\times a+r+d$$

其中 $a$ 是 `pain` 的数量，$d$ 是 `effort` 的数量。生成器对 flag 的倒序字节进行编码，所以恢复出的字节序列还需反转。

读取前六组配料/指令，枚举较小非负整数 $a,d$ 并要求每组产生可打印字符。官方辅助求解器以样例 `FTCUD` 验证同一方程；完整生成器给出唯一参数：

```text
pain = 27
effort = 21
```

把所有 $c$ 转为字符并反转，得到：

```
DUCTF{2tsp_Vegemite}
```

## 方法总结

esolang 或主题语言题的第一步是把自然语言指令压缩成明确的状态转移和数学式。这里每段的系数、常数和未知偏移量都可从文本静态读出；用少量样本方程筛选参数，再用完整 flag 格式验证，比把所有可能字符逐位猜测更稳健。食谱截图、终端输出等纯文字材料应直接转写，不必作为图片保存。
