# flag-printer

## 题目简述

二进制的关键函数被若干 HLT 指令 0xf4 故意破坏，直接运行会因特权指令异常停止。题目提供的 patch.py 展示了生成思路；目标是通过周围稳定字节定位三处补丁并恢复正常控制流。

## 解题过程

不要全局把所有 0xf4 替换成 NOP，这会破坏真正的数据。官方脚本用正则匹配三段上下文：

- 函数序言首字节 0xf4 改为 0x55，即 push rbp；
- 连续三个 0xf4 所在位置改为 48 89 c6，即 mov rsi, rax；
- 尾部 0xf4 改为 0xc3，即 ret。

~~~python
patches = {
    rb"\xF4\x48\x89\xE5\x48\x83\xEC\x60": b"\x55",
    rb"\xF4\xF4\xF4\xBF....\xB8\x00\x00\x00\x00": b"\x48\x89\xC6",
    rb"\xF4\x0F\x1F\x80\x00\x00\x00\x00\xB8\x01\x00\x00\x00": b"\xC3",
}
~~~

每次只覆盖匹配起点处与补丁等长的字节，保存为新文件并赋予执行权限。修复后的程序打印：

~~~text
maple{r3v3r_0r_p4tch3r?}
~~~

## 方法总结

二进制修补应依赖控制流和上下文签名，而不是对单字节做无差别替换。反汇编补丁前后，确认栈帧序言、参数传递和函数返回都恢复合理，再运行副本；始终保留原文件用于哈希和回滚。
