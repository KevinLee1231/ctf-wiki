# BrainfOok

## 题目简述

题目在 Python 中实现了一套魔改 Brainfuck VM：4 个寄存器、96 个普通内存槽、两组 32 位 bit memory、两套跳转栈和 25 种 opcode。Python 负索引会访问数组尾部，整数也不会像 C 固定宽度那样自然溢出；若直接把 VM 机械翻译成 C 而不模拟这些语义，后半段校验会产生错误。

外层字符画、编码和 AES 只负责隐藏 VM code。真正难点是去掉会相互抵消的指令、无效位运算和冗余内存操作，同时保留 `#()` 相对跳转所依赖的位置，最后把低信息密度的数十亿步 VM 归纳成 32 字节输入上的高层约束。

## 解题过程

### 1. 恢复准确的 VM 语义

先从 Python code object/常量中取出解密材料与 VM 字符串，只保留有效字符：

```text
+ - < > ! ? ; { } [ ] ( ) . : $ @ & | ^ ~ , * % #
```

模拟器必须保留 Python 行为：寄存器和内存值为任意精度整数，`stat[-1]`、`stat[-2]` 等映射到数组尾部；`!`/`;` 管理循环地址，`#` 找到后续括号并用当前寄存器值修正目标，`()` 再根据 zero flag 跳转。错误输入常进入死循环，不能把超时简单当作 VM 崩溃。

### 2. 分段去混淆并恢复高层逻辑

`+-`、`<>` 等对称操作、未被消费的 bit-memory 操作和连续无效 `{}`/`]` 可以删除，但 `#()` 的目标按物理 code offset 计算。稳妥做法是在执行到每个实际跳转时记录寄存器、内存、标志、跳转栈和目标区间，把目标覆盖范围标为保留区；以断点快照继续后续执行，逐段简化，而不是一次全局替换。

归纳后，输入约束包括：

- 长度恰为 32，全部字符可打印，相邻字符不相等；
- 第 4、12、18、21、26 字节由 CRT 或单字节关系确定为下划线；
- 字节 0–3、28–31 和 13–16 分别进入三组 TEA 风格 16 位轮函数；
- 字节 5–11 乘以固定 $4\times7$ 矩阵并与四个常量比较；
- 其余字节还受链式 XOR、乘积、大小关系、质数构造和残留轮函数中间值约束。

### 3. 在高层重写约束

不要继续逐 opcode 跑 20 多亿步。把三个 16 位轮函数按 VM 的实际运算顺序重写，所有需要截断的结果显式 `& 0xffff`；矩阵和代数约束则直接写成 Python 断言或交给 Z3。特别注意第二、三组轮函数会复用前一阶段的 `sum` 和派生 key，不能把它们误当作三个彼此独立、均从零初始化的 TEA。

满足全部约束的 32 字节输入为：

```text
Th1s_e50l4nG_Mak35_m3_F3e1_D1zZy
```

把它重新送入原 VM，程序走到正确分支。最终 flag 为：

```text
SCTF{Th1s_e50l4nG_Mak35_m3_F3e1_D1zZy}
```

## 方法总结

本题不适合“每条 VM opcode 对应一条汇编”的模板化逆向，因为同一算术操作由多种低级组合实现，单步 trace 的信息密度极低。正确路线是先忠实模拟 Python 特性，再用执行轨迹保护跳转敏感区，分段去混淆，最后把行为提升成少量可读的算术约束。候选输入必须回放原 VM；高层模型求得可打印串只是中间证据，原实现通过才是最终验证。
