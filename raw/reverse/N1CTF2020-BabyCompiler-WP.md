# N1CTF 2020 BabyCompiler Writeup

## 题目简述

BabyCompiler 由 Lex/Yacc 生成，输入不是普通 flag 字符串，而是一段必须满足隐藏文法及语义动作的表达式。编译后的二进制包含大量自动生成的状态表、移进/归约代码和错误处理，真正有用的信息分散在词法 token 映射和每条归约规则的 action 中。

## 解题过程

### 恢复词法 token

先从字符串引用和词法分析器的接受状态入手。对照标准 Flex 模板，可以找到“匹配规则编号 → 返回 token”的 switch。题目可识别的关键字和符号包括：

```text
n1ctf  {  }  YACC  LEX  CTF  FUN  +  -  *  ^  NUMBER
```

在每个 `return TOKEN_ID` 处记录 token 编号，便可把 Bison 解析表中的数字重新映射为可读终结符。

### 恢复 Yacc 归约和语义动作

对照 Bison 生成代码模板，定位 `yyreduce` 以及按规则号分派的 switch。每个 case 对应一条文法规则，并会更新全局变量 `a,b,c,d,e` 或归约值 `yyval`。在调试器中对 switch 入口下断点，输入单个 token、两项表达式和带括号表达式，记录归约规则序列，可补全静态分析中难以辨认的优先级与结合性。

恢复后的结构表明，程序要求外层为 `n1ctf{...}`，内部由 `YACC`、`LEX`、`CTF`、`FUN` 和运算符组成。不同归约动作对全局状态执行加、减、乘、异或及常数比较；末尾数字是使所有状态同时命中的自由量。

### 反解表达式

按文法优先级逐步模拟语义动作，而不是使用宿主语言默认优先级。固定关键词与运算符后，把末尾整数记为 $x$，将最终比较条件化简即可求出：

```text
x = 1447380
```

完整输入为：

```text
n1ctf{YACC*LEX+CTF-FUN^1447380}
```

将其送回程序，词法分析不会进入错误 token，Yacc 最终归约到开始符号，且全部语义状态检查通过。

## 方法总结

Lex/Yacc 二进制虽然代码量大，但结构高度模板化。分析时先识别生成器模板，再只恢复三张映射：规则号到 token、归约号到文法、归约号到语义动作。文法优先级必须由解析过程确认；直接把表达式复制到 Python/C 计算，可能因 `^` 含义和结合性不同而得到错误结果。
