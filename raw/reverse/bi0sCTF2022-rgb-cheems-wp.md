# bi0sCTF 2022 RGB Cheems Writeup

## 题目简述

RGB Cheems 是一款 Unity 平台跳跃游戏。题目原本放在 Misc，但取得 flag 的决定性步骤是反编译并修改 Unity 的托管程序集：提高玩家移动能力，或关闭阻挡路线的二维碰撞体。因此归档到 reverse，而不是按原赛道名称机械放入 misc。

附件 `RGB_Cheems.rar` 中的关键文件是 `Chall_Data/Managed/Assembly-CSharp.dll`。游戏逻辑是 C# IL，使用 dnSpy 一类 .NET 反编译器即可阅读和修改，不需要逆向 Unity 引擎本体。

## 解题过程

### 定位玩家控制逻辑

先备份 `Assembly-CSharp.dll`，再用 dnSpy 打开并搜索 `PlayerController`。该类负责读取方向和跳跃输入，并把速度、跳跃力等字段用于刚体运动。直接调高这些数值，就能让角色跨越正常流程中难以通过的地形。

修改时应编辑 C# 方法或字段并重新编译方法，而不是在反编译视图里只改显示文本。保存模块后，将生成的 DLL 放回原路径，再启动游戏验证人物速度和跳跃高度是否变化。

### 关闭墙体与屋顶碰撞

仅提高速度并不是唯一解。关卡中的大墙和屋顶挂有 `BoxCollider2D`，对应脚本本身没有关键校验逻辑。可以在相关组件初始化时加入：

```csharp
GetComponent<BoxCollider2D>().enabled = false;
```

也可以通过编辑场景对象或在现有脚本中取得组件后禁用它。大墙碰撞关闭后可以直接穿过；屋顶碰撞关闭后还可以跳出地图边界，从外围绕到终点。两种路线的本质相同：修改客户端托管逻辑，使本地物理引擎不再执行原关卡约束。

### 到达终点

重新加载修改后的程序集，确认没有因目标框架或引用版本不一致导致模块保存失败。随后使用提高后的移动参数正常完成关卡，或在禁用屋顶碰撞后从地图外侧抵达终点。完成触发器显示：

```text
bi0sCTF{GG!_H4X_F0R_TH3_WIN!}
```

如果游戏在替换 DLL 后无法启动，应恢复备份，并检查 dnSpy 保存时是否保留了程序集名称、目标运行时和所有引用；无需重新打包整个 Unity 工程。

## 方法总结

Unity 题首先要判断逻辑位于托管层还是原生层。只要目录中存在 `Managed/Assembly-CSharp.dll`，而控制器和碰撞逻辑都能在 C# 中恢复，就应优先分析托管程序集。这里无需寻找内存破坏漏洞，修改速度、跳跃和 `BoxCollider2D.enabled` 已足以改变胜利条件。

归档分类应依据决定性技术障碍：虽然题目位于原仓库的 Misc 目录，但解法依赖 .NET/Unity 程序行为恢复与补丁，因此 reverse 更准确。
