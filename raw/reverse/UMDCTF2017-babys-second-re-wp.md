# Baby's Second RE

## 题目简述

`baby2` 会生成大量相同长度的候选字符串，再从指针表中选出一个参与比较。直接查看 `strings` 看不到 flag，关键是确定程序最终引用了候选表的哪一项。

## 解题过程

在 `main` 的栈帧中，候选指针数组起始于 `rbp-0x1f40`，最终送入比较逻辑的指针位于 `rbp-0xcc8`。二者的距离为：

$$
0x1f40-0x0cc8=0x1278
$$

64 bit 指针每项 8 字节，因此索引为：

$$
0x1278/8=591
$$

也就是取零基第 591 项。可以在候选表生成完毕后下断点，直接读取该槽位指向的 C 字符串；也可以在反编译器中复现程序的生成循环。该项内容为：

```text
ftofxcipqzwsbgvozjndeiriujudyjdr
```

程序使用的外壳与赛事常见格式略有不同，没有连字符：

```text
UMDCTF{ftofxcipqzwsbgvozjndeiriujudyjdr}
```

只有这个精确格式的 SHA-256 会命中 README 中的 `34287eadd26063d193587528795d3791bcb9219d6f19f2920be019c9ae2174a8`。

## 方法总结

面对大量诱饵字符串，不必逐项猜测。指针槽位的栈偏移差可以直接换算成数组下标，再动态读取对应元素。最终还应尊重二进制实际拼接出的外壳；题目名称相似不代表格式一定与其他题一致。
