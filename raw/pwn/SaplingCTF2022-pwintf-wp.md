# Pwintf

## 题目简述

程序在循环中反复把输入作为格式字符串处理，但 flag 不会直接留在可读参数中。需要先泄漏 libc 与栈地址，再利用 %hn 把后续栈参数改造成任意地址写原语，最终将 glibc 的 __free_hook 改为 system。输入缓冲区被释放时，缓冲区开头的 /bin/bash 被当成 system 参数。

## 解题过程

第一轮使用三个位置参数：

~~~text
%11$p
%6$p
%13$p
~~~

%11$p 对应 __libc_start_main 返回路径，减去配套 libc 中的固定偏移得到 libc 基址；另外两个泄漏建立当前格式串参数区与可修改栈槽的关系。

接着分四个 16 位片段写地址。先用 %13$hn 改写一个栈参数，使其依次指向目标参数槽；再通过计算出的动态位置参数，把 __free_hook、__free_hook+2、+4、+6 放进未来的第 8 至 11 个参数。最后一个格式串以命令开头，并用四次半字写把 system 地址写到 hook：

~~~text
/bin/bash #%<pad1>c%8$hn%<pad2>c%9$hn%<pad3>c%10$hn%<pad4>c%11$hn
~~~

每个 pad 都按“目标半字减去当前累计输出字符数，模 $2^{16}$”计算。处理完输入后程序 free 该堆缓冲区，实际调用变为 system("/bin/bash #...")。进入 shell 后得到：

~~~text
maple{h0p3_1t_d1dnt_t4k3_l0ng}
~~~

## 方法总结

复杂格式串利用通常分为三步：地址泄漏、建立稳定的间接参数写、按半字拆分最终目标。%hn 的值取决于累计输出量，必须逐段做模 $2^{16}$ 差值。Full RELRO 保护 GOT，但旧版 glibc 的 __free_hook 仍是可写控制目标；新版本已移除这些 malloc hooks，终点需随 libc 版本调整。
