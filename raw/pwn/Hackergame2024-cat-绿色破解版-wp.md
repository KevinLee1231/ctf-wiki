# cat 绿色破解版

## 题目简述

题目给出由 coreutils 9.5 编译的 `cat`，允许在 `_start` 到 `_term_proc` 之间修改至多 5 个字节。除最后一次修改可任意取值外，其余新字节只能是短条件跳转 `0x70..0x7f`、`0x00` 或 `NOP 0x90`；受检查的修改之间必须相距超过 8 字节。改后程序先接受 `cat secret` 的功能测试，再以 `cat secret -` 与选手标准输入交互。目标是让低权限程序创建 `/dev/shm/hacked`，内容以 `hacked by ` 开头。

决定性障碍不是比较原版与破解版本身，而是用极少字节修改把正常缓冲区操作转成栈溢出，再构造 ROP 写文件，属于 `pwn`。

## 解题过程

### 两字节补丁制造栈溢出

`simple_cat` 调用 `safe_read(input_desc, buf, bufsize)`，再调用 `full_write(STDOUT_FILENO, buf, n_read)`。缓冲区指针作为局部变量保存在栈上，反汇编中两处都通过 `[rbp-0x38]` 取出它。

这两个内存操作数使用的是 8 位有符号位移：机器码中的 `disp8 = 0xc8` 表示 `-0x38`。将该位移字节清零后，寻址就从 `[rbp-0x38]` 变成 `[rbp]`。在给定二进制中的两个文件偏移为：

```text
0x2f87 + 3 -> 0x00
0x2f03 + 3 -> 0x00
```

补丁相距足够远，且新字节都是允许的零。结果是 `safe_read` 不再写入正常堆缓冲区，而是从当前函数栈底开始覆盖保存的 `rbp`、返回地址和后续栈；`full_write` 同样改用这块区域。只需 2 字节就获得可控栈溢出，且正常的 `cat secret` 路径仍能通过题目功能检查。

### 用 ROP 直接完成验收目标

题目只要求写 `/dev/shm/hacked`，无需 getshell，也无需 ret2dlresolve。无 PIE 的主程序包含稳定的 PLT 和足够的 gadget，可构造：

1. 用写内存 gadget 把字符串 `/dev/shm/hacked\0` 写到 `.bss` 可写区。
2. 调用 `open(path, 66, ...)`，其中十进制 `66` 是 `O_CREAT | O_RDWR`。创建文件时 `open` 是可变参数函数，严格来说还应在第三个参数中给出 mode；官方链没有控制该参数，但在给定环境中仍能创建并持有可写 fd。
3. 再把 `hacked by <name>` 写到同一 `.bss` 缓冲区。
4. 官方参考链调用 `write(0, message, length)`；这依赖题目实际执行点的 fd 布局使新文件取得 fd 0，不是 `open` 的通用保证。迁移到其他环境时应先确认返回 fd，或增加把 `rax` 传给 `rdi` 的 gadget。

链中需要分别控制 `rdi`、`rsi`、`rdx`，并利用程序内的 `open@plt`、`write@plt`。payload 前 8 字节填充栈底，随后接写字符串 gadget 与两次函数调用。发送完整 ROP 后关闭发送方向，使 `cat` 的标准输入读到 EOF 并沿被覆盖的返回地址执行链。

这个最短方案避开了官方长解中另外两处补丁：把主函数关闭 stdin 的条件跳转翻转，以及让 `simple_cat` 单轮读写后直接返回。那些修改能建立更通用的任意地址读写/ret2dlresolve 路线，但对“写一个固定验收文件”的目标不是必要条件。

### 补丁检查边界

校验器的最后一次修改会“眼花”，因此最后一字节不检查新值且不加入间距列表；不过两字节最短解完全不依赖这个特例。它还会先执行改后 `cat` 读取固定文本并比较 stdout，所以补丁必须既保留普通文件读取，又只在随后带 `-` 的交互阶段被输入触发。

### 验证

官方 `open_write_exp.py` 使用上述两个清零偏移、固定 `.bss` 地址、PLT 和 gadget，最终写入以 `hacked by` 开头的内容；`xiao_E_checker.py` 只按该前缀和非空名字发放 flag。本次没有实际运行二进制或远程服务，结论来自检查器、参考 exploit 与官方对 `simple_cat` 反汇编的静态交叉核对。

## 方法总结

- 核心技巧：通过清零两处寻址位移字节，把正常 read/write 缓冲区重定向到栈底，以最小补丁制造 ROP 控制流。
- 识别信号：可控单字节 patch、固定非 PIE 程序、同一缓冲区指针被 read/write 重复使用，以及功能测试后还有标准输入交互，意味着应优先搜索“一处语义修改、多处利用效果”。
- 复用要点：按验收目标选择最短链；只需创建固定文件时，`open + write` 通常比 getshell 或 ret2dlresolve 更稳定。对基于文件偏移的补丁必须绑定到题目给定二进制版本，不能脱离样本复用地址。
