# number mashing

## 题目简述

程序读取两个有符号 `int`，拒绝 $x=0$、$y=0$ 与 $y=1$，随后要求整数商 `x / y` 恰好等于原来的 $x$ 才打印 flag。看似只有除以 $1$ 才会满足，但检查恰好漏掉了 $y=-1$ 与最小负数相除的边界。

决定性问题是 C 有符号算术溢出在目标 AArch64 二进制中的表现：数学上的 $-2^{31}/-1=2^{31}$ 不能由 32 位有符号整数表示。随附官方 solver 给出了能令该二进制通过比较的输入，故本题按低层整数溢出检查绕过归入 Pwn。

## 解题过程

### 关键观察

`number-mashing.c` 的核心逻辑等价于：

```c
if (x == 0 || y == 0 || y == 1) exit(1);
int z = x / y;
if (z != x) exit(1);
```

对普通可表示值，$x/y=x$ 要求 $y=1$（或 $x=0$），二者均被拒绝。选择 `x = INT_MIN = -2147483648`、`y = -1` 时，数学结果 $2147483648$ 溢出 32 位 `int`。C 层面这是未定义行为，但题目交付物是由 QEMU 运行的 AArch64 程序；其 `SDIV` 在该溢出情形返回 `INT_MIN` 而不触发 x86 `IDIV` 那样的除法异常。因此目标二进制中 `z` 与 `x` 具有相同位模式，比较成立。

### 提交与验证

官方 solver 静态给出的唯一输入为：

```text
-2147483648 -1
```

它避开三项显式拒绝条件，并触发上述溢出比较。题目 `flag.txt` 与题目配置都给出验证值 `DUCTF{w0w_y0u_just_br0ke_math!!}`。本归档未运行目标程序；结论来自源码、发布配置与官方 solver 的一致对照。

## 方法总结

- 核心技巧：将等式检查与机器宽度一起分析，特别留意 `INT_MIN / -1` 这种唯一会使有符号除法结果越界的边界。
- 识别信号：输入已排除 $0$、$1$ 却要求除法结果保持不变，通常应检查负数、最小整数和截断语义。
- 复用要点：C 标准把这类溢出视为未定义行为；WP 与 exploit 都应以给定编译产物为准，不能把其行为泛化到别的架构、编译器或优化选项。
