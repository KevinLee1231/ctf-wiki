# N1CTF 2020 Pwn SignIn Writeup

## 题目简述

题目是一个以 `std::vector` 保存数值记录的菜单程序。删除操作移动内部指针并减少固定偏移，却没有清空已删除位置，也没有检查下界；攻击者可以反复执行删除，使访问位置越过容器边界。利用目标是先从堆管理器区域泄露 libc，再把越界写转化为 tcache 投毒，最终覆盖 `__free_hook` 为 `system`。

## 解题过程

### 反复删除制造越界访问

正常情况下，删除一个元素后程序应更新长度并拒绝继续删除空容器。但本题逻辑只把当前位置减去 8 字节，未校验它是否仍落在 vector 存储区，也未清除旧指针。先大量添加元素稳定堆布局，再反复选择同一索引删除，内部游标便会一路向低地址移动。

当游标到达 unsorted bin 附近时，`show` 会把堆元数据中的 main arena 指针按十进制打印出来。根据附带 libc 计算基址：

```python
leak = int(io.recvline())
libc.address = leak - 96 - 0x10 - libc.sym['__malloc_hook']
```

偏移中的 `96` 和 `0x10` 来自该 glibc 版本的 arena/bin 链接关系，复现时应以附件 libc 和实际泄露位置验证，不能当作通用常量。

### 移动到 tcache 链并投毒

继续执行删除，让失控游标到达 tcache 可复用的链表区域。之后的“添加”会把攻击者输入当作链表下一项写入。将目标设置为：

```python
target = libc.sym['__free_hook'] - 8
```

接下来的分配会返回该伪造地址附近。依次写入：

```text
/bin/sh\x00
system 地址
```

使 `__free_hook` 被改成 `system`。当程序再次释放保存 `/bin/sh` 的块时，实际执行变为 `system("/bin/sh")`。

官方和参赛队脚本中的大量循环次数用于跨过具体堆布局，例如先创建约 `0x120` 个元素、再执行数百和数千次删除。真正必须保留的是“游标每次移动 8 字节”这一不变量；循环次数应在本地调试中依据地址差计算，而不是无解释地复制。

## 方法总结

C++ 容器并不会自动消除业务代码中的边界错误。分析菜单题时，应同时记录逻辑长度、容量、数据指针和当前游标的变化；即使没有经典 UAF，只要游标能越过容器，仍可能读写堆管理器元数据。利用脚本中的长循环应还原成地址关系，这样才能解释泄露点和 hook 覆盖为何成立。
