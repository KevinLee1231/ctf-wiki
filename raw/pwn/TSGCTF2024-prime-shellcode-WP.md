# TSGCTF2024 prime shellcode

## 题目简述

程序在随机页地址映射 0x1000 字节，读取恰好一页输入，并要求每个原始字节都是 $0$ 到 $255$ 之间的素数。校验通过后把页面改为 RWX，覆盖开头三个字节为 `48 31 d2`，清空通用寄存器并跳入页面执行。

普通 `/bin/sh` shellcode 含大量非素数字节，不能直接提交。目标是用所有字节均为素数的第一阶段指令构造任意写，在校验后把普通第二阶段 shellcode 写回同一 RWX 页面。

## 解题过程

### 1. 取得随机映射基址

输入前三字节会被服务端改写，所以先用素数 `0x02` 填充占位。随后使用字节 `43 59` 编码的 `pop r9`。官方 payload 连续放置七次该指令，跨过间接调用建立的栈内容，最终把保存在调用帧中的 shellcode 地址取到 `r9`。

再用全部由素数字节组成的寄存器传递指令：

```asm
mov rbp, r9
mov r15, rbp
mov r11, r15
```

此后 `r11` 作为当前写指针，`r9` 保留页面基址。

### 2. 只用素数字节在 EAX 中合成任意小整数

指令 `mov bl, imm8` 的 opcode `0xb3` 本身是素数；只要立即数也选择素数，就能把任意 8 位素数放入 `ebx`。下列传递指令的机器码字节也全部为素数：

```asm
mov esp, ebx
mov ebp, esp
mov eax, ebp
```

若目标字节为 $v$，先选择不大于 $v$ 的近邻素数 $r$，令 `eax=r`。再把 `ebp` 设为 2，反复执行 `add eax, ebp`。若差值为奇数，用：

```text
+2 +2 -3 = +1
```

补齐最后一位。零可以从程序预先清零的 `r13d` 复制，1 则由 $3-2$ 构造。因此 0 到 255 的任意目标值都能在 `eax` 中生成，而第一阶段自身仍只含素数字节。

### 3. 形成任意地址写

`mov r15d, ebx`、`add r11, r15` 和 `sub r11, r15` 的编码也满足素数字节限制。用与数值合成相同的“近邻素数加减 2/3”方法，可把 `r11` 调整到页面内任意偏移。

最后执行：

```asm
mov dword ptr [r11], eax
```

其字节为 `43 89 03`，仍全部是素数。虽然一次写 4 字节，solver 逐字节向后移动地址并重叠写入，最终可得到任意连续字节串。

### 4. 写入并执行普通第二阶段

第一阶段在：

```text
page + 0x0f00  写入 "/bin/sh\0"
page + 0x0e00  写入普通 execve shellcode
```

第二阶段等价于：

```asm
mov rdi, r9
add rdi, 0xf00
xor rsi, rsi
xor rdx, rdx
mov rax, 59
syscall
```

第一阶段剩余空间用素数字节 `0x95` 填充；该字节解码为无害的寄存器交换，执行流会顺序滑到 `0xe00`，而那里此时已经被改写成第二阶段。最终执行 `execve("/bin/sh", NULL, NULL)`，读取 flag：

```text
TSGCTF{y0u_ar3_7ruly_a_pr1m3_5h3llc0d3r!}
```

## 方法总结

本题不是寻找一条完全由素数字节组成的最终 shellcode，而是先在受限字节集中构造计算与写内存原语，再自修改生成不受限制的第二阶段。只要允许页面同时可写可执行，且受限指令集能合成任意小整数和定址写，字节过滤就不能形成安全边界。应在写入完成后只授予 RX、在执行期间禁止写入，并对执行模型使用真正的指令级沙箱，而不是依赖输入字节白名单。
