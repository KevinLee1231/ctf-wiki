# MiniLCTF2023 - pycalculator

## 题目简述

服务把每行输入交给 Python `eval`，但先限制长度不超过 32，并拒绝所有 ASCII 英文字母。括号、引号、反斜杠、数字和非 ASCII 字符仍可使用。这是一道 Python jail：关键在于 Python 会把标识符按 NFKC 规范化，而过滤器只检查原始字符串中的 ASCII 字母。

## 解题过程

把内置函数名改写为全角字符，词法分析后会还原为普通标识符；字符串则用八进制转义避免出现字母。直接读取当前目录的 `flag`：

```python
ｏｐｅｎ('\146\154\141\147').ｒｅａｄ()
```

原始输入中没有 ASCII 字母，长度也在限制内；Python 执行时把 `ｏｐｅｎ`、`ｒｅａｄ` 规范化为 `open`、`read`，八进制字节依次对应 `f`、`l`、`a`、`g`。

还有一个更彻底的非预期绕过。第一层只提交：

```python
ｅｖａｌ(ｉｎｐｕｔ())
```

它通过原始过滤并调用第二次 `input()`；第二行内容直接进入内层 `eval`，不再经过长度和字母检查，因此可以提交任意 Python 表达式。官方旧 WP 写成 ASCII `eval(input())`，那会被源码中的过滤器拒绝；必须同样使用全角标识符。

## 方法总结

字符黑名单必须区分“过滤看到的码点”和“语言前端最终解释的标识符”。Python 对标识符做 Unicode NFKC 规范化，使全角拉丁字母成为常见逃逸入口。另一个通用检查点是二次输入：限制只作用于外层表达式时，`eval(input())` 会把未过滤数据重新引入执行器。两条路线都依赖执行边界逃逸，因此归入 Pwn，而非普通 Misc 编程题。
