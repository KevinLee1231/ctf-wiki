# Pyploit

## 题目简述

程序实现了一个极小的类 Python 解释器，只支持变量赋值、简单运算、输出和退出。变量由自定义链表/缓存管理，每个值对象带引用计数。表面的解析崩溃并非主要利用点；真正的漏洞发生在给已有变量重新赋值时：

- 旧值的引用计数先减 1；
- 计数到 0 时释放值对象；
- 变量链表中的缓存项没有被移除；
- `x = x` 仍可继续命中这条悬空记录，使计数减到负数并反复访问已释放对象。

通过自定义 mmap 缓存的复用，可以让这个“重复减 1”作用到新的变量指针，最终形成可控地址递减和目标内存递减原语。

## 解题过程

### 还原变量缓存布局

逆向变量查找与扩容函数可见，一组变量缓存中：

```text
base + 0x20   变量对象指针区
base + 0x340  变量名区
```

两者相差 `0x320`。每组原本按约 100 个变量组织，但程序并没有在语义层禁止继续创建；填满后会从 `free_mmap` 取旧映射或创建新映射。

先创建约 200 个 `dummy` 变量，再对前 100 个执行：

```text
dummy0 = dummy0
dummy1 = dummy1
...
```

这会释放一批值对象并把旧缓存映射送入复用路径，同时旧链表仍保留悬空引用。随后创建新变量，新的指针数组会覆盖旧数组的一部分。

### 把自赋值变成递减原语

重叠后，旧变量记录中的 `num_value` 位置可以对应到新缓存中的某个指针。于是：

```text
old = old
```

不再只是修改普通引用计数，而是在把一个新对象指针减 1。重复执行可把它逐字节/逐地址推到选定目标；接着对该新变量自赋值，又会对目标地址处的计数槽执行减 1。

利用时要先建立调试版的结构关系表，记录：

- 哪个旧变量控制哪个新指针；
- 每次自赋值实际递减 32 位还是 64 位字段；
- 从当前指针移动到目标需要多少次；
- 目标字段允许被递减多少而不提前破坏解释器。

公开利用先让重叠变量的输出指向 loader 区域，通过 `print()` 泄露 `ld` 指针，再按附件版本固定差值求出 `ld_base` 与 `libc_base`。之后把受控指针逐步递减到 `stdin->_IO_buf_base` 对应位置。

### 借 stdin underflow 获得大块写

题目 libc 与 Nullullullllu 使用相同思路：`stdin` 是无缓冲 FILE，`_IO_buf_base` 指向对象内部短缓冲区。用递减原语把该指针最低部分向下移动，退出确认中的 `getchar()` 进入 `_IO_new_file_underflow()` 时，就会把输入覆盖到 `stdin` 自身。

第一阶段输入重新设置：

```text
stdin->_IO_buf_base = &_IO_2_1_stdout_
stdin->_IO_buf_end  = stdout + fake_file_size
```

下一次读取会把攻击者数据直接写进 `stdout`。

### 伪造 stdout 触发 FSOP

构造适配附件 glibc 2.39 的 wide FILE：

- 在 `_flags` 附近放置 `";sh;"`；
- 把可调用槽设置为 `system`；
- 设置可写 `_lock` 与 `_wide_data`；
- vtable 选用合法的 `_IO_wfile_jumps` 附近地址；
- 其余读写指针满足刷新/输出分支条件。

将伪结构通过退出提示的输入写入 `stdout`。程序随后再次输出提示或错误信息时进入伪造的 wide-file 路径，最终调用 `system("sh")`，再读取 flag。

完整的变量堆风水、泄露步骤和重复次数见 [R3CTF Pwn 复现记录](https://xshhc.github.io/2024/07/29/2024_R3CTF_part1/)。本文保留了公开脚本背后的四个必要阶段：自赋值 UAF、缓存映射重叠、指针递减、stdin 到 stdout 的 FSOP 升级；具体循环次数仍应以附件二进制动态验证。

## 方法总结

这道题最容易误判的是把“引用计数变负”只当成普通 UAF。真正可利用之处在于旧缓存与新指针数组发生结构化重叠，使 `x=x` 变成稳定的算术写原语。自定义解释器题应同时还原语义对象、缓存容器和底层映射回收三层生命周期。最终的 FILE 利用依赖具体 libc，公开脚本中的 loader 差值、循环次数和 vtable 偏移都不是通用常量。
