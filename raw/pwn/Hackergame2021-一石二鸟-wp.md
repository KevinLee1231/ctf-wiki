# 一石二鸟

## 题目简述

程序由 Haskell 编译，但漏洞来自 `vector` 库的 unsafe 写入：用户可给出未经边界检查的数组索引和值。目标是“一次写入修改数组中两个位置”。关键不是理解完整 Haskell 运行时，而是把二进制当普通 ELF 调试，找出数组数据区以及运行时保存的数组基址指针，再用越界写覆盖该指针。

## 解题过程

### 定位数组写入 primitive

在 GDB 中输入很大的索引让程序崩溃，停在类似下面的写指令：

```asm
mov qword ptr [rbx + rcx*8], rax
```

其中 `rbx` 是数组元素区基址，`rcx` 是用户索引，`rax` 是用户提供的值。调试样本中数组基址约为：

```text
0x4200105758
```

在同一 Haskell heap 映射中搜索该指针值，可以找到运行时对象中保存的数组数据指针，样本位置约为：

```text
0x42001fcfd8
```

越界索引按 8 字节元素计算：

$$
index=\frac{0x42001fcfd8-0x4200105758}{8}
$$

本地环境得到约 `126734`，远程布局相差两个元素，实际索引为 `126732`。

### 一次写入影响后续多处

把该位置改成另一个合法、含有大量非零值的映射基址：

```text
index = 126732
value = 4194304    # 0x400000
```

交互形式可概括为：

```bash
./runme 126732 4194304
```

第一次 unsafe 写并非直接改目标数组的两个元素，而是改了数组对象的“数据区指针”。程序随后继续通过这个已被污染的指针读取或写入，于是一次指针覆盖改变了多个逻辑位置，满足题意并触发形如 `flag{S0_S1mp1e_r1ght_...}` 的结果。

偏移受编译环境、参数和 Haskell heap 布局影响；复现时应在与远程接近的环境中从崩溃点重新计算，而不是盲信固定地址。

## 方法总结

- 核心技巧：把无边界检查的数组写转化为运行时对象指针覆盖，再利用后续访问产生“一次写、多处生效”。
- 识别信号：高级语言的 unsafe 容器 API、用户可控索引以及稳定的自建 heap 映射。
- 复用要点：不必先逆完高级语言运行时；从实际写指令、基址和指针引用入手。ASLR 可能不改变相对偏移，但环境差异仍需现场校准。
