# lost-in-space

## 题目简述

服务随机映射 1000 个彼此分离的 RWX 页面，并用 2500 条无向边把它们组成图。每个节点页保存相邻页指针；编号 200 的目标节点有特殊标记。攻击代码从节点 0 的偏移处开始执行，正常程序映射和原栈会被移除，通用寄存器被清零。seccomp 允许的系统调用还要求指令指针位于目标节点页内。

因此不能直接执行 ORW shellcode，必须先在未知图中找到目标页，再把第二阶段代码搬过去执行。

## 解题过程

第一阶段先在节点 0 页内重定位自身，并划出一块可写区域作为临时栈。每个节点的邻接表以页指针和终止标记组织，因此可在纯汇编中实现深度优先搜索：

1. 读取当前页的目标标记，若为 1 则搜索完成。
2. 遍历邻接指针，把尚未访问的页面压入搜索栈。
3. 记录已访问页，防止无向边导致来回循环。
4. 当前节点无新邻居时弹栈回溯。

这里不能依赖固定地址或系统调用分配额外内存；访问集合、回溯路径和代码都放在已经拥有的 RWX 页面中。找到标记页后，将第二阶段 ORW 代码复制到该页并跳转。

seccomp 的关键不是彻底禁止 `open`、`sendfile` 等调用，而是检查调用发生时的指令指针。第二阶段现在位于目标页，便满足这一附加条件，可以打开 `flag.txt`，用 `sendfile` 把内容发送到标准输出，最后退出：

```text
maple{its_a_small_world_when_log_N_minus_gamma_over_log_k_small}
```

## 方法总结

本题把控制流位置本身变成了能力：同一条系统调用从普通节点执行会被拒绝，从目标节点执行则被允许。面对随机映射结构，先识别内存中的自描述数据格式，再实现不依赖 libc 的图遍历。seccomp-BPF 审计也不能只列允许的 syscall 编号，还要检查参数和 instruction pointer 条件。
