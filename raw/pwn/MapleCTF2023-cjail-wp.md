# cjail

## 题目简述

服务把输入写入 C 源文件并编译执行，但拒绝非空花括号、分号、预处理符号、百分号、问号、小于号、下划线以及字符串 `system`。题面刻意把注意力引向函数体过滤；实际上 C 的声明语法中也能放置会在函数入口求值的表达式。

## 解题过程

可直接提交：

```c
int main(char bluh[execvp("/bin/sh")]){}
```

函数体只有空的 `{}`，因此通过“花括号内不得有内容”的检查；源码也不含分号、下划线或 `system`。参数中的数组写法在函数形参处会调整为指针，但数组界表达式仍可能在进入函数时求值，于是程序启动后调用 `execvp("/bin/sh")`。

由于没有包含函数原型，编译器只给出隐式声明警告而继续生成调用。调用 `main(argc, argv)` 时，第二参数 `argv` 原本位于 `rsi`；这个单实参的隐式 `execvp` 调用只显式设置 `rdi` 为 `"/bin/sh"`，使 `rsi` 仍可作为参数向量使用。`execvp` 因而以 shell 替换当前进程。连接进入交互 shell 后读取 flag 文件即可得到：

```text
maple{h0w_c0u1d_1_b3_so_34s1ly_d3f34t3ddddddddddd_zb7VwbnWHsiqOIxzHa}
```

## 方法总结

C jail 不能只过滤语句和函数体。数组界、初始化器、属性、内联汇编、链接器选项乃至编译器扩展都可能在声明阶段产生代码。本题还依赖旧式隐式函数声明和调用约定中的残留寄存器，因此复现时应使用题目相同的编译器参数与架构；在现代严格模式下把警告升级为错误即可切断这条利用链的一环。
