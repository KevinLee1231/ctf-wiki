# artifact-11-revenge

## 题目简述

程序分配 10 个连续的 33 字节槽位，每次允许向指定槽位读入最多 32 个字符，然后修改首尾字符、把字符串复制到新分配的 40 字节缓冲区并追加文本。正常输入应当只影响当前槽，但首字符变成 NUL 后的长度下溢可以改写前一个槽的终止符，从而把多个槽串成超长 C 字符串，最终在 `correct()` 的栈缓冲区上形成溢出。

二进制关闭 PIE 和栈保护，并提供调用 `system("/bin/sh")` 的 `win()`，目标是把 `correct()` 的返回地址改为该函数。

## 解题过程

每个槽的布局是 32 字节输入加 1 字节 NUL。对槽 $i>0$ 输入一个空格后，`change_first_character()` 执行：

```c
input[0] -= 0x20;
```

空格 `0x20` 变为 `0x00`，于是 `strlen(input)` 返回 0。随后：

```c
size_t last_idx = strlen(input) - 1;
input[last_idx] -= 16;
```

无符号下溢使 `last_idx` 等价于 `-1`，恰好访问当前槽前一字节，也就是上一个 33 字节槽的终止 NUL。该字节从 `0x00` 变为 `0xf0`，两个槽之间不再有字符串终止符。

利用顺序为：先把槽 0 填满 32 字节；对槽 1 输入空格以破坏槽 0 的 NUL，再把槽 1 填满；重复该过程即可构造跨槽的长字符串。最后重新选择槽 0，并发送空行让 `%32[^\n]` 匹配失败，从而不写入新的 NUL，同时仍继续处理已有长串。

检查函数只比较前缀：

```c
!strncmp(input, "I love greycademy! <3", 21)
```

因此 payload 开头满足该前缀即可，后面仍可携带溢出数据。`correct()` 对 `strlen(input)` 个字节执行：

$$
flag_i=input_i\oplus input_{i+1}\oplus(rand_i\bmod256)\oplus KEY_i
$$

但局部数组 `flag` 只有 40 字节，长字符串会覆盖保存的局部变量、`rbp` 和返回地址。由于写入栈上的不是原输入而是上述 XOR 结果，必须反向求输入。程序固定执行 `srand(67)`，`rand()` 序列和全局 `KEY` 都可从同版本环境提取；对希望输出为 $o_i$ 的位置，选择当前 $input_i$ 后计算：

$$
input_{i+1}=o_i\oplus input_i\oplus rand_i\oplus KEY_i
$$

需要同时约束几个关键栈字段：保存的 `size` 维持为总长度 `0x70`，循环索引不被提前破坏，返回地址设为 `win()+5` 以保持调用 `system` 时的栈对齐。构造前还要逆补偿每次调用造成的首字节减 `0x20`、末字节减 `0x10`，以及作为槽连接符的固定 `0xf0`。

最终把反求出的连续输入按每 33 字节一个槽拆成最多 32 字节的片段，依次执行“下溢连接、填满槽位”，再用空行触发槽 0。`correct()` 的 XOR 循环把攻击者选定的栈字节写出并返回到 `win()`，获得 shell 后读取：

```text
grey{bu+_t34ch3r_th15_w45_n0+_c0v3r3d_1n_cl455_acdf9c0db3fa012e}
```

## 方法总结

利用链由三种边界错误组合而成：零长度字符串让 `strlen()-1` 下溢，连续槽的终止符被破坏后让“最多 32 字符”的局部限制失效，而 `correct()` 又用不受限的总长度写固定栈数组。最特殊之处是栈覆盖值经过相邻字节、固定随机流和 KEY 的 XOR 变换，需把 payload 构造写成约束反解，而不能直接拼接返回地址。
