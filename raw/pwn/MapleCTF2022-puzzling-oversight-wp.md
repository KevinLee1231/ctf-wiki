# puzzling-oversight

## 题目简述

程序实现一个 16 位数值的滑块谜题。棋盘状态 `gamestate` 与菜单函数指针表相邻，移动和数值增量使用 `uint16_t`，却没有正确限制索引与累计值。攻击者可以通过棋盘操作跨越数组边界，逐个修改菜单函数指针；相关 `.bss` 区域又具有可执行权限。

## 解题过程

目标是在 `gamestate` 中写入 14 字节的 32 位兼容 `execve("/sh",0,0)` shellcode，并把最靠近棋盘的菜单函数指针低 16 位改到该载荷。官方使用的紧凑字节序列为：

```python
shellcode = bytes.fromhex("682f736800545f9996b03b0f0500")
```

程序每次操作只能对一个 16 位单元增加数值，且棋盘移动方向使写入顺序与执行顺序相反。因此把“14 字节 shellcode + 目标地址低两字节 `0x4052`”整体反转，按两个字节一组处理。每轮读取当前棋盘值，计算模 $2^{16}$ 的增量：

```python
delta = (0x10000 - current + wanted) % 0x10000
```

连续八次操作后，前七个单元组成 shellcode，第八个单元把菜单项指向它。再次选择该菜单项即在 RWX `.bss` 执行载荷，获得 shell：

```text
maple{1s_th3_puzzl3_3v3n_s0lv4ble_4ctu4lly}
```

## 方法总结

业务上看似“只能加数”的接口，在无符号整数环中可以借助回绕写出任意 16 位值。审计这类内存布局题时，应把相邻全局对象画出来并确认段权限；若数据区可执行，覆盖函数指针和布置短 shellcode 可以合并为同一条写原语。端序与逆向写入顺序是本题最容易出错的部分。
