# The Weakest Link

## 题目简述

三题联动 OSINT 的最后一题要求找到 LISA 与 UIUC Chan 的秘密 Spotify 合作。两人的公开主页都不展示目标歌单，关键是理解 Spotify 的可见性边界：未列出的协作歌单仍可能通过好友动态暴露当前播放来源。

## 解题过程

从上一题定位的 `UIUC Chan` LinkedIn 页面打开 Contact Info，可获得其 Spotify 用户页。该资料只公开一个 Illinois 主题歌单，目标不在其中。LinkedIn 的 About 区域同时留下提示：她一直播放音乐，并声称秘密 Spotify 协作项目没有出现在个人资料上。

Spotify 歌单可见性需要区分三种情况：公开歌单显示在资料页；私密歌单只有所有者能访问；未列出歌单不展示在资料页，但持有链接仍可打开。目标又是协作歌单，Spotify 桌面端的 Friend Activity 会显示用户正在播放的协作歌单，即使该歌单未列在协作者资料页。

因此关注 `UIUC-Chan`，在桌面端好友动态等待其播放记录。记录显示歌曲来自 `songs for train lovers`；点击该来源即可进入由 LISA 和 UIUC-Chan 共同维护的歌单。歌单包含六首火车主题歌曲，描述栏给出：

```text
uiuctf{7rU1Y_50N65_0F_7H3_5UMM3r_432013}
```

官方五张截图只记录 LinkedIn 联系方式、文字提示、Spotify 资料、好友动态和歌单描述，均已在正文中完整转写，没有保留为图片。若平台状态已经变化，复现所需的关键证据仍是账号名、歌单名、协作者关系和描述文本，而非截图中的界面布局。

## 方法总结

- “未出现在个人资料”不等于完全私密；应分别检查搜索、分享链接、协作关系、好友动态等不同可见面。
- 这条链路的决定性 pivot 是 `LinkedIn 联系信息 -> Spotify 账号 -> Friend Activity -> 未列出协作歌单`，每一步都要核对身份连续性。
- 动态平台会随播放状态和隐私策略变化，WP 必须解释泄漏机制并记录关键文本，不能只要求读者点击一个当前可能失效的账号链接。
