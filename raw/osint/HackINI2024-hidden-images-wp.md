# HackINI2024 hidden images

## 题目简述

题面只给出与“仓库、开发者、隐藏镜像”有关的关键词，没有本地附件。需要把这些线索关联到公开容器镜像仓库，找到出题者发布的 Docker 镜像，并在容器内部识别真正的 flag 程序。

## 解题过程

根据官方赛后记录，比赛期间可以从关键词和出题者标识 `rx0f` 定位到 Docker Hub 上的镜像：

```text
rx0f/not-sus:latest
```

拉取并以交互方式进入镜像：

```bash
docker pull rx0f/not-sus:latest
docker run --rm -it rx0f/not-sus:latest sh
```

进入容器后检查根目录，可以发现 `/flag`。直接使用 `cat /flag` 只会把可执行文件的二进制内容打印到终端，并不是答案；应先确认文件类型和权限，再执行它：

```bash
file /flag
ls -l /flag
/flag
```

程序输出：

```text
shellmates{N0w_Y0u_Kn0W_4bOuT_d0cK3R_huB}
```

该镜像属于比赛时的外部公开资源，当前是否仍在线不影响题目的原始解题链；上述镜像名、容器路径和执行方式已完整记录在正文中。

## 方法总结

本题的核心是 OSINT 关联而非容器逃逸：从稀疏关键词推断平台，通过作者标识搜索公开制品，再在镜像中做最小化检查。容器内名为 `flag` 的对象不一定是文本文件，遇到乱码时应先用 `file` 判断类型，随后按文件语义读取或执行。对依赖外部平台的题目，WP 还应保留当时的精确镜像标签和验证命令，避免链接失效后丢失关键步骤。
