# suprimeRSA

## 题目简述

题目实现了标准的 RSA 加密，但素数并非均匀随机生成，而是具有固定的剩余类结构：

$$
p=kM+e^a\bmod M,
$$

其中 $e=65537$，$M$ 是若干连续小素数的乘积。该结构与 ROCA（Return of Coppersmith's Attack，CVE-2017-15361）所利用的弱 RSA 密钥形式一致。目标是利用公开模数中的结构恢复 $p,q$，再按正常 RSA 流程解密密文。

## 解题过程

### 1. 识别弱素数结构

公开题目代码中的核心逻辑可整理为：

```python
from Crypto.Util.number import bytes_to_long, getPrime, isPrime
from sympy import prime
import random

FLAG = b"hgame{...}"
e = 0x10001


def primorial(num):
    result = 1
    for i in range(1, num + 1):
        result *= prime(i)
    return result


M = primorial(random.choice([39, 71, 126]))


def gen_key():
    while True:
        k = getPrime(random.randint(20, 40))
        a = getPrime(random.randint(20, 60))
        p = k * M + pow(e, a, M)
        if isPrime(p):
            return p


p, q = gen_key(), gen_key()
n = p * q
enc = pow(bytes_to_long(FLAG), e, n)
```

题目给出的数据为：

```python

enc = 365164788284364079752299551355267634718233656769290285760796137651769990253028664857272749598268110892426683253579840758552222893644373690398408
e = 65537
```

普通 RSA 要求 $p,q$ 难以由 $n$ 反推出，但这里的候选素数在模 $M$ 下只能落在 $65537$ 的幂所形成的很小子群中。也就是说，公开模数泄露了两个素因子的剩余类结构，可以先在有限的指数候选中定位剩余，再把未知的小系数转化为 Coppersmith 小根问题。ROCA 的公开披露与检测资料可参见研究团队的 [CVE-2017-15361 说明](https://crocs-muni.github.io/roca/)。

### 2. 分解模数

原 PDF 给出了两种可行方式：使用完整的 Sage/LLL 实现，或直接调用适用于 512 位弱密钥的 NECA。后者由 Jannis Harder 实现，项目说明明确指出它针对受 ROCA 影响的 512 位 RSA 密钥；源码入口可从 [NECA 项目页](https://jix.one/neca/) 获取。

编译后把十进制模数作为唯一参数传入：

```bash
./neca 787190064146025392337631797277972559696758830083248285626115725258876808514690830730702705056550628756290183000265129340257928314614351263713241
```

PDF 中保存的分解结果为：

```text
p = 954455861490902893457047257515590051179337979243488068132318878264162627
q = 824752716083066619280674937934149242011126804999047155998788143116757683
```

先验证 $pq=n$，避免把工具输出或抄录错误带入后续解密。

### 3. 恢复私钥并解密

得到素因子后，计算

$$
\varphi(n)=(p-1)(q-1),\qquad
d\equiv e^{-1}\pmod{\varphi(n)},
$$

再求 $m\equiv enc^d\pmod n$：

```python
p = 954455861490902893457047257515590051179337979243488068132318878264162627
q = 824752716083066619280674937934149242011126804999047155998788143116757683
e = 65537
enc = 365164788284364079752299551355267634718233656769290285760796137651769990253028664857272749598268110892426683253579840758552222893644373690398408

n = p * q
phi = (p - 1) * (q - 1)
d = pow(e, -1, phi)
m = pow(enc, d, n)
plaintext = m.to_bytes((m.bit_length() + 7) // 8, "big")

assert n == 787190064146025392337631797277972559696758830083248285626115725258876808514690830730702705056550628756290183000265129340257928314614351263713241
print(plaintext.decode())
```

本地复算得到：

```text
hgame{ROCA_ROCK_and_ROll!}
```

该结果也与公开选手复现中针对同一组 $n$、`enc` 和因子的记录一致，相关完整题目数据可见[这篇复现](https://www.cnblogs.com/SevensNight/p/18766216)。

## 方法总结

本题的核心不是 RSA 参数规模，而是素数生成器泄露了强结构。看到 $p=kM+e^a\bmod M$、primorial 以及固定 $e=65537$ 的组合时，应优先想到 ROCA，而不是盲目尝试通用分解。攻击恢复 $p,q$ 后，剩余步骤就是标准 RSA 解密。防御上必须使用经过审计的密码库及均匀随机的素数生成方式，不能自行设计带固定模剩余结构的 RSA 密钥生成器。
