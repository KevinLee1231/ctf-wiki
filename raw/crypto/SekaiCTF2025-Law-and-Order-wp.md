# Law and Order

## 题目简述

题目实现了基于 secp256k1 的 FROST 风格门限签名，参数为 $n=9,t=7$。仓库 README 明确说明比赛发布包中的源码是误放版本，官方 `challenge/app/chall.py` 与 `solution` 才是正确题目；本文只依据修正后的源码分析。

正确版本同时存在两类缺陷：

- 用户提交的椭圆曲线点没有做 on-curve 校验；
- 点相等函数并非比较坐标，而是检查 $P+(-Q)$ 的 $x$ 坐标是否为零。

攻击者因此可以在曲线外构造小阶点，使承诺证明、验证份额和最终签名都在错误代数结构中通过。

## 解题过程

### 1. 利用错误点相等

正常应检查：

```python
P.x == Q.x and P.y == Q.y
```

题目却近似执行：

```python
(P + (-Q)).x == 0
```

只要把点的坐标选到加法公式的特殊分支，就能让两个不同点被判定相等。由于输入点也没有验证是否满足

$$
y^2=x^3+7,
$$

攻击者可以自由选择满足后续分母与小阶条件的曲线外坐标。

### 2. 伪造承诺知识证明

官方解法选取一个 $x=0$ 的曲线外点 $C_0=(0,y)$，使其在题目错误加法下具有 3 阶性质。再枚举 PoK 的随机量 $\mu$，令 $R=\mu G$，直到 Fiat–Shamir 挑战

$$
c=H(C_0,R,\ldots)
$$

满足 $c\equiv0\pmod3$。

这样验证式中的 $cC_0$ 在伪群中消失。其余承诺使用类似 $(1,0)$ 的退化点，并提交零响应，即可借助错误相等判断通过知识证明。

### 3. 伪造验证份额

服务端会从 7、8、9 号参与者中随机选择签名集合，并始终包含攻击者控制的 9 号。重复协议，直到随机集合只留下可控参与者。

对公钥验证份额，同样选择具有目标 $x$ 坐标的曲线外点，再解出能令错误比较式横坐标为零的 $y$。它不需要真的是某个秘密标量的 $G$ 倍，只需骗过实现中的等式。

### 4. 让 nonce 与挑战项在小阶子群中消失

FROST 签名份额通常为：

$$
z_i=d_i+\rho_i e_i+\lambda_i s_i c.
$$

官方解法构造非法 $D_i,E_i$，并反复选择它们，直到绑定因子 $\rho_i$ 和最终挑战 $c$ 在模 3 条件下让所有小阶点项消失。随后提交：

```text
z_i = 0
```

因为验证过程继续使用未校验点和错误相等函数，零份额通过；聚合出的最终签名也以同样方式通过验证。

## 方法总结

门限签名的安全证明默认所有参与元素都位于指定素数阶群中。实现必须在进入任何挑战哈希或线性组合前完成：

- 坐标范围检查；
- 曲线方程检查；
- 非无穷远点检查；
- 必要时的子群检查；
- 完整、规范的点相等比较。

只修复最终签名验证不够。承诺、PoK、验证份额和 nonce 都是攻击者可控输入，每个入口都必须拒绝曲线外点。本题没有官方成功会话中的 flag 文本，因此本文只给出经源码和官方解法闭合的伪造链，不虚构结果。
