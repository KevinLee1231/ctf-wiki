# 小 Z 的靓号钱包

## 题目简述

题目要求提交地址 `0xFFfFFfFFfFFf0aa0914DF1465327f33d591B30D8` 对应的 32 字节以太坊私钥。检查器只接受 `0x` 加 64 个小写十六进制字符，然后用私钥重新派生地址并比较。

该地址由 Profanity v1.12 生成。漏洞不在智能合约或链上状态，而在靓号生成器把 32 位随机种子扩展为私钥、再只修改固定高位的方式。决定性步骤是恢复 ECDSA 公钥并对 secp256k1 标量做中途相遇，因此归入密码学。

## 解题过程

### 从历史交易恢复完整公钥

以太坊地址只保存公钥的 Keccak-256 摘要后 20 字节，不能直接反推出公钥。不过目标地址曾在 Görli 测试网上签过交易，交易哈希为：

```text
0x1032e388e1bae7fbdacb8ab5206abd3cf8f602736107b832de51bb10dac5e410
```

对交易去掉签名字段，按其交易类型和链 ID 重新编码并求签名消息哈希，再把签名的 $(v,r,s)$ 交给 secp256k1 的 ECDSA 公钥恢复算法。历史测试网现在是否仍可访问不影响后续复现；官方题解已经给出恢复结果：

```text
0x04a362925f16b3f45e7048b376dfd54beedee8defc8ea0804823c489f3cf5862f13e89da68fa280f0812ef2d339d95352bd97c03ccf0a6304a1aa004b6557ddd4b
```

开头的 `04` 表示未压缩公钥，后面依次为 32 字节 $x$、$y$ 坐标。对坐标部分求 Keccak-256 并取末 20 字节，可再次验证目标地址。

### 还原 Profanity v1.12 的密钥空间

阅读生成器可知，它先用真正随机的 32 位整数初始化 `mt19937_64`，连续取四个 64 位输出，拼成初始私钥 $k_0$。因此看似 256 位的 $k_0$ 实际只有 $2^{32}$ 种。

为了寻找更漂亮的地址，程序只枚举私钥最高三个字节的变化。设变化量为 $x$，则最终私钥可以写成

$$
k=k_0+x\cdot 2^{232},\qquad -(2^{24}-1)\le x\le 2^{24}-1.
$$

相应公钥满足

$$
Q=kG=k_0G+x(2^{232}G),
$$

其中 $G$ 是 secp256k1 生成元。于是有

$$
k_0G=Q-x(2^{232}G).
$$

这正好把搜索拆成两个集合：一边枚举约 $2^{25}$ 个高位修正量，另一边枚举 $2^{32}$ 个随机种子。

### 构造中途相遇表

先对每个 $x$ 计算 $Q-x(2^{232}G)$，把点的 64 位指纹和 $x$ 存入哈希表。随后枚举所有 32 位种子，用与 Profanity 完全相同的 `mt19937_64` 和输出顺序生成 $k_0$，计算 $k_0G$ 并查表：

```text
for x in [-(2^24-1), 2^24-1]:
    table[fingerprint(Q - x * 2^232 * G)] = x

for seed in [0, 2^32):
    k0 = four_mt19937_64_outputs(seed)
    if fingerprint(k0 * G) in table:
        recover k from k0 and x
        verify the full public key and address
```

官方实现使用两套 secp256k1 库：常规库负责解析和点微调，优化过的固定基点乘法实现负责高速计算 $k_0G$，再用 OpenMP 并行枚举种子。哈希表只保存点的一段 64 位表示以节省内存，因此命中后必须用完整公钥或派生地址复核，不能把短指纹命中直接当成答案。

还要留意整数端序。官方代码把标量存为四个小端 64 位 limb，高三个字节落在最高 limb 的高 24 位，所以修正写成：

```cpp
seckey[3] -= (static_cast<int64_t>(x) << 40);
```

这里的符号与建表时 $Q-x(2^{232}G)$ 的定义配套；若自行改变建表方向，私钥合成处也必须同步改变符号。打印四个 limb 时按 `3, 2, 1, 0` 输出，补足为 64 个十六进制字符，最后交给题目自带的 `private_key_checker.py` 验证即可。

## 方法总结

本题利用了“输出空间很大”掩盖“种子空间很小”的错误安全假设。交易签名先把地址补全为椭圆曲线公钥；Profanity 的 32 位种子和固定三字节增量又把私钥写成两个独立小空间之和，从而可用中途相遇把不可行的联合暴力拆开。实现时最容易出错的是交易签名哈希的重建、`mt19937_64` 的精确输出顺序、标量端序与修正量符号，以及只用短指纹建表后忘记做完整候选验证。
