# GlacierCTF 2025 Hypercube

## 题目简述

题目提供一个 128 位密钥的 PRF Oracle。PRF 将四个经过裁剪的密码组件逐位异或：3 轮 Ascon、1 轮 AES、2 轮且去掉 feed-forward 的 SHA-256 压缩函数，以及 2 轮 SKINNY-128。客户端只能提交一次批量查询，最多包含 512 个 16 字节输入，随后必须猜出完整密钥。

关键不在逐个攻击某个组件，而在于“异或不会提高布尔函数的代数次数”。每个组件轮数都很少，因此组合后的输出位仍可用低维 cube 的高阶差分压缩成关于密钥位的仿射关系。

## 解题过程

### 1. 把 cube 求和看成高阶导数

固定一个基础输入 $x$，选取 $d$ 个活动位构成集合 $C$。对某个输出位 $f_k(x)$，计算

$$
D_C f_k(x)=\bigoplus_{u\in\{0,1\}^d}
f_k\left(x\oplus\sum_{i=1}^{d}u_i e_i\right).
$$

每做一次差分，相关变量的次数至少下降一次。源码中四个组件均只有很少的轮数；它们的异或结果也仍是低次数多项式。因此，合适的二维 cube 会让上式退化为密钥位的仿射函数：

$$
D_C f_k(x)=b\oplus a_0k_0\oplus a_1k_1\oplus\cdots\oplus a_{127}k_{127}.
$$

这里 $a_i$ 和常数项 $b$ 可以完全在本地离线求出。

### 2. 离线筛选有效且独立的方程

官方 solver 的离线阶段随机生成基础输入、两个活动位和输出位，并对随机密钥对做差分测试。若候选 cube 在大量随机密钥上都满足线性叠加关系，就保留其超多项式系数。

对零密钥求值可得到 $b$；逐一翻转第 $i$ 个密钥位，再与 $b$ 异或即可得到 $a_i$。每发现一条候选方程，就在 $GF(2)$ 上检查其是否提高当前矩阵的秩，只保存线性独立的行。这个过程持续到矩阵秩足以约束绝大多数密钥位。

### 3. 用一次在线查询收集右端项

二维 cube 只需要 $2^2=4$ 个顶点。将所有已选 cube 的顶点去重后放进唯一一次批量请求；总输入数必须不超过题目的 512 块限制。收到 Oracle 输出后，对每个 cube 的四个相应输出位求异或，再减去离线算出的常数项 $b$，得到

$$
A k = y \pmod 2.
$$

随后用高斯消元求出一个特解及零空间基。若矩阵没有达到满秩，就枚举规模很小的 kernel，使用任意一组已知输入/输出重新计算完整 PRF，排除错误候选。找到唯一匹配的 128 位密钥后提交即可。

仓库中的 Rust solver 已将离线 cube 搜索和在线求解拆开；在线阶段可按其参数运行：

```bash
cargo run --release -- <host> <port>
```

源码内置实例对应的 flag 为：

```text
gctf{x0ring_d03s_n0+_incr34s3_4lg3br4ic_d3gr33}
```

## 方法总结

本题考查 cube attack 与低轮密码的代数次数。异或多个“看起来不同”的组件不能掩盖它们共同的低次数缺陷；输出位的高阶差分仍会变成密钥位的线性方程。实战中还要同时处理三个工程约束：离线验证候选 cube 的线性、只保留增秩方程，以及把所有在线顶点压缩进一次 512 块查询。最后必须用真实 PRF 输入输出验证 kernel 枚举结果，不能把任意线性方程解直接当作密钥。
