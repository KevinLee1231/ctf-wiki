# Bro-key-n

## 题目简述

题目给出一份被下划线遮去大量字符的 PKCS#1 RSA 私钥。原始私钥由两个 2048 位素数组成，因此模数约为 4096 位；遮盖并非随机删除整个文件，而是保留了 DER 结构以及若干关键字段：完整的 $N$、完整的 $e=65537$、$d$ 的高位、$q$ 的低位和 $d_p=d\bmod(p-1)$ 的大部分高位。

服务端只接受与该公钥匹配的 SSH 私钥，并通过 `authorized_keys` 的强制命令输出消息。决定性障碍是 RSA 部分私钥暴露：只要利用泄露的 $d_p$ 高位分解 $N$，其余私钥字段都可重新计算。

## 解题过程

### 从 PEM 中恢复已知字段

PEM 正文是 DER 数据的 Base64 表示。先把没有被遮盖的 Base64 位转换为带未知位标记的十六进制，再按 PKCS#1 `RSAPrivateKey` 的 INTEGER 顺序解析：

```text
version, n, e, d, p, q, dp, dq, qInv
```

DER 的类型和长度字段仍然存在，所以即使中间内容被遮盖，也能确定每段未知数据属于哪个整数。官方整理结果表明：

- $N$ 和 $e$ 完整可得；
- $d_p$ 共约 512 个十六进制位，其中高 383 位已知；
- 其余泄露可以辅助确认布局，但恢复因子时只需 $N,e$ 和 $d_p$ 的高位。

### 利用部分 $d_p$ 恢复 $p$

令

$$
d_p=d\bmod(p-1).
$$

存在 $1\le k_p<e$ 使得

$$
e d_p-1=k_p(p-1).
$$

把 $d_p$ 写成“已知高位加未知低位” $d_p=a+x$，其中 $x$ 很小。整理上式可得

$$
a+x+e^{-1}(k_p-1)\equiv 0\pmod p.
$$

由于 $p\mid N$，问题转化为：寻找小整数根 $x$，使 $A+x$ 与 $N$ 有非平凡公因子，其中

$$
A=a+e^{-1}(k_p-1)\pmod N.
$$

官方 Sage 脚本按照部分私钥暴露攻击构造 20 维格，使用 $X=16^{150}$ 作为未知低位的上界，对候选 $k_p$ 做枚举并执行 LLL。每条短向量还原为关于 $x$ 的多项式；一旦得到整数根 $r$，就检查：

```python
g = gcd(A + r, N)
if 1 < g < N:
    p = g
    q = N // p
```

这一过程对应官方脚本注释所指的[部分 RSA 私钥暴露攻击模型](https://eprint.iacr.org/2020/1506)：正文真正需要的条件不是链接本身，而是“已知 $d_p$ 的足够多高位、未知低位有明确上界，并且 $k_p<e$ 可枚举”。

### 重建私钥并验证

得到 $p,q$ 后即可重算

$$
d=e^{-1}\bmod (p-1)(q-1),
$$

并生成完整私钥：

```python
from Crypto.PublicKey import RSA

q = N // p
phi = (p - 1) * (q - 1)
d = pow(e, -1, phi)
key = RSA.construct((N, e, d, p, q))
open("recovered.pem", "wb").write(key.export_key())
```

使用恢复的私钥登录后，服务端强制命令输出验证消息。仓库中的密钥生成脚本还特意让 Base64 私钥正文包含 `/uiuctf/hidden/in/plain/sight/` 这一可读片段；服务端给出的最终 flag 为：

```text
uiuctf{hidden_in_plain_sight}
```

## 方法总结

- 核心技巧：解析残缺 PKCS#1 DER 布局，并用 $d_p$ 高位泄露实施格攻击，从 $N$ 中恢复素因子。
- 识别信号：RSA 私钥虽然大量被遮盖，但长度字段、$N/e$ 和 CRT 参数的连续高位仍在；这类结构化泄露不能按“缺失字符太多”直接判定不可恢复。
- 复用要点：先精确标注 DER 字段边界，再决定使用哪一组部分密钥关系；格攻击得到候选根后必须以 `gcd(A+r, N)` 和 $pq=N$ 验证，最后重新计算全部 CRT 参数，不应尝试手工补齐 PEM 文本。
