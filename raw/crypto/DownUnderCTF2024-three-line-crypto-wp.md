# three line crypto

## 题目简述

加密程序只有三条逻辑语句：它生成 16 字节随机数组 `q`，并令前一明文字节初值 $y=0$；每读入当前明文字节 $x$ 就输出 `q[y % 16] ^ x`，再令 $y=x$。因此密文满足：

$$
c_i=p_i\oplus q_{p_{i-1}\bmod16},\qquad p_{-1}=0.
$$

索引由未知的前一明文字节决定，不能把它当作普通周期 XOR；但 key 只有 16 个独立字节，且附件明确说明原文是英语长文，所以可用语言统计恢复这张 16 项查表。

## 解题过程

对一个候选 key，解密递推与加密式完全对应：

```python
pt, y = [], 0
for x in ct:
    d = key[y % 16] ^ x
    pt.append(d)
    y = d
```

官方 `solution.py` 从随机 16 字节 key 出发，把解出的文本按二元组（digram）计数。它从英语语料 `www.txt` 建立二元组频率表，并以 Bhattacharyya coefficient 衡量候选明文与英语分布的接近程度：

$$
\operatorname{score}(P)=\sum_g\sqrt{f_{\rm corpus}(g)f_P(g)}.
$$

每轮枚举两个 key 位置及其新字节值；只要 score 提升就接受该两点变异，然后继续爬山。由于上一字符会决定下一步访问的 key 位置，单点修改常难以脱离局部状态，官方脚本特意使用 2-mutation。收敛后输出最终递推得到的全文，其中包含 flag。

题目发布的唯一密文是二进制数据，应以 `open(..., 'rb')` 读取；用文本模式会因解码替换或换行转换破坏字节值。官方 solver 注释说明这是一种启发式方法，典型运行时间为 10--20 分钟，本文没有声称本地复跑了该随机爬山过程。仓库配置记录的验证值为：

```text
DUCTF{when_in_doubt_xort_it_out}
```

## 方法总结

短 key 的自定义反馈 XOR 不会自动带来密码强度。这里状态转移直接暴露为自然语言统计可优化的确定性递推，密钥空间还能分解为 16 个局部参数。已知格式、长文本冗余和可计算语言分数足以弥补没有已知明文的缺口。涉及文本的流加密应使用标准认证加密并以 bytes 处理数据，而不是自制索引规则。
