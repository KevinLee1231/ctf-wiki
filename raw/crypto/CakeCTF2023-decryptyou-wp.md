# decryptyou

## 题目简述

`crypto/decryptyou/challenge/main.c`（与 `distfiles/main.c` 对应）实现了一套 RSA-CRT 加解密服务，关键点是：

1. 服务生成 RSA 私钥时固定 `e = 65537`，并在 CRT 中保存 `dp`、`dq`、`u=q^{-1}\bmod p`。
2. 服务器随机取明文 $x$，使用指数 $1333$ 加密后对外打印：
   $$ c = x^{1333} \bmod n $$
3. 每次接收客户端提交的十进制 `c` 后用 CRT 解密并比较解密结果是否等于该随机明文。

除此之外，解密输入读取实现是：
```c
char buf[0x200];
scanf("%s", buf);
```
无长度限制的字符串扫描会越过 `buf`，抵达调用者栈帧中 RSA 结构的 GMP 元数据。官方 payload 保留 `u` 的 limb 指针，却把其尺寸字段改成较小值，使 CRT 重组时使用被截断的 $u$。这道题确实同时包含内存覆盖与密码学，但取得 flag 的主线是把故障 CRT 变成因子边界 oracle，再完成 RSA 反演，因此归入 `crypto`，并在正文保留其 Pwn 触发条件。

## 解题过程

`solution/solve.py` 提供了完整可复现主链。关键思路可抽象为三步：

1. 拿到 $n$ 与加密样例 $c = x^{1333}\bmod n$；
2. 发送精心构造的长输入污染解密状态，再用二分法定位可行区间还原 $n$ 的一个因子；
3. 通过指数不一致性反演得到目标明文并构造校验密文。

脚本里用到的污染输入为：
```python
payload = b"0\0"
payload += b"A"*(0x250 - len(payload))
payload += p32(4) + p32(4)
```
输入以 `b"0\0"` 开头有两个作用：`scanf("%s")` 仍会按非空白 token 继续写入后面的溢出字节，而紧接着把缓冲区当 C 字符串解析的 `mpz_set_str` 会在内嵌 NUL 处停止，只把当前密文读成 0。末尾两个 32 位整数则改写 GMP 整数的尺寸元数据。这一步不是为了直接覆盖 flag，而是把 CRT 系数 $u=q^{-1}\bmod p$ 变成错误值。

随后对每个候选中点 $t$ 发送：
$$ c' = t^{65537}\bmod n. $$
当 $0\le t<\min(p,q)$ 时，两个 CRT 分支都恢复同一个整数：$m_p=m_q=t$，所以即使 $u$ 已损坏，差值项仍为零，服务仍返回 $m'=t$。当 $t$ 到达较小素因子时，两侧剩余类不再相同，错误 $u$ 使重组结果偏离 $t$。因此 `m_ == t` 是一个关于较小因子边界的单调判定；二分区间中的首个失败值就是 $p$、$q$ 中较小者，另一因子由整除 $n$ 得到。[出题人的赛后说明](https://furutsuki.hatenablog.com/entry/2023/11/16/015259)给出了同一判定，并补充了另一条可选路线：比较正确候选明文与故障解密结果，对差值和 $n$ 取最大公约数也可能直接得到一个因子。

拿到两个素因子后：
$$ x = c^{d_{1333}} \bmod n,\quad d_{1333}=1333^{-1}\bmod((p-1)(q-1)) $$
这一步恢复了服务端的随机明文 $x$。但服务端解密仍按 `e=65537` 所在 CRT 系列计算，因此要拿到 `m == x`，要提交：
$$ c_{forge}=x^{65537}\bmod n $$

```python
ng, ok = 0, n
while abs(ok - ng) > 1:
    q_ = (ng + ok) // 2
    c = pow(q_, 65537, n)
    sock.sendlineafter("c = ", str(c))
    m_ = int(sock.recvlineafter("m = "))
    if m_ == q_:
        ng = q_
    else:
        ok = q_

factor = ok  # 首个失败边界；不要依赖循环最后一次 midpoint 恰好是哪一侧
assert n % factor == 0
p, q = n // factor, factor
e = 1333
d = pow(e, -1, (p-1)*(q-1))
m = pow(flag_c, d, n)
ans = pow(m, 65537, n)
sock.sendlineafter("c = ", str(ans))
sock.interactive()
```

服务端用原始随机数 $x$ 校验解密结果。官方脚本最后提交 $x^{65537}\bmod n$；但此时 $u$ 仍然损坏，只有 $x$ 落在同一“两个剩余类相等”的区间时才会直接返回 $x$。因此该脚本具有实例概率性：恢复 $x,p,q$ 后应先检查 $x<\min(p,q)$，不满足就重连并重做，而不能把一次无 flag 响应误判为公式错误。另一个[公开参赛者解法](https://chocorusk.hatenablog.com/entry/2023/11/14/051905)把 $u$ 置零，并明确记录了相同的重试边界。成功实例返回：

```text
CakeCTF{h4lf_crypt0_h4lf_pWn_l1k3_c4k3!?}
```

这与题目给出的 `decryptyou` 题名一致：既有“解密器”的利用，也有“pwn 风格”输入污染特征，只是验证路径集中在 RSA CRT 上。

## 方法总结

- 核心技巧：结合“指数不一致”的 RSA（加密端 1333、解密端 65537）与可控输入污染，先通过偏差 oracle 做分解，再把恢复明文反向映射为可被解密端接受的密文。
- 识别信号：看到 CRT 解密实现、可重复查询的明文输出，以及无长度约束的输入读取时，应检查能否只破坏某个 CRT 系数并获得故障解密 oracle。
- 复用要点：内嵌 NUL 可以让“输入函数继续写入”和“后续 C 字符串解析提前结束”同时成立。因子搜索依赖的是 $t<\min(p,q)$ 时两个 CRT 分支相等这一单调边界；恢复因子后还要分别处理原样例的指数 1333 与解密器指数 65537。
