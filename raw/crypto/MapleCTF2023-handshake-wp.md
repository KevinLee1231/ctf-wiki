# handshake

## 题目简述

题目模拟了一套类似 MSCHAPv2 的握手认证。服务端先计算口令的 MD5，然后从摘要中截取三段 3 字节数据，分别扩展成 DES 密钥，对同一个 8 字节挑战做加密并拼接结果。题目给出一次管理员握手流量，但禁止原样重放该挑战，要求伪造一次新的管理员响应。

表面上需要恢复完整口令，实际上三个 DES 分支彼此独立，每个分支真正未知的熵只有 24 位。

## 解题过程

将抓到的响应按实现拆成三个 16 字节块。对第 $i$ 块，只需枚举 $0$ 到 $2^{24}-1$，把候选值编码成 3 字节，再使用题目中的位扩展函数生成带奇偶校验位的 8 字节 DES 密钥。若候选密钥对已知挑战的加密结果等于对应响应块，该段便恢复成功。

官方脚本得到的三个扩展后密钥为：

```python
keys = [
    b"\xb5\xecNNNN\xfb\xa2",
    b"\xaa\xd8LLLL\xe6\x94",
    b"\xb8\xc6))))\x91\xef",
]
```

这里没有必要继续逆推出 MD5 原像。服务端验证新握手时最终使用的就是这三把响应密钥，因此选择一个未出现过的新挑战，例如：

```python
challenge = b"a" * 16
response = b"".join(make_response(key, challenge) for key in keys)
```

`make_response` 应完全复用题目服务端的分块和 DES 调用方式，避免自行猜测填充或端序。将用户名 `admin`、新挑战及拼接后的响应提交，既绕过“旧挑战不可重用”的检查，又能通过管理员认证，得到：

```text
maple{MSCHAPv2_isnt_so_secure_after_all}
```

## 方法总结

协议的安全强度取决于最窄的秘密分片，而不是摘要或分组密码名称看起来有多强。把口令摘要切成互不关联的 24 位 DES 密钥，使一次 $2^{72}$ 的问题退化成三次 $2^{24}$ 的独立搜索。拿到派生认证密钥后，新鲜挑战只能阻止重放，不能阻止攻击者计算合法的新响应。
