# Intercepted Transmissions

## 题目简述

附件 `encoding` 是一串二进制，但并非按 ASCII 的 8 位分组。源码给出了 CCIR476 风格的 7 位码表、字母/数字符号两套状态以及状态切换码。核心是还原可逆表示层编码，归入 Crypto。

## 解题过程

先按 7 位切分比特串。源码明确给出了几个控制码：`1011010` 为 LTRS（字母表），`0110110` 为 FIGS（数字和符号表），`1011100` 为空格。解码初始状态为 LTRS；每读到状态码只切换模式、不输出字符。

随后以当前状态查询对应码表。例如在 FIGS 状态中，`1101001` 是 `#`，`1110100` 是 `5`，`0101110` 是 `1`；切回 LTRS 后同一组比特才按字母表解释。题目给出的开头 `##` 也可用来确认分组方向和 FIGS 状态没有读反。

将整串依次转换，得到：

```
##TH3 QU0KK4'S AR3 H3LD 1N F4C1LITY #11911!
```

题面要求再包上一层 flag 格式，答案为：

```
DUCTF{##TH3 QU0KK4'S AR3 H3LD 1N F4C1LITY #11911!}
```

## 方法总结

遇到短位串时，先从长度和重复结构判断分组宽度，不能默认 ASCII。具有两个字符表的电传编码还必须维护状态机：控制码改变后续字元的解释，而不是普通字符。已知明文前缀是很好的校验点；若前缀无法还原，应优先检查位宽、起始状态和字母/符号表切换。
