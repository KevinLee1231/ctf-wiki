# Spad3kapig

## 题目简述

服务为每条连接随机生成一个固定的 `team_seed`，并给出 10 秒时间。每轮重新以随机状态建立自定义 LCG，先输出一次 `seed`，再用后续 51 个输出执行 Fisher–Yates 洗牌。提交错误牌序后，服务会公开正确牌序；提交完全正确的下一副牌即可得到 flag。

LCG 参数为：

$$
a=\texttt{team\_seed}\oplus\texttt{0x77777777},\quad
c=2025,\quad
m=2^{31}-1.
$$

关键问题是 C++ 中 `a`、`state` 都是 `uint32_t`，所以乘法先模 $2^{32}$ 溢出，再模 $m$。每轮泄露的一个 31 位状态和洗牌末牌的低模信息，足以用 HNP 格恢复同一连接中的 $a$。

## 解题过程

### 从牌序提取一次 RNG 低模输出

每轮代码先执行：

```cpp
given_seed = rng.next();
```

这个十六进制值记为 $s_i$。随后洗牌的第一次迭代是：

```cpp
i = 51;
j = rng.next() % 52;
swap(cards[51], cards[j]);
```

后续迭代的 `i` 都不超过 50，不会再触碰位置 51。因此最终牌序最后一张牌的原始编号恰好是：

$$
r_i=\operatorname{next}(s_i)\bmod52.
$$

连续提交 12 次明显错误的牌序，例如重复 52 张 `sA`，每次读取服务公开的正确牌序，便得到 12 组 $(s_i,r_i)$。这里每轮的初始随机状态不同，但乘数 $a$ 在同一连接中不变。

### 建立含三层模约束的 HNP

真实更新顺序为：

$$
w_i=(as_i+c)\bmod2^{32},\qquad
z_i=w_i\bmod m,\qquad
r_i=z_i\bmod52.
$$

所以存在整数 $k_i$ 和极小的 $t_i$，使：

$$
as_i+c\equiv r_i+52k_i+t_i m\pmod{2^{32}}.
$$

对题目正常分布，官方求解器枚举 $t_i\in\{0,1\}$。由于：

$$
\gcd(52,2^{32})=4,
$$

约掉公共因子后可按模 13 处理未知的 $k_i$。对每个 $t_i$ 组合，先计算：

```python
target_i = (r_i + t_i * m - c) % 2**32
```

再构造一个 $14\times14$ 的嵌入格：前 12 个对角元取 $13\cdot2^{32}$，倒数第二行放入经 $13^{-1}\bmod2^{32}$ 归一化的 $s_i$，最后一行放入同样归一化的 `target_i`，并用最后两列标记乘数与目标向量。LLL 的短向量同时给出小的 $k_i$ 和公共乘数候选 $a$。

求解后还需检查：

```python
team_seed = a ^ 0x77777777
1 <= team_seed <= 2**31
```

并用所有 12 组样本重新执行“模 $2^{32}$、模 $m$、模 52”的完整更新式验证。枚举错误时这一检查会立即失败。

### 预测下一副完整牌

服务下一轮仍使用相同的 $a$，会再次打印一个新状态 $s$。以：

```python
state = s
a = recovered_a
c = 2025
m = 2147483647
```

实现与 C++ 完全一致的更新：

```python
state = ((a * state + c) % 2**32) % m
```

然后按 `i = 51, 50, ..., 1` 计算 `j = next() % (i + 1)` 并交换。最后把编号映射成源码规定的花色顺序 `s, h, c, d` 和点数顺序 `A23456789XJQK`，在 10 秒超时前提交 52 张牌。

## 方法总结

本题只需观察洗牌后的最后一张牌：它不会被后续交换覆盖，因而直接泄露第二次 LCG 输出模 52。多轮的新随机状态并没有保护固定乘数，反而提供了多组共享 $a$ 的 Hidden Number Problem 样本。

最容易写错的是整数语义。正确模型必须先做 `uint32_t` 的模 $2^{32}$ 溢出，再模 $2^{31}-1$，最后模 52；把它误写成普通的模 $m$ LCG 会恢复失败。作者的 [Spad3kapig 仓库](https://github.com/D33BaT0/my-ctf-challenges/tree/main/r3ctf%202025-crypto/Spad3kapig) 包含完整 LLL 嵌入和交互脚本；仓库也说明比赛中存在基于优化爆破/生日方法的非预期解，但正文保留的是预期密码分析路线。
