# coinflip

## 题目简述

服务允许玩家自行提供任意长度的整数作为 Python `random.Random` 的种子。每轮从梅森旋转算法生成的随机位中取一位决定硬币结果，猜中便获利；需要在最多两千万轮内把资金提升到七百万。直接预测未知随机状态不可行，但这里的种子完全由攻击者控制，而且 CPython 会把超大整数拆成许多 32 位字后送入 `init_by_array`。

题目的突破口是反向构造一个很长的种子，使初始化后的 MT19937 状态几乎全为零，从而产生足够长的可预测低位序列。

## 解题过程

CPython 的大整数种子不是先哈希到固定长度，而是按 32 位小端字数组参与两轮可逆的状态混合。官方 `genseed.py` 用 Z3 对这段 `init_by_array` 建模：把 624 个种子字作为 32 位位向量，逐条复现异或、移位、乘法和加法，并约束初始化后的 `mt[1]` 到 `mt[623]` 为 0。`mt[0]` 会按实现固定为 `0x80000000`，无需也无法消掉。

求解后把 624 个 32 位字按小端拼成一个超大整数，作为服务端种子。此时生成器的状态极度退化，后续输出的低位在很长一段范围内高度可预测。题目消费随机数的方式是把一个 MT 输出从最低位开始逐位取出，而值 0 对应获胜，因此按官方生成的输入连续提交预期结果即可积累资金。

实际利用不需要在线运行 SMT。先离线执行一次约束求解，把得到的超大十进制种子和下注序列保存；连接服务后提交该种子，按照题目每轮的位消费顺序下注，达到目标余额后选择领取奖励，得到：

```text
maple{1nv3rt_m3rs3nne_tw1ster,bet,pr0f1t!!1!_0aa3a8efe77eaade}
```

## 方法总结

“允许用户设置随机种子”不仅意味着结果可复现，还可能允许用户挑选生成器的病态内部状态。CPython 对大整数种子的完整映射必须按源码审计，不能想当然地认为种子会先经过安全哈希。本题也说明，求解器适合用来一次性生成攻击材料；在线阶段应尽量只做确定性的协议交互，减少超时和状态错位风险。
