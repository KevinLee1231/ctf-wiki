# TSGCTF2021 B??e64 WP

## 题目简述

服务端随机生成一个由小写字母和数字组成的 32 字符秘密，将其连续 Base64 编码 8 次，得到长度 344 的字符串。选手需要先提交一个同长度的掩码，掩码只能包含 `*` 和 `?`，且 `?` 不超过 124 个；服务端仅在 `?` 对应位置公开编码字符。随后必须连续还原 8 个随机秘密才能获得 flag。

关键在于多层 Base64 并不会让 344 个输出位置拥有相同的信息量。Base64 把 3 字节映射成 4 字符，前缀具有局部确定性；连续编码 8 次后，固定一小段原文会固定很长一段输出，而部分输出位置的信息熵很低。需要一方面写出能从稀疏已知字符回溯原文的解码器，另一方面挑选最有区分度的 124 个位置。

## 解题过程

定义八重编码函数：

```python
import base64

def enc(text):
    for _ in range(8):
        text = base64.b64encode(text.encode()).decode()
    return text
```

若原文前 $n$ 个字符已经固定，那么每经过一层 Base64，确定前缀长度近似乘以 $4/3$。精确地逐层取整后，可计算第 $i$ 个原文字符确定时能够安全比较的编码前缀长度：

```python
determined = []
for i in range(32):
    length = i + 1
    for _ in range(8):
        length = length * 8 // 6
    determined.append(length)
determined[-1] = 344
```

从原文首字符开始枚举 `a-z0-9`。对当前候选执行八重 Base64，只比较已经确定的前缀以及掩码公开的位置；若冲突就尝试下一个字符，字符集耗尽则回退上一位：

```python
def compatible(encoded, masked):
    return all(m == "*" or e == m for e, m in zip(encoded, masked))

cur = 0
choice = [0] * 32
while cur < 32:
    candidate = "".join(CHARSET[i] for i in choice)
    prefix = determined[cur]
    if compatible(enc(candidate)[:prefix], masked[:prefix]):
        cur += 1
    else:
        choice[cur] += 1
        rewind = cur
        while choice[rewind] == len(CHARSET):
            choice[rewind] = 0
            rewind -= 1
            choice[rewind] += 1
```

为了判断公开位置是否足够，可以分别以正序、逆序字符集求出字典序最小和最大的可行原文；两者相同就说明在当前掩码下解唯一。

掩码选择采用离线启发式：随机生成大量 32 字符原文，统计 344 个编码位置的字符熵，优先保留高熵位置；再从低熵位置开始移除，只要随机测试集中的解仍保持唯一就继续。官方求解器使用的掩码如下，其中实际只有 122 个 `?`，低于服务端上限 124：

该掩码在官方测试中能唯一恢复约 95% 的随机秘密。客户端连接失败时重新连接即可；在若干次连接内完成连续 8 轮，服务端返回：

```text
TSGCTF{Ba5e6A_has_a_f1xp0int}
```

多层编码前部逐渐趋向固定模式，例如以 `Vm0wd2Qy` 开头的串继续 Base64 后仍产生相似前缀，因此那些位置熵低、区分能力弱，掩码刻意不公开它们。

## 方法总结

本题不是普通“看到 Base64 就解码”，而是利用编码的冗余和前缀传播性做部分信息恢复。求解器用前缀长度界限剪枝，把 $36^{32}$ 的穷举化为逐字符回溯；掩码则通过位置熵和唯一性测试筛选。面对重复编码或确定性变换，应检查各输出位置的信息熵，而不是只看总长度：增长出来的字符很多，但其中相当一部分由格式和旧前缀决定，并没有带来等量的新信息。
