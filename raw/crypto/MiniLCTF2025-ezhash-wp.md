# ezhash？！

## 题目简述

题目实现了一个 280-bit 状态的自定义滚动 hash。对 32 字节 ASCII 字符串 `value`，先令 $x=(\operatorname{ord}(value_0)\ll7)\bmod2^{280}$，随后对包括首字符在内的每个字符执行

$$
x\leftarrow (kx\bmod2^{280})\mathbin{\mathtt{xor}}\operatorname{ord}(c),
$$

最后再与长度异或。隐藏的 $k$ 是 128-bit 整数；输出给出 64 组长度为 32 的 `testvalue/testhash`，以及 flag 的 hash。目标是先恢复 $k$，再逆转 flag 的逐字节状态。

## 解题过程

### 用已知测试对恢复 key

XOR 不能简单当作整数加法，但对固定测试字符串可以直接按位精确建模。以 280-bit `BitVec` 表示状态和 key，约束 $0\le k<2^{128}$，将一组 `testvalue` 的每轮乘法、截断和 XOR 原样写入，末状态等于对应的 `testhash`。Z3 给出的候选 key 必须代回剩余 63 组测试；全部 hash 一致才接受。

这里不能只把每轮 XOR 改成加法来恢复 key：该近似仅适用于下一阶段的“小修正量”格构造，直接对已知测试对这么做会丢失精确位语义。

### 将目标 hash 化为小修正量格

令目标末状态为

$$
t=\texttt{shash}\mathbin{\mathtt{xor}}32.
$$

每个字符只占低 7 bit。对某一轮，`(k*x) xor char` 与整数 $k*x$ 的差只改变低 7 位，记为有界修正量 $s_i$。逐轮展开并模 $2^{280}$ 合并，可得到关于 32 个小量的线性同余：

$$
(2^7k^{32}+k^{31})s_0+k^{30}s_1+\cdots+ks_{30}+s_{31}+t\equiv0\pmod{2^{280}}.
$$

用这 32 个系数构造 34 维嵌入格：前 32 个对角元为 $1$，另设一个目标坐标和一个模数坐标；将系数和 $-t$ 乘以较大比例（[同届公开复现](https://mi1n9.github.io/2025/05/11/2025miniLCTF/) 使用 $2^{500}$），模数坐标放入 $2^{280}\cdot2^{500}$。LLL 后，选择目标辅助坐标为 $1$、模数辅助坐标为 $0$ 的短向量，即得到修正量候选。

### 逆向取回字符并验证

设 $M=2^{280}$、$k^{-1}=k^{-1}\bmod M$。从末轮向前，对每个修正量 $s$ 执行：

```python
product = (state - s) % M
ch = state ^ product
assert 0 <= ch < 128
state = product * inverse_key % M
```

逆序收集 `ch` 即为 flag。最后重新运行题目 hash，要求结果严格等于给定 `shash`；同时检查长度为 32 且字符格式合理。这个回代检查能排除 LLL 返回的无关短向量。

## 方法总结

- 核心技巧：先用精确 bit-vector 语义恢复乘法 key，再利用字符仅影响低 7 bit 的事实将 flag 恢复转为小误差线性同余。
- 识别信号：窄字符集、固定宽度截断乘法和多组已知输入/输出是“Z3 求参数 + 格恢复未知文本”的组合信号。
- 复用要点：key 恢复阶段必须保留 XOR；格阶段的修正量只描述低位差。结果必须同时通过逐字节范围与完整 hash 回代验证。
