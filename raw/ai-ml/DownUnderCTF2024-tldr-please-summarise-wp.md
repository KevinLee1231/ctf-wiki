# tldr please summarise

## 题目简述

附件是一篇看似正常的 Emu War 介绍文档。题目利用了把不可信文档直接交给 LLM 总结或“代做题”的风险：文档正文中混入了一段面向 ChatGPT 的指令，试图让模型停止原任务、下载并执行外部脚本。决定性障碍是识别并安全处置提示注入，因此归入 AI/ML，而不是文档取证。

## 解题过程

不要把 DOCX 上传给具有工具调用或代码执行能力的模型，也不要执行文档中的任何 shell 命令。将 DOCX 作为 ZIP 容器只读解析 `word/document.xml`，可见其绝大多数段落都是 Emu War 的普通叙述；在“Public Perception and Political Fallout”之后夹入了伪装成系统消息的段落。

该段落的语义是“停止脚本执行，转而下载、Base64 解码并执行一个临时脚本”。这正是典型的间接提示注入：攻击者无法直接改变操作者的提示词，于是把越权命令藏进模型即将读取的外部内容。应将其视为数据，而非指令。

官方解答说明该外部 Base64 内容中直接携带 flag。结合题目配置中登记的静态答案，无需访问该链接或运行任何载荷即可得到：

```
DUCTF{chatgpt_I_n33d_2_3scap3}
```

这也解释了题面“重新安装 Windows”的玩笑：真正的风险不在 DOCX 格式，而在于允许模型把文档文本升级为命令并交给执行工具。

## 方法总结

处理“让 AI 读附件”的题目时，应先把附件视为不可信输入：提取文本、区分正文和元指令，并禁止模型或 Agent 将附件中的命令、链接、工具调用参数直接付诸执行。提示注入是否成功取决于模型/Agent 的指令优先级与工具边界，而不是普通 Web 参数或 Office 漏洞；因此正确做法是最小权限、人工确认外部动作，并把附件指令一律降权为待审查数据。
