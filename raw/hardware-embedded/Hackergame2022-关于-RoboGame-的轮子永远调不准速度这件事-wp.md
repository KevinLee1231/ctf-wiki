# 《关于 RoboGame 的轮子永远调不准速度这件事》

## 题目简述

题目模拟一个 8051 控制器、36 个轮子和 I2C EEPROM。修改某个轮子时，相邻轮子会被伪随机速度覆盖；需要在九次调速内让前十个轮子速度相同。I2C 地址 `0x24` 上的 EEPROM 保存正在执行的固件，并允许最多把 9 个二进制位从 1 擦成 0。

核心是利用端口解析缺陷访问 EEPROM，定位 8051 指令中的立即数并做单向位补丁，因此归入硬件与嵌入式方向。

## 解题过程

### 绕过端口范围检查

端口解析函数只限制字符串长度为一个字符，却没有验证字符是否为十进制数字：

```c
int8_t port_to_int8(char *port) {
    if (port[1] != 0 && port[1] != ' ') {
        return -1;
    }
    return (int8_t)str_to_uint8(port);
}
```

`str_to_uint8` 对单字符计算 `port[0]-'0'`。要访问十进制 36，也就是 `0x24`，应发送 ASCII `T`：

$$
0x54-0x30=0x24.
$$

例如读取 EEPROM 当前页的 64 字节：

```text
r T 64
```

这里终端中的 `T` 就是实际字节 `0x54`；若使用脚本，也可以写成 `b"\x54"`。

### 转储并定位 rand 函数

EEPROM 共 4096 字节，按 64 字节分页。写请求的第一个数据字节选择页号，之后再读取该页：

```text
w T 1 <page>
r T 64
```

依次保存所有页面即可还原固件。题目同时给出了 `firmware.c`，可用 SDCC 编译并查看 `.rst` 列表文件中的源码—汇编对应关系。随机速度函数为：

```c
int8_t init_rand = 7;
int8_t speedtb[8] = {0x11, 0x45, 0x14, 0x19, 0x81, 0x24, 0x00, 0x19};

int8_t rand(void) {
    init_rand += 1;
    init_rand &= 7;
    return speedtb[init_rand];
}
```

对应 8051 指令位于约 `0xBB`：

```text
0000BB  53 08 07    anl _init_rand,#0x07
```

把立即数 `0x07` 改成 `0x00` 后，索引每次都归零，`rand()` 永远返回 `speedtb[0] = 0x11`。

### 利用 EEPROM 的单向写入打补丁

EEPROM 的写入不是普通覆盖，而是：

```c
new_byte = old_byte & ~clear_mask;
```

因此只能清除位。`0x07 -> 0x00` 恰好只需清除 3 位，低于 9 位预算。立即数字节在绝对偏移 `0xBD`，即第 2 页偏移 `0x3D`。请求总长度为 63：第一个字节选页 2，前 61 个掩码为 0，最后一个掩码为 7：

```python
payload = b"w T 63 2 " + b"0 " * 61 + b"7\n"
```

固件从 EEPROM 取指，补丁写入后随即生效，不需要另行重启。

### 在四次操作内统一前十个轮子

写某个轮子时，固件还会把左右相邻轮子设置为 `rand()` 的结果。补丁后该结果恒为十进制 17，也就是 `0x11`。依次把 1、4、7、9 号轮子直接设为 17：

```text
w 1 1 17
w 4 1 17
w 7 1 17
w 9 1 17
```

覆盖范围分别是 `{0,1,2}`、`{3,4,5}`、`{6,7,8}`、`{8,9,0}`，所以前十个轮子最终全部为 `0x11`，只用了四次调速。

最后读取端口 0 至 `0x23` 的单字节速度。端口仍需以单个 ASCII 字符传入，可用 `chr(0x30+i)` 构造；把返回的 36 个十六进制字节转成 ASCII 并连接，就是 flag。

## 方法总结

本题把输入校验、I2C EEPROM 语义和 8051 位补丁串成一条利用链。关键不是任意写固件，而是在“只能 1→0、最多 9 位”的条件下寻找合适立即数。选择 `ANL #0x07` 是理想目标：清 3 位即可让伪随机索引恒为零，再用覆盖相邻节点的集合设计四次调速完成约束。
