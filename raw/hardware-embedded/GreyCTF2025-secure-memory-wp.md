# Secure Memory

## 题目简述

题目提供 FPGA Verilog 和徽章交互模板。安全内存根据 5 位地址输出字符；底层 RAM 在 10 Hz 时钟上同步更新输出，但外层门控却组合判断当前地址是否为 31，由此形成检查地址与已锁存数据之间的时序竞态。

## 解题过程

先停止徽章后台并重新加载题目 bitstream，然后把 FPGA 互连 GP8–GP15 配成输出，把 PMOD／JTAG 对应引脚配成 8 位输入。模式位设置为 `010`，进入 Secure Memory 模式。

模板提供 `set_address(addr)`，将低 5 位地址送到互连。直接依次设地址并读取会遇到保护逻辑；正确利用是先让目标地址稳定约 0.15 秒，使内部流水线选中对应字符，然后在真正采样输出前立刻把外部地址改成允许访问的 31：

```python
def dump():
    out = ""
    for address in range(32):
        set_address(address)
        time.sleep(0.15)
        set_address(31)
        out += read_char()
    return out
```

也就是组合门控立即看到安全地址 31，而同步 RAM 的 `mem_value` 在下一个 10 Hz 上升沿前仍持有前一目标地址的数据。枚举 32 个位置后可恢复内存字符串并取得：

```text
grey{race_flag}
```

若 RP PMOD 可用引脚不足，可复用 JTAG 引脚补齐 8 位数据总线。

## 方法总结

硬件访问控制必须让授权判断和数据选择基于同一个锁存地址；若一个使用当前输入、另一个使用延迟寄存器，就会形成地址竞态。利用时延必须略小于设计的下一个采样周期：太快无法锁存目标，太慢则保护判断和读地址都更新。题目名中的 “race” 指的是硬件时序竞态，不是多线程软件竞争。
