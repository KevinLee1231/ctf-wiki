# CatCore

## 题目简述

题目提供 CatCore Hyper 数据手册和现场 FPGA 徽章，目标是进入开发者模式、读取片上内存中的 XOR 密钥，再构造显示 flag 的 Hyper 指令。官方 PDF 共三页；逐页核对后，所有必要表格和命令格式均可准确转为文本，不需要保留整页截图。

## 解题过程

数据手册列出 UART 模式配置位为 `3'b011`。Legacy 指令通常为 18 字符，外层格式是相同 opcode 包住 16 字符数据；`D...D` 会执行一条加密或开发模式 Hyper 指令。Hyper 指令本身为 16 字符，常用 opcode 为：

```text
@  开发模式提示
A  显示 flag
B  LED 控制
C  读取内存
```

手册第 3 页说明开发者模式在启动时把 Lattice 芯片的 N8 拉低。现场板卡上该信号对应 FPGA Flash 的 CS；将 CS 短接到 GND 后复位，即可进入开发者模式。开发模式允许尾部含 `DEV` 的未签名指令执行，例如：

```text
D@---------DEV@D
```

内存读取格式为：

```text
C<address>-------------C
```

且同一指令需发送两次，第二次输出才是流水线后的正确值。手册暴露了调试地址引脚 `A10/A9/A8/A3`；其中 A3 在封装图上伪装成 NC。把 A3 拉到 GND 并枚举开发模式内存地址，可通过 UART 泄露用于 Hyper 指令签名／加密的 XOR 密钥。

显示 flag 的明文 Hyper 指令是以 `A` 包围的 16 字符块，其中数据字段要求为：

```text
1w4n7myfl49p15
```

对期望指令与读取的密钥逐字节 XOR，构造外层 `D...D` 执行器指令。若内存中存在少量不确定字节，只需在候选位置枚举全部 256 种 XOR 值，并观察 UART／显示结果。成功后得到：

```text
grey{lmao_sandbox}
```

## 方法总结

本题把硬件故障注入、数据手册审计和简单指令加密组合在一起。关键链路是“Flash CS 拉低触发 dev mode → NC 实际连接调试地址位 → 流水线内存读泄露 XOR 密钥 → 构造 Flag opcode”。PDF 中的模式表、opcode 和 pinout 都已在正文完整转写；它们是文本协议而非独立视觉证据，保留整页图片反而会降低可检索性。
