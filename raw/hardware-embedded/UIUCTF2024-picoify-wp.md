# Picoify

## 题目简述

这是一个 PIC16F628A 无损压缩竞赛。服务生成 2048 字节的随机文本，通过 UART 逐字节送入参赛者提交的 PIC HEX 固件，收集固件输出的压缩流，再用参赛者一并提交的 Python 解压器校验。压缩后大小不超过原文的 75% 才达到基础通过线；Flag 格式是 `SHA256(secret || reduction).reduction`，继续提高压缩率还会影响排名。

## 解题过程

输入只含空格、数字和大写字母，所有字节均位于 `0x20` 到 `0x5a`。对每字节减去 `0x20` 后，结果最大为 `0x3a`，可用 6 位表示。于是每 4 个字符的 24 个有效位能压成 3 字节，恰好减少 25%。令 $c_i=\text{input}_i-0x20$，打包关系为：

```text
out0 = c0 | ((c1 & 0x03) << 6)
out1 = (c1 >> 2) | ((c2 & 0x0f) << 4)
out2 = (c2 >> 4) | (c3 << 2)
```

官方固件在 UART 接收中断中完成同一件事：用 `remaining` 记录缓存内的有效位数，把新字符的 6 位值移入 `buf`；累计到至少 8 位便调用发送函数输出一个字节，再把未发送的高位留给下一轮。实现时还要注意 PIC16 的银行切换，每次访问 `PIR1`、`RCREG`、`TXREG` 等寄存器前使用 `BANKSEL`，并在中断入口保存、出口恢复 `W` 与 `STATUS`。

解压器按相反位序每 3 字节还原 4 个字符：

```python
import sys

d = data
index = 0
for offset in range(0, len(d) // 3 * 3, 3):
    out[index] = (d[offset] & 0x3f) + 0x20
    out[index + 1] = ((d[offset] >> 6) | ((d[offset + 1] & 0x0f) << 2)) + 0x20
    out[index + 2] = ((d[offset + 1] >> 4) | ((d[offset + 2] & 0x03) << 4)) + 0x20
    out[index + 3] = (d[offset + 2] >> 2) + 0x20
    index += 4
sys.stdout.write(out[:index].decode("ascii"))
```

测试长度固定为 2048，且可被 4 整除，因此基础方案输出 $2048\times6/8=1536$ 字节，减少 512 字节。提交 `prog.hex` 和解压脚本的 Base64 后，公开仓库所含实例返回：

```text
7fcaa70c65af8d73aaae94f74892249b1e4127ccbd0b20a9e13131c76a48622e.512
```

该哈希与服务端 secret 和实际减少量绑定；若使用更强压缩算法，末尾数字与哈希都会变化。

## 方法总结

- 决定性技巧是利用受限字符集去掉 ASCII 的冗余高位，将每个字符从 8 位压到 6 位；这已经精确达到 25% 基线。
- 固件正确性不只取决于位运算，还取决于 PIC16 的银行寄存器、UART 中断时序、上下文保存和发送完成等待。
- 解压器必须与固件采用完全一致的位序，并先做本地往返测试；本题是排名型挑战，基础 WP 给出的是可通过方案，不代表理论最优压缩率。
