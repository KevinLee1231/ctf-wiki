# embedder

## 题目简述

题目提供为 ESP32（Xtensa）编译的 Rust 固件。程序把 GPIO22 配置为 LED 输出、GPIO23 配置为下拉按钮输入；只有按钮在一组严格时序中依次满足高、低、高、低、高，才会调用 `light_flag`，用 LED 明灭时长发送摩尔斯电码。

这道题的决定性机制是微控制器 GPIO 与信号时序，因此归入硬件/嵌入式，而不是仅因附件是 ELF 就归普通逆向。

## 解题过程

从固件反汇编或仓库源码可还原按钮门控：初始必须为高，300 ms 后为低，400 ms 后为高，200 ms 后为低，800 ms 后再为高。人工准确复现这组边沿较麻烦，官方方法是把 GPIO23 的五个条件分支改成始终通过，然后在 ESP-WROOM-32 或模拟器中把 LED 接到 GPIO22。

`light_flag` 使用固定时长编码：

```text
点：高电平 100 ms，低电平 100 ms
划：高电平 300 ms，低电平 100 ms
字符间隔：额外低电平 100 ms
单词间隔：额外低电平 300 ms
```

录制 GPIO22 波形后，按高电平持续时间区分点划，再按低电平间隔切分字符。解码出的完整消息是：

```text
TJCTF(WH4T 1S 4 BUTT0N 4NYW4YS 93B02FE5)
REPLACE PARENTHESES WITH CURLY BRACES,LETTERS ARE LOWERCASE
```

生成器在编码前把下划线替换为空格、花括号替换为圆括号，并把恢复说明一并发出。按末尾说明逆变换即可得到：

```text
tjctf{wh4t_1s_4_butt0n_4nyw4ys_93b02fe5}
```

## 方法总结

- 嵌入式固件分析要先确定目标架构和外设角色；这里 GPIO23 是门控输入，GPIO22 才承载秘密输出。
- 与其猜按钮节奏，不如补丁条件跳转或在模拟器中驱动输入波形，保持 LED 输出函数原样，便于获得可信信号。
- 摩尔斯文本还包含格式恢复指令。必须先完整解码，再执行“圆括号转花括号、空格转下划线、小写化”，不能只截取看似像 flag 的片段。
