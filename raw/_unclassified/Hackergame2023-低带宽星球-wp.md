# 🪐 低带宽星球

## 题目简述

服务端给出一张 1024×1024、由三个竖直纯色块组成的 PNG，要求上传一张解码后逐像素完全相同的图片。两档大小限制分别为 2048 字节和 50 字节。

服务端使用 libvips/pyvips 自动识别格式，去除双方的 Alpha 通道后比较宽、高与每个像素，而不要求上传文件仍是 PNG。决定性障碍是选择并构造足够紧凑的无损图像表示，不属于现有安全漏洞、隐写或逆向方向，因此归入 `_unclassified`。

## 解题过程

### 2048 字节限制

图片只有三段常量颜色，PNG 的过滤与 DEFLATE 已经很擅长压缩这类数据。对下载的原图做无损优化即可：

```bash
optipng --keep -o1 image.png
```

提交前应确认文件不超过 2048 字节，并且优化前后解码得到的 RGB 像素一致。这里不能做调色板近似、缩放或有损编码，因为比较器检查的是最大像素差必须为零。

### 50 字节限制

50 字节几乎容不下传统格式的文件头与三色像素描述。突破点是 pyvips 背后的 libvips 支持 JPEG XL，而 JPEG XL 的 modular tree 可以直接表达“按横坐标分三段，每段各通道为常数”，无需存储一百万个像素。

先从原图读取两条颜色边界 `x1 > x2`，以及右、中、左三块的 RGB 值。将这些值填入以下树；变量 `c` 的 0、1、2 分别代表 R、G、B，分支的缩进就是真假子树：

```text
RCT 0
if x > {x1}
  if c > 1
    - Set {right_b}
    if c > 0
      - Set {right_g}
      - Set {right_r}
  if x > {x2}
    if c > 1
      - Set {middle_b}
      if c > 0
        - Set {middle_g}
        - Set {middle_r}
    if c > 1
      - Set {left_b}
      if c > 0
        - Set {left_g}
        - Set {left_r}
```

用 JXL Art 工具的 `jxl_from_tree` 编译树：

```bash
jxl_from_tree tree.txt image.jxl
```

题目生成器本身就在边界和颜色的随机范围内重试，直到同一棵树编译出的文件不超过 50 字节，所以每位选手拿到的目标都可按此模板编码。上传前应做三项本地检查：文件大小不超过 50 字节；解码尺寸仍为 1024×1024；解码后的 RGB 与原图逐像素相同。服务端会按文件内容识别 JXL，扩展名不参与判定。

## 方法总结

第一问是常规无损压缩，第二问则要求把图片视为一个极短的生成程序。真正有用的观察是服务端比较“解码后的像素”，而不是“文件字节或格式”；因此应从解码器支持的格式和目标图的结构复杂度出发，用 JPEG XL 的决策树直接描述两条边界与九个颜色常量。
