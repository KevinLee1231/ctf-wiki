# Hackergame2020 超自动的开箱模拟器 WP

## 题目简述

题目把 1 到 128 随机放入 128 个箱子，并对每个目标数各运行一轮。每轮 Brainfuck 程序最多开 64 次箱子；输出 `1`、`2`、`3` 分别表示左移、右移和打开当前箱子，打开后读到的数字会作为下一次输入。只有 128 个目标全部找到才返回 flag。

这是百囚徒问题的自动策略构造，主障碍是置换环与 Brainfuck 状态机实现，暂归 `_unclassified`。

## 解题过程

### 利用置换环

把箱子位置到箱内数字的映射记作置换 $\pi$。目标为 $t$ 时，从编号 $t$ 的箱子开始，读出 $\pi(t)$，再打开编号 $\pi(t)$ 的箱子，如此沿置换环前进。只要 $t$ 所在环的长度不超过 64，就一定能在限制内遇到装有 $t$ 的箱子。

所有 128 轮使用同一排列，所以全部成功等价于该排列不存在长度大于 64 的环。对于 128 个元素，这一概率为：

$$
1-\sum_{k=65}^{128}\frac{1}{k}\approx0.310743811.
$$

一次提交约有 31% 成功率，失败时重新提交几次即可；这远高于每轮随机开 64 个箱子的联合成功率 $2^{-128}$。

### 用 Brainfuck 实现策略

解释器中的箱子下标是 0 到 127，箱内数字和 target 是 1 到 128，所以每次要把输入减一后再右移。以下是官方可用策略：

```brainfuck
+> >+>++>+++<<< <[> -[>.< -] , - [>>.<< -] >>>.<<< <]
```

Brainfuck 忽略空格，去除空格后等价于：

```brainfuck
+>>+>++>+++<<<<[>-[>.<-],-[>>.<<-]>>>.<<<<]
```

初始化后的几个常量单元依次提供操作码 `1`、`2`、`3`。外层循环每次执行：

1. 输出 255 次 `1`，把箱子游标可靠地推到最左端；到达下标 0 后，多余左移会被解释器忽略。
2. 用 `,` 读入 target 或上一次开箱结果，减一得到目标箱子的 0 基下标。
3. 输出该下标次数的 `2`，从最左端移动到对应箱子。
4. 输出一次 `3` 开箱；解释器把箱内数字送回输入队列，供下一轮循环继续沿环追踪。

当随机排列的最大环长不超过 64 时，128 轮全部成功并输出 flag；否则服务会报告某个目标在 64 次内未找到，重新开始一次新排列即可。

## 方法总结

百囚徒策略把 128 个看似独立的搜索任务关联到同一个置换结构上。每个参与者只跟随自己的环，整体成败便由最大环长决定。实现层面的两个坑是编号从 1 开始而数组下标从 0 开始，以及每轮 Brainfuck 状态都会重置，不能跨目标记忆；上述程序只依赖当前输入，正好满足限制。
