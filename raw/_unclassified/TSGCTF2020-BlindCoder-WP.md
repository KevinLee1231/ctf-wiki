# TSGCTF2020 BlindCoder WP

## 题目简述

服务随机生成 50 个互不相同的 32 位无符号整数作为隐藏测试集 $S$。每次可提交一个长度不超过 1000 的表达式，服务对所有测试值运行它，并只返回“输出恰好等于 $N\bmod10$”的用例数量；最多查询 1000 次。若最终完整猜中集合 $S$，即可获得 flag。

这是一道纯查询算法题，没有合适的安全方向，因此归入 `_unclassified`。关键是把判题分数转换为集合计数 oracle，再在 1000 次预算内恢复 50 个数。

## 解题过程

对任意布尔条件 $P(N)$，提交：

```text
P(N) ? N % 10 : 100
```

条件成立时输出正确末位，条件不成立时输出 100，而真实末位只可能是 0 至 9。返回的通过数因此精确等于：

$$
\left|\{x\in S\mid P(x)\}\right|.
$$

第一阶段从已知含 50 个数的区间 $[0,2^{32})$ 开始。对一个含 $k>1$ 个秘密的区间 $[l,r)$，查询左半区：

```text
(l <= N && N < (l+r)/2) ? N % 10 : 100
```

返回 $k_L$ 后，右半区数量就是 $k-k_L$；只把数量大于 1 的区间继续入队，数量等于 1 的区间保存。对随机 50 元集合，[官方复杂度分析](https://scrapbox.io/tsgctf2-writeup-naan/BlindCoder_writeup_(En))指出这一阶段平均约需 71 次查询，即可得到 50 个互不相交、各含一个秘密的区间。

若再分别二分每个单例区间，区间典型宽度约为 $2^{32}/64=2^{26}$，需要约 $26\times50=1300$ 次，超出预算。优化方法是一次同时询问两个单例区间的左半部：

```text
((l1 <= N && N < m1) || (l2 <= N && N < m2)) ? N % 10 : 100
```

结果只可能为 0、1、2：

- 返回 0：两个秘密都在右半部；
- 返回 2：两个秘密都在左半部；
- 返回 1：两者分居左右，但暂时不知道哪一个在左。只需单独解析其中一个，另一个方向即可取反推得。

所以一次合并查询平均相当于约 1.5 次独立二分，第二阶段期望查询数约为 $1300/1.5\approx867$。官方 Python solver 用队列保存待定单例区间；遇到返回 1 时递归解析第二个区间，再用布尔取反确定第一个。加上第一阶段仍能控制在 1000 次之内。恢复全部端点后提交排序不重要的 50 个整数，服务转成集合比较并返回：

```text
TSGCTF{ichi_zero_zero_zero_zero_zero_zero..._Counting!!}
```

## 方法总结

这道题先利用“错误分支输出不可能值”把黑盒判题器变成任意谓词的计数查询，再用区间二分恢复隐藏集合。真正的优化不是更快地二分单个数，而是把多个独立布尔问题放进一次计数查询；返回 0 或 2 可同时解决两位，返回 1 也保留可由另一结果消除的相关性。面对只给总分的隐藏测试系统，应先判断能否设计永不意外通过的哨兵输出，再把分数解释成集合统计量。
