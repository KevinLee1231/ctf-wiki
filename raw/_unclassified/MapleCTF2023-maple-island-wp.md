# maple-island

## 题目简述

服务生成 20 个奇数组和 20 个偶数组“选手”，每名选手都是 4 字节数据，并给出双方的偏好表。函数 `create_a_perfect_world` 根据这些偏好建立稳定匹配，再把匹配结果拼成 160 字节数据，与密文异或。题目的决定性障碍是复现稳定婚姻算法及其输出顺序，而不是密码算法，因此归入未细分方向。

## 解题过程

阅读源码可知，奇数组一侧作为求婚者。维护每个求婚者尚未尝试的下一名对象以及偶数组一侧当前接受的对象，重复以下步骤：

1. 取一个尚未匹配的奇数组选手，向其偏好表中下一名偶数组选手求婚。
2. 若对方未匹配，直接接受。
3. 若对方已匹配，则按自己的偏好表比较新旧求婚者；保留更喜欢的一方，另一方重新进入待处理队列。
4. 所有人匹配后，按题目函数规定的索引顺序输出配对。

这就是 Gale–Shapley 稳定匹配。容易出错的地方不是算法本身，而是把配对按错误一侧排序，或把单个配对连接成 `zero || one`。官方实现按最终列表逐项连接 `one || zero`，20 对、每项 8 字节，恰好得到 160 字节“OTP”：

```python
pairs = create_a_perfect_world(ones, zeros, one_pref, zero_pref)
pad = b"".join(ones[i] + zeros[j] for i, j in pairs)
plain = bytes(a ^ b for a, b in zip(ciphertext, pad))
```

对给定实例复现同一状态机和排序后，异或得到完整文本，其中 flag 为：

```text
maple{G05h_1_w4nt_4_st4bl3_m4tch_t00_pls_1_4m_50_l0n3ly}
```

## 方法总结

看到 XOR 不应立即把题目归为密码学；密钥已经完全由公开输入确定，真正需要还原的是配对算法。复现服务端算法时，应把“谁求婚、偏好比较方向、队列回退方式、最终排序、字节拼接顺序”都视为协议的一部分。用输出总长度 $20\times(4+4)=160$ 做检查，可以快速发现遗漏或重复配对。
